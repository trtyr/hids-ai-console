## 6 为什么不能自动重连 VPN（2026-11-21 追加）

按「恢复 Mac 隧道」的方向继续核查了 Mac 上的 OpenVPN Connect：

```
profile    ~/Library/Application Support/OpenVPN Connect/profiles/1790060919466.ovpn
remote     vpn.chaitin.net:1194（服务端证书 CN=openvpn.in.chaitin.net）
客户端日志 ~/Library/Application Support/OpenVPN Connect/log/ovpn.log 末尾：
  [Nov 18, 2026, 16:09:18] Session is ACTIVE
  [Nov 18, 2026, 16:09:18] AUTH_FAILED
  [Nov 18, 2026, 16:09:23] EVENT: DISCONNECTED
IV_SSO=webauth,crtext        （服务端要求交互式 SSO / 浏览器登录）
sudo -n true → SUDO_NO       （Mac 上 trtyr 无免密 sudo；openvpn CLI 起 tun 需要 root）
```

即：最后一次连接（11-18 16:09）就是 **AUTH_FAILED**，账号/会话已失效，且服务端要求交互式 SSO；
不能靠 keychain 里保存的密码静默重连（也不应该去提取用户凭据）。`utun5` 是那次会话留下的残留接口，
所以「路由在、网关不通」。这一步必须由用户在 Mac 上手动完成 SSO 重新认证。

## 7 再核查：实验室路由由「零信任客户端」提供，不是 OpenVPN（2026-11-21 追加）

Mac 上实际提供 `192.168.24.0/22` 路由的是零信任客户端（`/Applications/零信任客户端.app`，进程 `ztacli`/`ztacore`）
与 `BoostNet`：`utun5` 地址 `10.2.3.67 → 10.2.3.254`，路由表里 `192.168.24/22`、`172.16.220/24`、`172.16.221/24`、
`192.168.20` 都指向 `10.2.3.254`。但：

```
ping 10.2.3.254 → fail
nc 192.168.24.21 22/443/8080/15514 → 全部 CLOSED
零信任客户端配置：AutoLogin=false（需要人工登录/SSO）
osascript 控制窗口 → “osascript 不允许辅助访问”（Mac 未授予辅助功能权限）
Mac 上 sudo -n → SUDO_NO
```

即：路由存在但零信任网关不响应，且客户端不自动登录、GUI 自动化被 macOS 辅助功能权限拒绝、无免密 root。
重连必须由用户在 Mac 上手动打开零信任客户端完成登录；这不是脚本能绕过的。OpenVPN 那条是另一个已失效的
profile（见 §6），不是本次实验室路由的来源。
