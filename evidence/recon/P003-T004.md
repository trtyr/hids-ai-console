## 1. 功能理解

本卡不改代码，只补契约：把六处「有结构但没写清」的地方写成测试方能照着断言的 schema 与枚举。
判据是 `openapi.yaml`（机器可读契约）与 `docs/modules/*.md`（给人读的契约）双向都有，且字段来源带 `文件:行号`。

验收条目对应的缺口（B01-B10 是外部审计编号，卡里已逐条自述，仓库内无该清单）：

| 验收 | 缺口 | 结构 | 补前的契约状况 |
| --- | --- | --- | --- |
| A1 | B01-B05 | `steps` / `missing_evidence` / `claims` / `evidence` / `validation` / `review` | openapi 里六处全是 `additionalProperties: true`，一个字段都没写 |
| A2 | B06 | TraceBoard `nodes` / `edges` / `activity` 元素 | 同上，元素无字段 |
| A3 | B07 | WikiPage `content` / `characters` / `status` | `WikiPageSummary` 只有 4 个字段、`status` 无枚举；`getWikiPage` 响应是 `JsonObject` |
| A4 | B08 | RuleSet `config` 的 `schema_version` / `enabled` / `rules` | openapi `config: additionalProperties: true` |
| A5 | B09 | `required_evidence[].status` 五态 | docs 有状态表，openapi 里 status 无枚举 |
| A6 | B10 | `Alert` 详情的 `detail` 随事件类型变化 | openapi 只写 `detail: { type: object }`，没说字段会变 |
