## 1. 功能理解

`node gate/gate-cli.js docs` 对 `docs/` 做结构与元数据体检（`gate/gate-cli.js:159-360`）。本卡把它的 **error 级 findings 清零**：

## 3. 依赖影响面

- **门禁规则之间会互相触发**：给无 type 的文档补 `type: module` 会**打开**「定位/值语义/行为承诺/失败面」与「值语义表要有单位」的检查——
  今天这四篇没报 no_units_column 是因为 type 为空、整块被跳过（`gate/gate-cli.js:263-264`）。所以 A2 与 A3 的改法必须一起验：
  先加 frontmatter 跑一次门禁，按新冒出的 findings 决定是补标题还是补单位列。
- **`docs/architecture.md` 提升为 architecture 层**会打开 layer_leak / layer_dup（`:315-329`）：它已含 ```` ```js ```` 块（`architecture.md:390`），
  layer_leak 只在「有代码块」时报错 → 这条**会红**，需要处理（该块是 `runtimePaths()` 的目录清单，属实现细节，挪到模块页保留指针）。
- **新建 L0 与既有文档共享句子会红**：`docs/architecture/` 与 `docs/architecture.md`、`docs/modules/*` 属不同目录段，
  同一行（≥12 字，剥前缀后）两边都出现 → layer_dup。L0 内容必须自己写，不能整段照抄。
- **不碰代码**：产品代码、测试、`web/**` 全不动；`npm test` 与 evidence 件只跑一遍留证。
- 承诺编号改动只动文档：测试里的 `// covers:` 回指在根 `*.test.js` 与 `evidence/test/**`，门禁的 `test_uncited`/`promise_untested` 只扫
  `tests|test|e2e|spec` 目录（`:296-309`，本仓没有这些目录）→ 改编号**不会**触发测试侧联动的门禁错。
