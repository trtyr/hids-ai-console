## 1. 功能理解

一句话：**把「深度溯源」从「左列表 + 右白板」的同屏形态，按 D015/D016 拆成「先列表、点一行进这一条」**——
列表页回答「看哪一条」（类型/主机/告警时间/状态/链长/断点/更新时间，可筛可分页，列表里不画链）；
白板页回答「这一条怎么触发的」（告警钉右边、原因往左长，点可拖且位置记住，不能自己加点加线，
进行中自己长、完成后按 `discovery` 重放、断点写在图上不点开也看得见，页面没有对话输入框）。

## 3. 依赖影响面

- `web/src/trace.js` 的三个导出只被 `pages/trace.js` 与两份测试引用（`grep -rn listTraceBoards` 已核）。
  `pages/alert-detail.js` 用的是 `src/alert-detail.js:182` 的**另一个** `getTraceBoard`（读旧 `nodes` 做关联实体），
  本卡不动它 —— 后端 `presentBoard` 保留 `...board`，`nodes` 仍在（`trace-board.js:126`）。
- `src/router.js` 的 `PAGES` 增一项 → `test/router.test.js`、`test/shell.test.js` 的条数断言跟着改；
  侧栏六入口不变（`trace-board` 的 `navLabel: null`）。
- 后端（T014 已合入，`openapi.yaml:456-560` + `:1708-1815`）：
  - `GET /api/trace/boards`：`count`(1-50) / `offset` / `status`(可逗号多选) / `type` / `host` / `from` / `to`，
    回 `{ boards[], total }`，列表项 `TraceBoardSummary`（含 `chain_length` / `has_gaps` / `updated_at`）。
  - `GET /api/trace/boards/{target}`：`hops[] / links[] / gaps[] / discovery[] / alert / chain_length / has_gaps`。
  - `POST /api/trace/boards`：已有回 **200**、新建回 **202**，正文 `{ target }`；422 = 这条告警没有可用资产。
- 改动风险：
  - `asBoard` 放松/收紧都影响 `getTraceBoard` 与 `startTraceBoard` 两处调用与 `alert-detail` 的 partial 分支（不共享）。
  - 列表页与白板页共用 `assets/pages/trace.css`（同一份 `<link data-page-style="trace">`），选择器前缀分开
    （`.trace-page` / `.trace-board`），互不漏样式。
