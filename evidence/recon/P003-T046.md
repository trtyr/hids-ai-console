## 1. 功能理解

模型调用现在是黑盒：三域（研判 / 规则维护 / wiki 维护）发出去的提示词多大、回包多长、耗了多久、死在哪一步（超时 / 回包不是 JSON / 调用报错），只有各自业务错误字符串里的一点残渣。
本卡要做两件事：

1. **结构化事件**：三域每一次模型调用按 `log.js` 的行形状落事件（域、角色、轮次、方向、输入/输出字符量、耗时、结局），密钥与正文原文一个字都不进日志。
2. **回放接口**：按告警 ID 把一次研判会话的逐轮消息摘要、工具调用序列、各轮结论变化读出来——**读已落盘的案卷，不重放模型**。

**口径决定（写进文档，测试按文档写）**

- 一次模型调用落**两条**事件，`direction` 区分：`request`（发出去，带 `input_chars`）/ `response`（收回来，带 `input_chars` + `output_chars` + `duration_ms` + `outcome`）。理由：调用挂死或进程被杀时，只有 request 那条能证明「发过」，单条事件做不到。
- 字段：`domain`（`triage|rule|wiki`）、`role`（`triage|review|rule_maintainer|wiki_maintainer`）、`turn`（调查轮次，循环外单发顺延）、`phase`（`shortcut|investigate|review|revision|validation|narrative|maintain`）、`attempt`（同一轮同一 phase 的重试序号，1 起）、`direction`、`input_chars`、`output_chars`、`duration_ms`、`outcome`、`tool_calls`（回包工具调用数）、`alert_id` / `session_id`（有则带）、`model`（模型名）、`error`（失败时 ≤120 字，过 `log.js` 两道脱敏闸）。
- `input_chars` = `JSON.stringify({messages, tools}).length`（请求体序列化字符数）；`output_chars` = 回包 `content` 字符数（`tool_calls` 另记条数）。
- 结局：`timeout`（`AbortSignal` 超时 / 报错含 timeout/超时）、`invalid_json`（`decode` 抛）、`error`（其余调用失败）、`ok`。
- 回放接口只读 `<数据根>/investigations/<hash>.json` 与其中的证据清单：**不调模型、不调牧云**。
