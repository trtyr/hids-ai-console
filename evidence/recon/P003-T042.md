## 1. 功能理解

今天整条链只吃一组模型配置（`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`），研判、独立复核、两个维护者、溯源白板共用同一个 `ChatModelClient` 实例。本卡把模型配置**按角色分层**：新增「复核」与「轻量」两组键，四个角色（研判 / 独立复核 / 两个维护者 / 溯源白板）各自拿到自己的配置实例；不设新键时逐键回退主判三项，行为与今天一字不差。`GET /api/config` 要能看出每个角色 resolved 到哪个模型，`POST /api/config` 要能改这六键（走 T029 的既有覆盖层，不做 T043 的新机制）。

**键名（本卡定形）**：复核组 `LLM_REVIEW_BASE_URL` / `LLM_REVIEW_API_KEY` / `LLM_REVIEW_MODEL`；轻量组 `LLM_LIGHT_BASE_URL` / `LLM_LIGHT_API_KEY` / `LLM_LIGHT_MODEL`。超时五个角色共用 `LLM_TIMEOUT_MS`（不新开键）。

**角色映射（本卡定形）**：

| 角色 | 实例键 | 配置组 | 消费者 |
| --- | --- | --- | --- |
| 研判 | `triage` | 主判 `LLM_*` | 两个 `InvestigationAgent`（triage / deep） |
| 独立复核 | `review` | 复核组 | `InvestigationAgent` 的复核轮（`investigation-agent.js:854`） |

| wiki 维护者 | `wiki_maintainer` | 轻量组 | `WikiWorkbench` |
| 溯源白板 | `trace_board` | 轻量组 | `TraceBoardService` |

**回退口径**：逐键回退——复核组 / 轻量组某个键空，就用主判的同名字段（`*_BASE_URL`→`LLM_BASE_URL`、`*_API_KEY`→`LLM_API_KEY`、`*_MODEL`→`LLM_MODEL`）。`source` 三态：`primary`（这一组三个键全空，全部回退）、`own`（三个键全有，全用自己）、`mixed`（部分有，逐键回退）。主判三项不齐时五个角色都不建实例（与今天 `model = null` 同一判据）。

## 3. 依赖影响面

- **装配顺序**：`createModelRolesFromEnv()` 必须在 `promptStore` / 各消费者之前（替换 `server.js:40` 那一行即可，位置不动），因为 `configStore`（`server.js:32`）已经把覆盖层盖进 `process.env`。
- **`applyLiveConfig` 的语义扩张**：主判三项改了之后，`primary` / `mixed` 角色的回退字段必须跟着变——不重新解析就会「写配置只改了研判，维护者还拿旧地址」。旧 `model` 单目标分支保留，`evidence/test/P003-T029/config-write.test.js:87-104` 仍绿。
- **`WRITABLE_CONFIG_KEYS` 的读取点**：`config-store.js:71`（覆盖层读回）、`:97`（`values()` 回给 `applyLiveConfig`）、`:105`（不可写键 400）。加键即三处一起生效，没有第二份清单。
- **校验面**：`validateConfigValues` 复用 `ChatModelClient` 构造器；只写 `LLM_REVIEW_MODEL` 时校验对象是「合并后的生效值」（baseUrl/apiKey 回退主判），所以不会因为只写一个键就 400。坏 `LLM_REVIEW_BASE_URL` 报错要点名 `LLM_REVIEW_BASE_URL` 而不是 `LLM_BASE_URL`。
- **连带测试**：根 `*.test.js`（`npm test`，228 条基线全绿）——`investigation-agent.test.js` 覆盖复核轮（改 `:854` 会碰）、`config-*` 与 `agent-api.test.js`；`evidence/test/P003-T029/*` 两支按新语义改；`evidence/test/P003-T025/config-contract.tester.test.js` 按 `openapi.yaml` schema 校正文，schema 同步后仍绿（顶层八键、`secrets` 五键不动）。
- **不碰**：`web/**`；`SECRET_CONFIG_KEYS` / `REQUIRED_CONFIG_KEYS`（新六键都不是必填、不进 `secrets`——新组的密钥不单独报布尔，靠 `model.roles[*].source` 三态看有没有自己的组，正文里依旧不出现任何密钥原文）；`docs/modules/model-client.md`（既有漂移，见未决）；T043 的覆盖层新机制（本卡只往既有 `WRITABLE_CONFIG_KEYS` 加键）。
