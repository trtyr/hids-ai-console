## 一、功能理解

进程起来之后，运维不能登机器改环境变量重启来换牧云地址/令牌或模型地址/密钥/模型名。本卡给一条写配置的接口：写进去的值**落盘**（重启仍生效）、**运行中立即生效**（后续牧云与模型调用走新值）、**立刻被 `GET /api/config` 反映**，并且任何响应与日志都不回显机密原文。没被改过的键继续读环境变量。

## 三、依赖影响面

- **模块级装配全部读 `process.env`**（`server.js:29-54`）：`host/port`、`gateway`、`apiToolbox`、`agentToolbox`、`model`、`agent`、`deepInvestigator`、`triageMonitor`、`wikiWorkbench`。store 在装配前把覆盖层写进 `process.env`，这些一行不用改就吃到持久化的值。
- **路由握着对象引用**：`createServer(service = gateway, toolbox = apiToolbox, investigator = agent, …)` 是值捕获。所以运行中生效**不能重建对象**（重建等于换引用，路由还拿旧对象），只能原地改值——`applyLiveConfig` 打的就是 `gateway.rpc.baseUrl/token`、`agentToolbox.client.url/token`、`model.url/apiKey/model`。持有这些引用的下游（`apiToolbox`、`triageToolbox`、两个 `InvestigationAgent`、`wikiWorkbench`、`triageMonitor.service`）都是同一批对象，跟着变。
- **取值校验用装配处同一套构造器**：`RpcClient`（`rpc-client.js:4-5`）判 URL 前缀与 Token ≥6、`ChatModelClient`（`model-client.js:22-24`）判三项齐全与 URL 前缀。写接口拿合并后的生效值去建一次客户端来判——判据只有一份，写进来的值一定能被重启后的装配建成。
- **`configSummary(env)` 是纯函数**：`GET /api/config` 与启动闸门共用（`server.js:1009`）。路由改传 `config.env`，单测能用注入的 env 对象而不是真 `process.env`。
- **日志**：`log()` 来自 `log.js` 单例，单测用 `useJournal()` 换替身（`log.js:69`）。`config.updated` 只带键名数组。
- **鉴权**：`hasAccess()` 在请求入口第一行（`server.js:576`），`POST /api/config` 天然过这道闸；`HIDS_BASIC_AUTH_PASSWORD` 没配时 `hasAccess` 直接放行（`server.js:58-65` 口径，docs §4）。
- **会被碰到的既有测试**：`evidence/test/P003-T019/data-dir.test.js:49` 断言源码里有 `const runtime = runtimePaths(moduleDirectory);` 原句——那一行不动；它同时按 `runtimePaths()` 的返回做断言，**要看看是否枚举键集**（若枚举，加 `configOverrides` 会红，得同步该测试——它在别的卡 scope 里，先跑一遍看）。
- **`.env.example` 与代码键集双向一致的既有测试**（T025）：本卡**不新增任何环境变量**（持久化文件路径由 `runtimePaths()` 给），所以那条不会红。
