## 一、功能理解

这张卡不是加功能，是**堵研判链路上四条「会撒谎」的路**：

1. 模型 6 轮没交出可用 JSON → 现在整条研判进 `failed`（`investigation-agent.js:629`），案件目录没有 `05-研判结果.md`，
   运维看不到任何结论。要求：改成**降级结论**——存疑 + 缺口清单，口径与 `runUnmatchedSyslog` 一致（`investigation-agent.js:748-800`），
   于是 `triage-monitor.js:497` 那条 `writeSyslogResult` 照常把 `05-研判结果.md` 写出来。
2. 独立复核不可用时，只有 `highRisk` 五类会从 threat 降存疑（`investigation-agent.js:650`），其余类型照旧顶着「真实威胁」出门；
   复核要求修订但修订请求失败时，`catch { verdict = draft }`（`investigation-agent.js:647`）**静默沿用草稿**。
3. `evidence-view.js:9` 的 `host_id` 兜底链末尾挂了裸 `id`——事件行里 `id` 是**事件 ID**，不是主机 ID。
   必查项拿这个数去查「同主机关联事件」，查到的是**另一台机器**（或干脆空页，`required-evidence.js:33`），
   然后被写成「已查当前页但未返回记录」（`required-evidence.js:136`）——把「查错机器」报成「那台机器没事」。
4. 必查项里 `authorization_record` / `web_request_or_file_access_log` 两项**写死 `source: false`**（`required-evidence.js:78-88`），
   每张告警都记一条「没有可用数据源」缺口；而牧云 MCP 目录里本来就没有这两个工具，这不是缺口，是「平台暂不提供」。

另外三件工程账：deep 模式不采必查项（`investigation-agent.js:392-394`）、必查项逐项串行 + 模型一轮多工具调用串行、
降级路径五个互不依赖的加载串行（`investigation-agent.js:749-755`）、以及文件内三处漂移的注释锚点。
