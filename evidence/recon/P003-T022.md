## 1. 功能理解

模型在 6 轮调查里没交出一份能用的结论文本时，现在的失败记录只有一句笼统的
「模型未在调查轮数内给出有效 JSON 结论」（`investigation-agent.js:586`）——运维看不到模型到底回了什么、
为什么退回。本卡要让它带上末次回包的形状（字数、开头一段、末次退回原因），并且失败本身不许把
已经写成的结论盖掉、失败记录还能再跑一次。

## 3. 依赖影响面

- **谁读这条错误**：`triage-monitor.js:470-471` 把 `error.message` 截 250 字写进 `record.detail`（阶段「研判失败」）。
  错误文本超过 250 字就被砍尾巴，所以摘要必须在 240 字内按「轮数 → 回包字数 → 开头 → 退回原因」排。
- **A2 重跑不卡队列**：队列侧已有——`enqueue(id, {retry:true})`（`triage-monitor.js:207`）、`drain()` 的
  `.finally(() => { this.active--; this.drain(); })`（`triage-monitor.js:393`）。本卡不碰队列，只保证 agent 这不留状态。
- **A3 结论不被盖**：`history.save()` 只在成功路径（`triage-monitor.js:452`），失败分支只改 `status/stage/detail`
  （`:470-471`），结论字段不碰。agent 侧根本没有 store 引用，所以本卡只要保证「失败仍然抛错、不返回降级结果」。
- **连带要跑的测试**：`investigation-agent.test.js`（全部）、`triage-monitor.test.js`（A2/A3 的队列侧守卫）、
  `integration.test.js` / `agent-api.test.js`（错误文本出现在 HTTP 层的地方）。
- 无外部请求、无时钟依赖：全部用例用假 model / 假 fetcher。
