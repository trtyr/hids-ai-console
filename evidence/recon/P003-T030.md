## 1. 功能理解（A1 的答案）

**A1 的答案：路径已经有了，不需要新增接口。** 现查（牧云事件 ID）→ 研判队列＝既有的
`POST /api/agent/triage/{alertId}`（`server.js:1176` → `TriageMonitor.enqueue`（`triage-monitor.js:670`））。
入队后由队列的 `run()` 走「无 syslog 报文」分支：`investigator.run(targetId, { mode: 'triage' })`
（`triage-monitor.js:1042`）→ `InvestigationAgent.run` 按事件 ID 调 `get_<类型>_event` 从牧云拉详情
（`investigation-agent.js:444-445`、`investigation-agent.js:459`），结果由 `history.save(result)` 落研判记录
（`triage-monitor.js:1053`）→ 记录 `status=done`（`triage-monitor.js:1056`）。

所以本卡按 A1 的后半句做：**补测试钉住**这条路径，并把「重复入队」的语义写进契约（A2）。
本轮不改 POST 的既有语义——改成 409 会打断 web 侧「重试」按钮（`web/src/cases.js:167`、`web/src/alerts.js:156`，
`web/**` 本卡禁改），属于越界。
