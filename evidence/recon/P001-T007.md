## 四、六条关键口径的实测

### 4.1 轮次与调用上限

```
A choice 序列 = ["auto","auto","auto","auto","auto","none"] | 抛出 = 模型超出调查轮数仍请求工具
B choice 序列 = ["auto","REVIEW"]
C 抛出 = 模型未在调查轮数内给出有效 JSON 结论 | 调查轮数 = 6
D deep required_evidence = [] | review = supported
D triage required_evidence ids = ["related_events:records_returned","network_connections:source_unavailable","source_history:source_unavailable"]
```

- A：模型每轮都请求工具，循环跑满 6 轮，第 6 轮 `choice` 变成 `'none'`，模型再请求工具就抛错。
- C：6 轮输出都不是合法 JSON → 抛「模型未在调查轮数内给出有效 JSON 结论」。
- D：深度研判不生成必查项；常规研判同一告警类型生成三项，其中两项因工具目录里没有对应工具落到 `source_unavailable`。

单轮内批量请求工具时，第 9 次及以后的请求被上限挡下，不产生证据记录：

```
S2 turns= 4 batches= [5,5,5] evidence= 7
S2 tool_reuse trace= [{"kind":"tool_reuse","name":"list_global_events","evidence_id":"cw:3","args":{"i":0}}, ...]
```

第 3 轮同参重复查询被识别成 `tool_reuse`，不新增证据。

### 4.2 引用校验与降级

让 `verifyClaims` 恒返回不通过：

```
E choice 序列 = ["auto","REVIEW","none","none"]
E verdict = uncertain | confidence = 低
E validation = {"ok":false,"errors":[...],"removed_unverified_facts":true}
E missing_evidence = ["模型引用校验未通过", ...]
```

`none` 出现两次 = 引用校验退回修订两次（`for (let retry = 0; retry < 2 ...)`）。

误报门槛（复核 supported、校验 ok、但没有正向良性事实）：

```
F verdict = uncertain | missing = ["误报结论缺少 2 条可引用的正向良性事实或独立复核支持", ...]
```

`2` 对应高风险类型（蜜罐在 `highRisk` 里）。复核不可用 + 高风险 + 真实威胁：

```
G review = {"assessment":"unavailable","concerns":["独立复核未完成: ..."],...}
G verdict = uncertain | summary = 独立复核未完成，暂按存疑处理。原调查摘要：摘要
G missing = ["独立复核未完成，真实威胁结论待复核", ...]
```

## 五、客户报告长度：实测到 301

这是本卡最值得记的一条。

```
$ node --input-type=module -e "..."
suffix_len=37 allowed=263
A_裁剪段内第20字是句号 => len=58
B_裁剪段末尾无标点 => len=301
C_裁剪段末尾是逗号 => len=300
D_裁剪段末尾是句号 => len=300
```

`appendEvidenceReport`（`required-evidence.js:154-165`）的目标上限是 300，但 `required-evidence.js:164` 的
裁剪分支在末尾补一个句号。当被裁剪段末尾不是「，、；：。」或空白时，长度是 `maxLength + 1`。
`finalizeTriageOutput` 自己产出的 `report` 确实 ≤300（`triage-output.js:47`、`triage-output.js:64`），
但必查项摘要是**之后**追加的（`investigation-agent.js:545-546`），所以最终交付给客户的报告可能到 301。

页面按现状写：3.6 末尾与 6.1 各说一次，并给出可复跑命令（页面 5.2 节）。
