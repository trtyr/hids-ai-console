## 1. 功能理解

今天 `server.js` 的错误体只有 `{ error: "<消息>" }`，状态码由每个路由现场手挑：同一个「本程序没预料到的异常」，在规则 PUT / wiki 页 / wiki 会话说成 **400**（调用方传错），在研判控制 / 外层 catch 说成 **502**（上游失败）；「告警 ID 无效」靠 `/告警 ID 无效|研判模式无效/` 正则匹配文案、`请求正文` 也是靠 `/请求正文/` 匹配文案来分 400/502。本卡要：把错误收成四类（调用方传错 / 没配置 / 上游失败 / 本程序失败），一类一个稳定 `code`，状态码由分类决定而不是路由随手写；上游失败带上游摘要；本程序意外只回固定文案（堆栈、异常原文只进日志）；响应与日志都不回显凭据。
