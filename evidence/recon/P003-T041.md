# P003-T041 侦查 —— 规则库与知识库外置：活数据进数据根，维护接口正式化

## 一、功能理解

判据库（`wiki/`）与 Rego 规则库（`rules/`）今天还住在仓库里：`server.js:43` 的 `new WikiStore()` 缺省读仓内
`wiki/`，`server.js:49` 的 `regoRuleStore` 直接 `path.join(moduleDirectory, 'rules')`，规则维护者用
`writeRuleFile()`（`server.js:226-234`）直写那份文件。本卡把这两本库的**活数据搬进数据根**
（`HIDS_DATA_DIR` / `~/.local/share/hids-ai-console/`），仓库副本退化成只读种子；同时把「改一条规则」做成
带版本（`rules-history/<id>-<rev>.rego`）、带留痕（`rule-sessions/`）、有显式接口（读 / 改 / 历史 / 回滚）的正式维护面，
维护者 Agent 与人工共用同一套。

## 二、触点清单

### 2.1 库目录与种子（A1/A2）

| 落点 | 现状 | 改法 |
| --- | --- | --- |
| `rule-store.js:146` `class RuleStore` | 构造只收一个目录，无历史、无写入 | 缺省目录＝`<数据根>/rules`；新增 `historyDirectory`（`<数据根>/rules-history`）、种子源＝仓内 `rules/` |
| `wiki-store.js:6` `defaultDirectory` | `HIDS_WIKI_DIR` || 仓内 `wiki/` | `HIDS_WIKI_DIR` || `<数据根>/wiki`；仓内 `wiki/` 降为种子源 |
| `wiki-store.js:393` `historyDirectoryFor` | 只有「内置 wiki/」落 `wiki-history/` | 数据根 wiki 库与仓内 wiki 都落 `<数据根>/wiki-history/`（P003-T034 测试 `evidence/test/P003-T034/data-root.test.js:73,76,93` 钉住的三种情形逐条保持） |
| `server.js:49` | `new RuleStore(path.join(moduleDirectory, 'rules'))` | `new RuleStore()`（缺省＝数据根库＋种子） |

种子口径：目标目录**不存在**时从仓内副本整体拷一次（`cp recursive`），已存在则一个字都不动——「数据根无库时初始化一次」；
删掉整个库目录＝回到出厂基线（语义写进 docs）。

### 2.2 规则库版本化与写入（A3/A5）

| 落点 | 改法 |
| --- | --- |
| `rule-store.js` 新增 `save(id, rego, {note})` | 校验（复用模块内 `parseRule`，等价于今天的 `validateRego` 临时目录那套）→ 旧版落 `rules-history/<id>-<rev>.rego`（rev＝正文 sha256 前 16 位，与 `WikiStore.revision` 同一口径）→ 临时文件 + rename 覆盖 `<库>/<id>.rego` |
| 新增 `history(id)` / `readRevision(id, rev)` / `rollback(id, rev)` | 列历史、读某一版原文、回滚（回滚＝把旧版当新版 save 一次，当前版因此也进历史） |
| `server.js:226-234` `writeRuleFile()` | 删除；`RegoRuleMaintainer`（`server.js:240`）改调 `this.ruleStore.save()`，与 HTTP 维护接口同一条路 |

### 2.3 维护会话留痕（A4）

`rule-store.js` 新增 `RuleSessionStore`（目录 `<数据根>/rule-sessions/`），形制对齐 `WikiWorkbench`
（`wiki-workbench.js:77-105`：`<uuid>.json`、`0o700`/`0o600`、临时文件 + rename、`list()` 按 `updated_at` 倒序回摘要）。
一份会话记：`case_id`/`case_dir`/`event_type`/`reason`/`who`（输入案卷引用）、模型草案（`id`+`rego`+`rationale`）、
校验结果、终态（`updated` / `no_change` / `failed` + 原因）。

### 2.4 接口（A5/A6）

| 方法 / 路径 | 现状 | 改法 |
| --- | --- | --- |
| `GET /api/rules` | 有（`server.js:740`） | 保留，列表顺带带 `revision` 方便人工比对 |
| `GET /api/rules/{id}` | 有（`server.js:751`） | 保留 |
| `PUT /api/rules/{id}` | 无 | 新增：要求规则管理员令牌（`hasRuleAdminAccess`，与 `PUT /api/triage/rules` 同一道闸），正文 `{rego, expected_revision}`（乐观并发，与 wiki 页面同一口径） |
| `GET /api/rules/{id}/history` | 无 | 新增：列该规则历史版本 |
| `POST /api/rules/{id}/rollback` | 无 | 新增：`{rev}` 回滚 |
| `GET /api/rules/sessions` | 无 | 新增：维护会话摘要列表（必须排在 `GET /api/rules/{id}` 之前，否则 `sessions` 会被当成规则 id） |
| `GET/POST /api/wiki/pages`、`PUT /api/wiki/pages/{path}`、`/api/wiki/sessions/*`、`publish` | 有（`server.js:838-906`） | 接口一律不动，只换它们脚下 `WikiStore` 的目录（数据根库） |
