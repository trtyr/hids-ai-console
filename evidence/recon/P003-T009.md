# P003-T009 侦查：研判记录成为可查询的主列表

侦察方式：本卡范围就在三份实现/契约文件内（`triage-monitor.js`、`server.js`、`openapi.yaml`）+ 一份模块文档，逐文件读 + `grep`，没有跨模块普查，也没有外网事实要查。

## 1 功能理解

研判记录（syslog 进口的 `TriageCase`，`triage-monitor.js` 的 `records`）现在只能整页倒序翻：`GET /api/agent/triage/cases` 只收 `count`/`offset`（`server.js:292-299`、`triage-monitor.js:111-132`）。值班人要按结论 / 事件类型 / 主机 / 时间收窄，并且能把 `threat` 顶到最前面看。本卡就是把这条列表变成可筛可排的主列表，并把 syslog 形态 ID 直接打开研判记录这条链路用测试钉住，重复次数沿用既有 `repeat_count`（不新造计数）。

## 3 依赖影响面

- `cases()` 调用方：`server.js:298`（唯一 HTTP 入口）、`syslog-pipeline.test.js:87-89`、`triage-monitor.test.js:100`。新增参数全部可选、默认行为＝旧行为（倒序 + 不过滤），调用方不用改。
- `total` 语义从「全部条数」变成「过滤后条数」：不带筛选时两者相等，`syslog-pipeline.test.js:87` 的断言不受影响。
- 路由层新校验只在带参数时触发；不带任何新参数时仍只校验 `count`/`offset`，400 文案沿用现有风格（`筛选…无效：x`）。
- 受影响测试面：`triage-monitor.test.js`、`agent-api.test.js`、`syslog-pipeline.test.js`（只跑不改）、整套 `node --test *.test.js`（基线 136 条 / 1 红＝`maintenance-startup` 软链用例，与本卡无关）。
- `web/**` 目前没有调用 `/api/agent/triage/cases`（`grep -rn "triage/cases" web/src web/pages` 无命中），新参数不会打到前端。
