## 1. 功能理解

研判智能体现在只把「误报规则候选」（`triage-rules.js` 的 JSON 规则）塞进上下文，没有 Rego 规则、没有强制查知识库、结论靠模型直接吐 JSON。本卡把三件事钉进研判链路：

1. **A1**：分析开始时用 P003-T011 的 Rego 规则库对本次 syslog 告警事实求值，命中的规则连整段 Rego 写进上下文；没命中（或没有可求值事实、规则库读不了）就在上下文里写明没有。
2. **A2**：有知识库（`wiki-store.js`）时，分析过程必须调用知识库工具（`wiki_page` / `wiki_search`）；结果里写采纳了哪一页，或为什么没采纳。
3. **A3**：结论经一个出结果的工具 `submit_conclusion` 写出，正文（`summary`）不超过 500 字；超限退回重写，不落库。
4. **A4**：回归不变量——同主机（指纹已含 `host_ip`）、同一事件秒、同样告警只分析第一次，其余进 `repeat_count`（`triage-monitor.js:289-312`），本卡不改。

## 3. 依赖影响面

- **谁调 `InvestigationAgent.run`**：`server.js:216-229`（HTTP 研判）、`triage-monitor.js:404-428`（syslog / 轮询）。新增 `ruleStore` 参数有缺省值，两处调用不用改。
- **`RuleStore` 是 P003-T011 的库**（`rule-store.js:146`）：`evaluate(fact)` 返回 `{count, matched:[{id,name,rego}]}`，装载/求值失败会抛错 → agent 侧必须 catch，写进上下文「求值失败」，不能让研判整条挂掉。
- **事实映射**（群主给定，不许自造）：`type=eventTypeFor(msgid)`、`host=payload.host_ip`、`source_ip=payload.source_ip||payload.login_ip`、`command=payload.process_command_line`、`path=payload.file_path`、`peer=payload.target_ip`、`user=payload.user_name||payload.login_username`；空字段直接不出现在事实里（Rego 的 undefined 语义）。
- **结果形状**：`triage-monitor.js:392-397` 把 `result.verdict` 原样落 `result.json`；新增 `verdict.wiki` / `verdict.rego` 是只读附加键，`cases()`（`:111-145`）只挑白名单字段，不受影响。
- **`finalizeTriageOutput`**：triage 模式下会把 `summary` 收窄到 300 字（`triage-output.js:36`），所以 500 字上限在工具入口处判、落库后 ≤300 是既有口径；deep 模式没有这一步，500 字原样保留。
- **连带要跑的测试**：`investigation-agent.test.js`（本卡）、`triage-monitor.test.js`、`syslog-pipeline.test.js`、`agent-api.test.js`、整套 `node --test`。
