## 1. 功能理解

一条 syslog 告警在 `run()` 里要发 5~6 次模型请求（若干工具轮 + 终局轮 + 独立复核轮），
每次请求都把**整段历史**再发一遍（`model-client.js:30-33` 无状态 chat/completions）。
现在这条链上反复重发的有几块纯冗余：

1. 首轮把 `match.event`（牧云事件原始 JSON，含 timeline/base64 摘要）整条内联一次，同时
   `告警详情证据` 又内联同一事件的精简视图；正文其实已经落进案卷（`03-研判事实.md`）。
2. 首轮把必查项证据视图（每项最多 3000 字）连同状态一起塞进去，模型多数不看。
3. wiki 常驻页是 4 个整页正文（每页上限 9000 字），塞进首轮、终局轮、复核轮、经验复用轮。
4. 工具结果（每次上限 20000 字）一旦进了 `messages` 就永久留在历史里，逐轮重发。
5. 复核轮用 `record.view` 未裁（单条上限 12000），与结论轮的 4000 口径不一致。
6. 嵌套序列 timeline 20 行 / commands 8 行，逐轮重发。
7. 系统提示词（triage + 场景卡 + SOP + Rego + 边界 + 输出契约，实测约 9k 字）每轮重发，
   其中 `【工具：…】`→工具名清单的展开（`investigation-agent.js:94-99`）与 `tools` schema 重复。
8. `prompts/triage.md` 的输出 JSON 模板与 `submit_conclusion` 的 schema 重复。

本卡只动**给模型看的那一层**（视图裁剪、历史折叠、常驻件降级），不动研判判定逻辑。

### 6.1 复现证据

- **BUG1（blocker，挂死）**：`boundSyslogView`（`evidence-view.js:319`）第二段截断循环没有收敛条件——
  截断后的字段仍是「最长的字符串」，同一字段被反复截断（长度稳定在 ~163 字），总量若始终 >3000 就死循环。
  复现：`payload` 40 个短字段 × 100 字（总量 4575，无单条 >600）→ `timeout 8 node repro` **exit=124（超时被杀）**。
- **BUG2（major，read_evidence 取回空壳）**：`investigation-agent.js:730` 的注册循环把任何带 `evidence_id` 的工具回包都写进
  `evidenceFullText`；`already_queried` 回包（`:669-670`）也带 `evidence_id` → **覆写掉该证据原来的全文**。
  后果两处：折叠时 `foldedToolMessage` 解析到的是 stub（无 `view`）→ 摘要全空；`read_evidence`（`:613-625`）从
  `evidenceFullText` 取回 → 返回无 `view` 的 stub，而 note 还叫模型「调用 read_evidence 取回完整视图」。
- **BUG3（minor，schema 过期）**：`:234-236` 的 `wiki_page` 仍写「读取完整 Wiki 页面」、`properties` 缺 `keyword`，
  而实现（`:656`）已改成摘要 + 命中段且支持 `keyword`。
