# P003-T045 侦查：日志落盘（文件 sink / 轮转 / 查询与清理 API）

## 1. 功能理解

`log.js` 目前只往 stdout 写一行一条 JSON（`log.js:1-3`、`log.js:48-56`）。本卡让它**可选地再落一份文件**（配置 `HIDS_LOG_FILE` 才落，不配维持 stdout-only）、单文件超限轮转并按保留份数清老文件，再开两个管理接口：`GET /api/logs`（按 event / level / 时间范围过滤 + 分页，**读盘上的文件**）、`POST /api/logs/cleanup`（按时间 / 总大小清理历史文件，留痕）。脱敏三道闸（键名命中 / 字符串凭据擦除 / 请求头不进日志）原地沿用，落盘与查询结果里同样不许出现 Authorization / Cookie / Token。

## 3. 依赖影响面

- **谁 import `log`**：`server.js:23`、`config-store.js`、`triage-monitor.js`、`syslog-input.js`、`maintenance-server.js`、`package-policy.js`、`syslog-case.js`——全部走 `import { log }` 的 ESM 活绑定，`useJournal`/`useLogFile` 换实例对它们立刻生效（`log.js:61` 的注释就是这么写的）。
- **连带的既有测试**：`error-observability.test.js`、`evidence/test/P003-T023|T027|T044` 都注入内存 journal；只要 `createJournal` 签名与缺省行为不变，它们不受影响。
- **T044 的数据盘点**：`dataStores()` 里 `logs` 这一类＝数据根顶层的 `*.log`（`server.js:617-622` 注释、T044 测试写 `hids.log`）——**落盘文件缺省名取 `<数据根>/hids.log`、轮转出的历史文件仍是 `*.log` 后缀**，盘点与 `data/cleanup` 的 `logs` 类才看得见它们。
- **T025 启动闸门**：3 个新键都**不进必填闸门**（不配＝不落文件，合法部署），`configSummary` 八键形状不变（A2 那条测试按 schema 逐字段验，多一个键就会红）。
- 新路由不碰上游、不碰模型：查询与清理只读/删本地文件。

## 4. 改动方案 checklist

- [x] `log.js`：`logFileOptions(env)` 解析三个键（空/坏值口径：`HIDS_LOG_FILE` 空串＝不落；`HIDS_LOG_MAX_BYTES`、`HIDS_LOG_KEEP` 非正整数回落缺省）
- [x] `log.js`：`createFileSink({file,maxBytes,keep,now})`——append 一行、内存计字节、`size+新增 > maxBytes && size>0` 才轮转，**当前这条写进新文件**（不丢）；轮转名 `<stem>.<ISO 去冒号>Z<ext>`（`.log` 结尾）；按 `keep` 删最老的历史；I/O 异常吞掉不抛（回退成继续往原文件写）

## 5. 负范围（明确不做）

- 不引日志依赖（pino / winston 等一律不装）：`package.json` 不动，只用 `node:fs`。
- 不做按行/按天分文件、不做压缩、不做跨进程文件锁：单进程假设与现状一致（`log.js:59` 一个实例）。
- 不改 stdout 行为、不改行形状（`time/level/event` 三键与脱敏规则）、不改 `createJournal` 签名（既有四套测试靠它）。
- 不给两条新路由加新的鉴权：与 `/api/config`、`/api/data/*` 同口径（Basic 认证闸门 + 令牌无关）。
- 不动 `web/**`、不动 `configSummary` 的八键形状、不把三个新键塞进必填闸门。
- `docs/architecture.md` §3.6（log.js 的权威章节）原不在 scope：**已向群主申报并获批加进 scope**（只改落盘/轮转口径、事件表加 `log.cleaned`、重取 log.js 锚点），见报告「未决」第 1 条。
