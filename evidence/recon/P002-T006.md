## 1 功能理解

一句话：把壳里占位的「规则」页换成真页面——从 `GET /api/triage/rules` 读前置规则集（`config` / `revision` / `writable`），

设计稿的立场（`rules-notes.md:10`）：`config` 在文档里是自由对象，所以页面**不预设规则字段**，按真实 config 递归生成表单。
本卡沿用：表单不认字段名，只认 JSON 类型。

### 2.3 数据来源：**形态 B（对接已就绪后端）**

判据：`openapi.yaml` 三个 operation 齐全 + `server.js` 实现 + 能起的 base URL（`web/serve.js` 反代 `/api`）。

四样（逐条抄自文档/实现）：

| 项 | 值 | 出处 |
| --- | --- | --- |
| operation 1 | `GET /api/triage/rules`（`getRules`，无参数） | `openapi.yaml:372-382`；实现 `server.js:181-184` |
| operation 2 | `POST /api/triage/rules/validate`（`validateRules`），body `{ config }` → `{ valid: true, count: <int> }` | `openapi.yaml:406-431`；实现 `server.js:186-192` |
| operation 3 | `PUT /api/triage/rules`（`saveRules`），body `{ config, expected_revision }`，header `X-Rule-Admin-Token` | `openapi.yaml:383-405`；实现 `server.js:193-204` |
| 成功体 | `RuleSetResponse`：`config`（object, additionalProperties:true）、`revision`（string\|null）、`writable`（boolean）、**additionalProperties: true** | `openapi.yaml:851-857` |
| 实现多给的键 | `origin`（`file`/`example`/`invalid`）、`error`（配置坏时的原因） | `triage-rules.js:223-238`，`server.js:181-184` 原样展开 |
| `revision` 何时为 null | 配置取自 `triage-rules.example.json`（文件还没保存过） | `triage-rules.js:231` |
| `writable` 语义 | `Boolean(process.env.HIDS_RULE_ADMIN_TOKEN)`——服务端配没配令牌，不是当前用户权限 | `server.js:182`、`:68` 附近的 `createServer` 默认参数 |
| 保存成功体 | `{ config, origin:'file', revision }`（`JsonObject`，文档没细化） | `server.js:201-202`、`triage-rules.js:240-256` |
| 错误码 | 401 纯文本「需要登录后访问」（非 JSON，带 `WWW-Authenticate`）；400/403/503 `{ error }`；PUT 另有 **409**「规则配置已变化，请刷新后重试」与 GET **502**「规则配置读取失败：…」——两条都**不在 openapi 里** | `server.js:70-74`、`:57`、`:186-204`、`triage-rules.js:245` |
| 鉴权 | 每个请求 HTTP Basic（`server.js:130` `hasAccess`）；PUT 另需 `X-Rule-Admin-Token`（`:79-86` 定时比较） | `server.js:79-86`、`:130` |
| 校验实现约束 | `validateRuleSet` 要求 `config` 恰为 `{schema_version:1, enabled:boolean, rules:[]}`，无第四个键，`rules` ≤200 条，逐条校验 `id/event_type/action/enabled/host_id/...` | `triage-rules.js:126-138` |
| `count` 的真实含义 | `body.config.rules.length`（读实现：`server.js:190`） | `server.js:186-192` |

**稿 vs 接口的差**（A2 处理）：

1. `config` 稿是「自由对象」、示例 `{}`；实现是**固定三键**。→ 前端两个视图都不预设字段（符合稿），但空对象 `{}` 拿去校验会被实现判 400
   「规则集格式无效」——这是接口事实，界面照实显示服务端原话，不算前端编造。
2. 稿的「条目数」来自校验返回 `count`；实现给的是 `rules.length`。控件照稿，值只来自响应。
3. 稿「保存成功生成新 revision」是演示；实现的 PUT 回真 revision → 用返回值，不自己造。
4. 稿「令牌错误 403」与实现一致（`server.js:195`），保留。
5. 稿没有画 409 / 502，也没画 `origin` / `error` 两键 → 藏掉（不新增区块，只在错误/日志里带服务端原话，见 §4 方案 3）。
