# P003-T011 侦查 · Rego 规则库与求值

## 1. 功能理解

把「一条告警该被哪条策略套上」从写死的 JSON 规则集里拆出来，做成**文件形态的策略库**：一个目录下一条规则一个 `.rego` 文件，每条规则有显示名；服务能列出规则、按 id 读回 Rego 原文；给一条告警事实，返回命中的规则名与 Rego 正文，没命中就明确给空。本卡只做「库 + 求值 + 只读 API」，不改业务进程的规则预筛接线。

## 3. 依赖影响面

- **调用方**：无。`rule-store.js` 是新模块，唯一调用方是 `server.js` 的三条新路由与 `rule-store.test.js`。
- **被它调用**：`node:fs/promises`、`node:path`，不碰网络、不碰 `.data/`、不依赖环境变量。
- **共享状态**：无。`createServer` 只把 `ruleStore` 当只读依赖传进闭包；默认值是模块级 `new RuleStore(<仓根>/rules)`，与现有 `triageRuleEngine` 的位置参数互不影响。
- **命名冲突**：现有 `triage-rules.js` / `/api/triage/rules` 是 JSON 误报规则集，本卡是 Rego 策略库，**不复用、不改名、不合并**；路由用 `/api/rules` 前缀区分。
- **连带要跑的测试**：`node --test rule-store.test.js`；全后端 `node --test *.test.js`（基线 146 项 / 失败 1 项 `maintenance-startup.test.js`，`docs/_meta/gaps.md` 已记录是目录布局导致的环境性失败，非本卡引入）。
- **前端**：`web/**` 禁改，本卡不接页面；新接口以 `openapi.yaml` 为准。

## 5. 负范围（明确不做）

- **不接研判预筛**：不改 `triage-monitor.js`、`investigation-agent.js`、`triage-rules.js`，不影响现有 `rule_evaluation` 流程。
- **不做写接口**：不提供上传/编辑/删除 Rego 的 API；规则随代码库发布。
- **不接页面**：`web/**` 禁改，不加前端入口。
- **不引依赖**：`package.json` 不在 scope，且仓内零依赖风格；不引 OPA / opa-wasm / regorus，求值用本仓自带子集实现。
- **不实现完整 Rego**：只支持 `package`、`default match := false`、单个 `match if { ... }` 体、`==` / `!=` / `contains` / `startswith` / `endswith` / `not`；遇到集合、函数定义、`import future.keywords`、`else`、多规则体等，装载即报错（带 `file:line`），**不静默跳过**。
- **不动文档目录**：`docs/modules/**`、`docs/_meta/**` 不在 scope，本次对外契约只落 `openapi.yaml`。
