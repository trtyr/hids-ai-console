结论与口径：
- **读页面不需要管理员令牌**（在 `server.js:250` 的令牌闸之前就 return 了）→ 列表 + 正文可做真页面。
- **写能力的接口全要管理员令牌**：`/api/wiki/health`、`/api/wiki/sessions*`。控制台没有这个令牌的来源（`web/src/credentials.js` 只有 Basic 对，且禁改）→ 实测 `503 尚未配置知识库管理员凭据`。设计稿的「提交审核」= `POST /api/wiki/sessions`，**在这个控制台里永远 503** → 按 A2 藏掉入口 + 记 backend-findings（不留死按钮，D003）。
- 没有「更新页面」的写接口（`openapi.yaml` 的 `/api/wiki/*` 只有 pages 两个 GET 与 sessions 一族）→ 编辑只存本机草稿，界面上如实标注，不做「已保存到服务器」。

## 9 第三轮整改（tester 判 fail：F1 major + F2/F3 minor）

**功能理解**：编辑页签有未保存修改时，从**页面级**路径离开知识库页（壳侧栏导航 / 浏览器后退 / 关标签页刷新）

**依赖影响面**

- 侧栏锚点是**默认行为**导航（壳没挂 click 监听，`shell.js:83` 只做 `aria-current`）→ `preventDefault()` 就能拦，且不需要改壳。
- 浏览器后退在**同文档**内不触发 `beforeunload`，`app.js` 的 `hashchange` 会在同一次事件派发里先跑完 `page.render`，页面 DOM 已被换掉 → 只能提前用「同 URL 守卫条目」（`history.pushState`）把 URL 变化本身挡住：后退落回同 URL 的同一条目 → 只 `popstate`、不 `hashchange` → 页面不被重建，草稿还在。
- 页面模块没有 unmount 钩子（`router.js:8-12` 的 page 契约只有 `render`）→ document/window 级监听器靠 `host.isConnected` 自净 + `MutationObserver` 在 host 被换掉时立刻摘除。
- 不影响其它页面：守卫只在 `.knowledge` 挂载且 `isDirty()` 为真时生效，不脏时一个都不拦。
