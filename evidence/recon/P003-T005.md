## 1 功能理解

四件事，都是「出错时别把内部结构/内部文案漏给调用方，也别让故障静默」：

1. **A1（B24）**：知识库页面读不到时，404 正文里带着服务器绝对路径——`readFile` 的 ENOENT message 是 `ENOENT: no such file or directory, open '<绝对路径>'`，被原样回给 curl。
2. **A2（B27）**：syslog UDP 绑定失败（端口被占、权限不足）只落一行 `console.error`，`/api/agent/triage/status` 上仍然是 `input_mode: syslog`、`last_error: null`——值班人看不出「这个进程一条 syslog 也收不到」。
3. **A3（B21）**：`/api/status` 连不上牧云回 502（正文 `{configured, connected, reason}`）。这是有意的语义，但只在 openapi.yaml 里，且归属 T004；本卡不改代码，把契约写进报告交出去。
4. **A4（B26）**：`requireAccess` 的 401 正文是纯文本，但响应头没有 `Content-Type`；openapi.yaml 的 `BusinessUnauthorized`（`openapi.yaml:1013-1020`）声明的是 `text/plain`。
5. **A5（B28）**：`POST /api/triage/rules/validate` 直接读 `body.config` / `body.config.rules`，请求正文是 `null` / 数组 / 缺 `config` 时抛 TypeError，把 `Cannot read properties of null (reading 'config')` 这类英文内部文案回给调用方。
