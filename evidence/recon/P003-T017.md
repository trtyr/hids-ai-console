## 4. 数据缺口（A1 三列）与取值口径

`RegoRuleSummary` 只有 `id / name / description / file`（`openapi.yaml:1839-1847`）：没有 `effect` / `enabled` / `source` / `updated_at`。
A1 要「名字 / 一句话 / 效果 / 开没开 / 从哪来」五列，群主 2026-11-19 拍板（need_decision 回复）：

| 列 | 取值 | 性质 |
| --- | --- | --- |
| 名字 | `name` | 接口字段 |
| 一句话 | `description`（null → 「未写说明」） | 接口字段 |
| 效果 | 「放行」 | **展示默认**（D017：这轮只有放行，不先发明别的效果） |
| 开没开 | 「开」 | **展示默认**（装载着的规则就是在用的；`rule-store.js` 载入即生效，没有关掉的数据） |
| 从哪来 | 「未标注」 | **展示默认**，不许猜成「人建的」或「误报反哺的」；`prompts/rule-maintenance.md` 只要求 `# name:` / `# description:`，Rego 里没有来源注释 |

D017 提的「更新时间」也按同一口径不画（没有 `updated_at`）。D017 的「按效果 / 开关 / 来源筛」同样不做——三列都是常量，筛什么都不会变（报告未决）。
后端补 `effect / enabled / source / updated_at` 的卡今晚不开（群主口径），前端只在这一处映射改。

D017 明写「程序门禁编辑页不要当成这个」、D020「列表加详情，按 D017」——即新页没有稿。
