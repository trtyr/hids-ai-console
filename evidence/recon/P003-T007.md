## 八、执行结果与偏差（收工回读）

- 时间范围：按群主拍板的方案 A 实现（`select` 预设，只发 `from`），样式与旁边四个下拉同一套（`alerts.css` 的 `.filters select`）。
- 等级补「严重」、研判状态补「未研判」：同页表格列本来就有这两个值，取同级 `<option>` 为最近邻。
- 升序排序不做：接口没有方向参数，`aria-sort` 只报 `descending`；同一列再点不发请求。
- 知识库文案：保存按钮「保存到服务器」、脚注「已保存到服务器 / 未保存的修改」、来源「正文来源：服务器正文」、冲突条带「刷新正文」——均取规则页保存条为最近邻，记账在报告。
- 结果：`web/` 全量 `node --test` 327 条全绿（改动前基线 299 条，本卡新增 28 条）。

## 六、缺口与处理（design-intake §二）

| 缺口 | 处理 |
| --- | --- |
| 筛选条「时间范围」：稿只画了搜索 + 四个下拉（`alerts-notes.md:125` 把它列为待补） | 🔴 无先例 → 已 `contact_supervisor` 问群主（带方案：用同一条里的 `select` 预设「全部时间 / 近 24 小时 / 近 7 天 / 近 30 天」，传 `from`） |
| 等级筛选稿只有 高/中/低三档，接口四档（critical） | 加第四项「严重」：同页表格等级列本来就会出现「严重」，取同级 `<option>` 为最近邻，记账 |
| 研判状态筛选稿只有 排队中/研判中/完成/失败，接口另有 `not_queued` | 加「未研判」：同页表格状态列本来就会显示「未研判」，同级 `<option>` 最近邻，记账 |
| 表头「同列再点切换升降序」 | 接口只有 `sort=time|level`（都是固定方向）→ 只做降序、`aria-sort` 只报 descending，升序不做，记账 |
| 筛选结果超过扫描窗口（`truncated: true`） | 稿没有这一格 → 复用同类提示条（`alerts.html:967-984` 的 `.notice` 部分失败条）作最近邻，文案另写 |
| 知识库「保存草稿」与「正文来源：本地草稿」 | D003 选 A 后稿过期；按钮改「保存到服务器」、来源标「接口正文 / 已保存到服务器」，取规则页保存条的最近邻，记账 |
| 知识库冲突（409） | 稿没有冲突态 → 取规则页 409「刷新后重编辑」的最近邻 |
