## 三、实跑的命令与输出

### 3.1 规则集校验的拒绝理由

```
$ node --input-type=module -e "import { validateRuleSet } from './triage-rules.js'; ..."
schema_version=2 -> 规则集格式无效
extra-key -> 规则集格式无效
empty-rules -> ok
```

`rules: []` 是合法的（上限 200，不是下限 1）——triage-rules.js:128 只判上界。

### 3.2 读不到文件时的三种 origin

```
evaluate(no file) -> {"status":"disabled","reason":"未配置规则集"}
readConfig(no file) -> origin=example revision=null rules=1
```

`readConfig` 回落到同目录的示例文件（triage-rules.js:7、228-231）；
`evaluate` 不回落，直接给 `disabled`（triage-rules.js:262）。

### 3.3 文件存在但内容非法

```
evaluate(invalid) -> {"status":"error","reason":"规则集校验失败：Expected property name or '}' in JSON at position 2 ..."}
readConfig(invalid) -> origin=invalid revision=0228f717792ffbc0 error=Expected property name ...
```

`readConfig` 的 `invalid` 分支仍然带回原文件的 revision（triage-rules.js:235-236），
所以调用方拿着这个 revision 去保存，会撞上 409。

### 3.4 乐观并发的三个动作

```
save#1(expected=null) -> revision=d2adef2ee5b86abf origin=file
save#2(expected=r1) -> revision=794d43379f10029b
save#3(expected=r1, 已过期) -> status=409 规则配置已变化，请刷新后重试
dir entries -> rules.json
dir mode -> 700 | file mode -> 600
# 700/600 是 umask 002 下的实测。umask 022 时同一 mkdir 会得到 775，mode 参数会被 umask 吃掉。
file content -> "{\n  \"schema_version\": 1,\n  \"enabled\": true,\n  \"rules\": []\n}\n"
```

要点：

- 文件不存在时当前 revision 是 `null`（回落示例），所以**首次创建必须传 `null`**；
  传 `undefined` 会得到 `null !== undefined`，直接 409（triage-rules.js:244）。
- revision 是文件**文本内容**的 SHA-256 前 16 位（triage-rules.js:231、252）。
- 目录 0700、文件 0600、临时文件 `wx` 不覆盖、落盘后没有残留 `.tmp`（triage-rules.js:248-251）。

### 3.5 评估的三个状态

用一条 `honeypot` 规则 + 一个假工具箱（不连牧云）跑出来：

```

          {"field":"honeypot_address","value":"10.0.0.9","pointer":"/address"},
          {"field":"honeypot_type","value":"ssh","pointer":"/type"}]
```

把 syslog 的事件号改成 999 → `identity_unverified`；
把详情的 `state` 改成 2 → `identity_unverified`。

`process_path`、`process_command_line`（triage-rules.js:197-206），
我第一版假载荷没带这几个字段。
