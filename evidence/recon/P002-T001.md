### 2.3 数据来源：形态 B（对接已就绪后端）

判据：给了接口文档（`openapi.yaml`）＋实现（`server.js`）＋能起的 base URL。

四样（只读这四样）：

| # | 读到什么 | 出处 |
| --- | --- | --- |
| 1 | 用到的 operation：`GET /api/session`（`getSession`，无参数） | `openapi.yaml:26-41`；实现 `server.js:134` |
| 2 | 字段：200 体 `{ authenticated: true }`（`required: [authenticated]`，const true），**无账号名、无角色字段** | `openapi.yaml:36-40` |
| 3 | 错误：`401` → `components/responses/BusinessUnauthorized`（`openapi.yaml:41`）；实现是 `res.writeHead(401, WWW-Authenticate: Basic …)` + 纯文本正文「需要登录后访问」，**不是 JSON** | `server.js:70-74` |
| 4 | 鉴权：HTTP Basic，**每个请求**都过 `hasAccess`（`server.js:58-68`、`:130`）；用户名默认 `admin`（`server.js:65`）；未配置 `HIDS_BASIC_AUTH_PASSWORD` 时 `hasAccess` 恒真（`:59`） | `server.js:58-68`、`:130` |

由此定的两条实现口径：

- 登录＝把表单里的账号/密码拼成 `Basic base64(user:pass)` 打 `GET /api/session`：200 → 进壳；401 → 显示错误；网络失败 → 网络错误提示。**不写死演示账号**（稿里的 `hids/hids-2026` 与 `DEMO` 常量整段不要）。
- 之后的每个请求都要带同一份凭据 → 凭据放内存（`sessionStorage` 也不放，避免落盘；刷新＝重新登录）。
- 401 正文不是 JSON → adapter 不按 JSON 解析错误体；`401` 即「账号或密码不对」，不把服务端正文直接甩给用户。

**A3 直接由此得出**：会话接口只返回 `authenticated`，没有账号名/角色 → 壳上**不显示账号名与角色**，不编。`openapi.yaml` 未定义身份字段名，也不去猜字段名。

### 2.4 后端现状（为浏览器验证准备）

- `server.js` 没有静态文件路由（全文 grep `serveStatic|readFile|createReadStream` 无命中）→ `web/` 需要自带一个静态服务才能「打开」。
- 后端无 CORS 头（`json()` 只设 `Content-Type/Cache-Control/X-Content-Type-Options`，`server.js:53-56`）→ 跨端口直连会被浏览器拦。故 `web/serve.js` 静态服务同时把 `/api/*` 反代到 `HIDS_API_ORIGIN`（默认 `http://127.0.0.1:8080`），同源访问。
- 起 401 现场需要设 `HIDS_BASIC_AUTH_USER` / `HIDS_BASIC_AUTH_PASSWORD`（`server.js:117-118` 的默认值取自环境变量）。
