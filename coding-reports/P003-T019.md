## 二、验收逐条

### A1 案卷、研判记录、基线这些运行态写在仓库下的 `.data/`，不写到源码目录的上一级

- **路径真源只剩一处**：`server.js:805-818` 的 `runtimePaths()`；接线全走它（`server.js:41,42,47,51,52,53,54,96`）。
  `grep -c "'backend'" server.js` → `0`（改前 8 处）。
- **单测 3 条**（`evidence/test/P003-T019/data-dir.test.js`，`node --test evidence/test/P003-T019/data-dir.test.js` → `ℹ pass 3 / fail 0 / duration_ms 87`）：
  1. `A1 九条运行态路径都在仓库内 .data/ 下，且没有一处经过 backend/ 或上一级目录`——逐条断言 `paths[k] === path.join(仓库, 布局[k])`，
     且 `path.relative(仓库, 实际)` 不以 `..` 开头、路径段里没有 `backend`，键集合与布局表完全一致（多一条少一条都红）。
  2. `A1 换一个目录时同构`——`runtimePaths(<另一个目录>)` 九条全跟着走，证明没有把仓库路径写死在函数里。
  3. `A1 回归钉子`——直接读 `server.js` 源码，断言不再出现 `'backend'` 段、不再出现 `path.resolve(moduleDirectory, '..')`、
     且模块级 `const runtime = runtimePaths(moduleDirectory);` 还在（有人绕过 `runtimePaths` 自己拼路径就红）。
- **断言能失败（变异验证）**：把 `server.js:806` 的 `path.join(directory, '.data')` 改成 `path.join(directory, '..', 'backend', '.data')`，
  三条单测全红，首条报 `AssertionError: data 应落在仓库内 .data，实际 .../hids-ai-console/backend/.data`；改回全绿。
