## 2. 接口契约（实现口径）

`openapi.yaml` 在本卡 scope 内但卡上 forbidden 写明「留给 T004」，本卡未改动它——**契约以本节为准，T004 需把它落进 `openapi.yaml` 的 `/api/wiki/pages/{pagePath}`**（见「未决」①）。

```
PUT /api/wiki/pages/{pagePath}
鉴权：HTTP Basic（控制台账号 HIDS_BASIC_AUTH_USER / HIDS_BASIC_AUTH_PASSWORD）
      不需要 X-Prompt-Admin-Token（D003 选 A）
路径：pagePath 为相对路径，斜杠需 URL 编码，如 honeypot%2FHP-01.md
      只允许判据目录下 <ID>.md（common / webshell / memwebshell / rasp / revshell /
      suspicious-command / cmdaudit / malware / bruteforce / honeypot / elevation /
      abnormal-login / net / customer-experience），其余一律 400
请求体（application/json，正文上限 120000 字符）：
  expected_revision  string  必填，16 位十六进制（页面的 revision 指纹）
  content            string  必填，1 到 30000 字，整篇 Markdown（含 --- 头部元数据）
```

响应：

| 状态 | 场景 | 体 |
| --- | --- | --- |
| 200 | 写入成功 | `WikiPage`：`path` / `id` / `title` / `status` / `updated` / `revision`（新值）/ `characters` / `content`（落盘后的整篇） |
| 400 | `expected_revision` 缺失或不是 16 位十六进制 | `{"error":"缺少有效的页面版本，请刷新后重试"}` |
| 400 | 路径越界 / 不在判据目录 / 后缀不是 `.md` | `{"error":"知识库页面路径无效"}` 或 `{"error":"只允许修订判据页和客户经验页"}` |
| 400 | URI 编码坏 | `{"error":"知识库页面路径编码无效"}` |
| 400 | 正文不合规（空 / 超 30000 字 / 含 `\0` / ID 变了 / 状态不在 active·draft·deprecated / 缺 `evidence:` 或 `source:`） | `{"error":"页面正文必须为 1 到 30000 字"}` 等原文 |
| 400 | `PUT /api/wiki/pages/` 没写页面 | `{"error":"请在路径里写明要修改的页面"}` |
| 401 | 没带 Basic 或口令不对（部署配了 `HIDS_BASIC_AUTH_PASSWORD` 时） | 文本 `需要登录后访问`，带 `WWW-Authenticate: Basic` |
| 404 | 页面不存在 | `{"error":"ENOENT: ..."}` |
| 409 | `expected_revision` 与当前页面不符 | `{"error":"知识库页面已更新，请刷新后再提交"}`，不写盘 |

写盘语义（未改动，`wiki-store.js:152-176`）：先备份旧版到 `<wiki 同级>/.data/wiki-history/<ID>-<旧revision>.md` → 写 `<目标>.<uuid>.tmp` → `rename` 覆盖 → 追加 `log.md`（含操作人）。三个写方法共用 `pending` 串行链，同一版本并发两次提交 = 一次 200、一次 409。

`log.md` 新增内容形如：

```
## [<ISO 时间>] update | HP-01
影响判据：HP-01
要点：通过控制台直接编辑（操作人 operator）；上版 bc0e767a89ea8188，新版 71cfd2f4df01ece2。
```

## 3. 验收逐条

真机命令（工作树内跑，临时 wiki 目录，`HIDS_PORT=43401`，Basic `operator:op-pass`）：

```
$ curl -s -u operator:op-pass "http://127.0.0.1:43401/api/wiki/pages/honeypot%2FHP-01.md" | node -e '…取 revision'
{"id":"HP-01","revision":"bc0e767a89ea8188"}
$ curl -s -o put1.json -w "HTTP %{http_code}" -u operator:op-pass -H 'content-type: application/json' -X PUT \
    --data-binary '{"content":"---\nid: HP-01\n…\n外网背景扫描必须核对请求。\n","expected_revision":"bc0e767a89ea8188"}' \
    "http://127.0.0.1:43401/api/wiki/pages/honeypot%2FHP-01.md"
HTTP 200
{"id":"HP-01","path":"honeypot/HP-01.md","revision":"71cfd2f4df01ece2","正文含必须核对":true}

外网背景扫描必须核对请求。
```

单测：`wiki-current.test.js:56`（旧 revision → 新 revision、盘上正文变了、`log.md` 记下操作人 operator、GET 复读为新 revision）。

### A2 409 / 400 越界 / 401 未授权

```
$ curl -s -w " HTTP %{http_code}" -u operator:op-pass -X PUT --data-binary '<同一个旧 revision>' …
{"error":"知识库页面已更新，请刷新后再提交"} HTTP 409
$ curl -s -w " HTTP %{http_code}" -u operator:op-pass -X PUT --data-binary '<同上>' \
    "http://127.0.0.1:43401/api/wiki/pages/..%2Fserver.js"
{"error":"只允许修订判据页和客户经验页"} HTTP 400
$ curl -s -w " HTTP %{http_code}" -X PUT --data-binary '<同上>' "…/honeypot%2FHP-01.md"
需要登录后访问 HTTP 401
```

单测：`wiki-current.test.js:80`——401（匿名 / 只带管理员令牌）、409（旧版本且页面内容不变）、400（无 `expected_revision`、`..%2Fserver.js`、`honeypot%2F..%2F..%2Fserver.js`、`%2Fetc%2Fpasswd`、空页面路径）、404（`HP-09` 不存在），末尾复核被拒请求一条都没改页面。

### A3 写入原子：先临时文件再 rename，中途失败不留半篇

实现：`wiki-store.js:170-172`（`<目标>.<uuid>.tmp` `wx` 写 → `rename`）。单测 `wiki-current.test.js:113`：

- 把页面目录改成只读 → `update()` 抛 `EACCES` → 目录里只有 `HP-01.md`（无 `.tmp` 残留）、原文一字未变；
- 失败后串行写队列没卡死，下一次正确版本能写成功；
- 同一 revision 并发两次提交 → 一次 fulfilled、一次 rejected（`status 409`），不互相覆盖。

（`root` 下该用例 `t.skip`，只读目录模拟不成立。）

### A4 身份口径按 D003，不两套并存

- 写路径只认控制台 Basic：`PUT` 分支在 `server.js:313`，**排**在 `server.js:331-332` 的「没有 `promptAdminToken` → 503 / 令牌错 → 403」闸之前；`hasPromptAdminAccess` 在写路径上一次都没被调用（全树只有 `/api/wiki/health`、`/api/wiki/sessions*` 用它）。
- 反证（单测 `wiki-current.test.js:80`）：请求只带 `X-Prompt-Admin-Token: test-admin-token`、不带 Basic → **401**，说明写知识库不认维护端令牌；只带 Basic、不带令牌 → 200 可写，而同一个 Basic 账号 `GET /api/wiki/sessions` 仍 **403**，说明会话族的口径没被改动、两套身份没有并成一套。
- 身份的唯一来源是 `server.js:185` 的 `access`（`HIDS_BASIC_AUTH_USER` / `HIDS_BASIC_AUTH_PASSWORD`），响应与 `log.md` 都用它，没引入第二个身份来源。
