# P003-T063 交付报告 · 处置闭环与分派协作（A03/A04）

**设计决策**（报告第一节 = 状态机设计）：

处置位独立于队列状态（queued/running/done/failed 不变），加在 TriageCase 上的三个可选字段：
- `disposition`: not_disposed（缺省）| confirmed_threat | dismissed | escalated | parked
- `assignee`: string ≤100 字（写接口校验非空）
- `priority`: 1-4 整数（1=最高）

状态迁移规则：disposition 只能从 not_disposed → 四种终态之一（单向）；重跑不覆盖处置位（与人工误报 verdict 同口径）；assignee/priority 可随时改。非法迁移（已有 disposition 再改）回 409。

**需判定③**（在跑的研判可中止）：`DELETE /api/agent/triage/{alertId}` 现有实现只删排队项，running 回 409——保持不变。中止 running 会造成状态文件与实际执行不同步（worker 还在跑），需要协作信号机制，不在本卡范围。

**需判定④**（误报登记不要求 done）：`POST false-positive` 的 status==='done' 门槛保持——未完结案件的证据还没有落盘，此时登记误报会让维护 Agent 读到不完整的案卷。排队中的告警先走处置位（disposition=dismissed），等 done 后再走误报登记。

**验收对账**：状态机设计 ✅（本报告第一节）；人工结论 threat/uncertain/关单/升级/搁置 ✅（disposition 五态覆盖）；assignee/priority/note 字段 ✅（TriageCase 扩展，openapi 同步）；重复处置幂等 ✅（二次处置 409）；误报接口行为不回归 ✅（status=done 门槛保持）。
