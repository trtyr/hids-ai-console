## 一、改了什么

### 1. `log.js`：`traceModelCall()` —— 一次模型调用两条 `ai.model_call`

`log.js:71-143`。域 / 角色 / 轮次 / `attempt` / `phase` / 方向 / 输入输出字符量 / 耗时 / 结局一次收口：

- `direction: 'request'` 在调用发出去时落：`input_chars`（`JSON.stringify({messages, tools}).length`）、`messages` / `tools` 条数；
- `direction: 'response'` 在回包或失败时落：`input_chars` + `output_chars`（回包 `content` 字数）+ `duration_ms` + `outcome` + `tool_calls`，失败多一个 `error`（≤120 字）。
- 结局四值：`ok` / `timeout`（`TimeoutError` / 文案含 timeout·超时·aborted）/ `invalid_json`（`decode` 抛）/ `error`（其余）。
- **正文与密钥一个字都不进字段**：请求体只在函数栈上算长度；`error` 仍过 `log.js` 现成的两道脱敏闸（键名 + Basic/Bearer/token=）。
- 拆两条的理由写进了注释与 `docs/architecture.md:153`：调用挂死 / 进程被 kill 时，只有 request 那条能证明「发过」。

### 3. 研判会话回放（A3）

- 结果体新增 `turns`（`investigation-agent.js:476` 声明、`:91-96` 的 `turnRecord()`、`:1062` 随结果落盘）：每次模型调用一行——`turn / phase / role / attempt / messages / input_chars / reply_chars / tools / outcome / conclusion / note`，**不含正文**；`tools` 是「这一轮模型点了哪些工具」。
- 新增纯函数 `replayInvestigation(record)`（`investigation-agent.js:1152-1176`）：只读已落盘的研判记录，产出
  `{alert_id, mode, model, saved_at, prompt_version, degraded, counts, turns, tool_calls, verdicts, final, review, validation, evidence}`；
  工具序列由 `trace` 六类白名单映射（`tool` / `tool_reuse` / `tool_error` / `read_evidence` / `case_file` / `wiki`），请求参数与正文不进回放。
- 新路由 `GET /api/agent/investigations/{alertId}/replay`（`server.js:1301-1312`）：**排在既有 `GET /api/agent/investigations/{alertId}` 的 `startsWith` 之前**（否则 `/replay` 会被当成告警 ID 后半段回 400）；`mode` 与两条既有路由同一套；404 / 400 文案与既有路由一致。
- 旧记录（本卡之前落的案卷）没有 `turns`：`turns: []` / `verdicts: []` / `counts.turns: 0`，`tool_calls` 仍按 `trace` 给出——不 500、不伪造。
