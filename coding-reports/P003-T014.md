## 二、验收逐条

### A1 从一条告警创建溯源。已有则返回那条，没有则开始往回走

- `trace-board.js:324-331`：先 `this.running` 再读盘；已有直接 `get`（running 但不在跑会标 interrupted）后返回 `{created:false}`。`start`（旧签名）转调，行为一致。
- 没板才建：牧云告警走 `get_*_event` → `traceBoardSeed`；syslog 告警走分析证据（A4）；IP 走 `traceIpSeed`。
- HTTP：`server.js:316-318`，`created ? 202 : 200`。
- 单测：`trace-board.test.js`「A1 已有溯源直接返回那条」（toolbox 里 `investigation` 一调就抛，证明没重查）、「A1 没有溯源时从告警新建」；`agent-api.test.js`「POST 白板：已有返回 200，新建返回 202」。

### A2 列表能给出类型、主机、告警时间、状态、链长、有没有断点、更新时间，能分页能筛

- 字段：`summarizeBoard`（`trace-board.js:75-85`）给 `type` / `host` / `occurred_at` / `status` / `chain_length`（hops 个数，含告警那一跳）/ `has_gaps` / `updated_at`（另留 `id` / `alert_id` / `title` / `created_at`）。
- 筛选：`page`（`trace-board.js:282-293`）先按 status（多选）/ type / host / from-to（含端点）筛，再 `slice(count, offset)`，`total` 为筛后总数。
- HTTP 参数校验：`server.js:198-217`，非法 status / type / from / to、起点晚于终点都 400，文案与 cases 接口同口径。
- 单测：`trace-board.test.js`「A2 列表给出类型/主机/告警时间/状态/链长/断点/更新时间，能筛能分页」（3 板矩阵，逐字段 deepEqual + 6 种筛选/切页）；`agent-api.test.js`「白板列表把状态/类型/主机/时间筛选交给服务层，非法值回 400 且不调服务层」。

### A3 详情是 hops、links、gaps、discovery。线从更晚指向更早。断了要写明缺的是哪一跳

- `presentBoard`（`trace-board.js:87-145`）：`hops[]`（`id/kind/label/host/occurred_at/evidence_id/discovered`，告警起点那跳 `kind=alert`）、`links[]`（`from` 更晚、`to` 更早；先比 `occurred_at`，时间相同/未知时按离告警的深度定方向）、`gaps[]`（`{hop_id, reason}`）、`discovery[]`（`step/kind/id`；旧板没有就按 hops、links 顺序补）。
- 断点：程序生成的查不全（跨类事件 / 同类型事件 / 邻接地址截断）用 `addGap(board, entry.id, …)` 写明断在哪一跳（`trace-board.js:422`、`:431`、`:466`）；AI `conclude` 也收结构化 `{hop_id, reason}`（`trace-board.js:556-560`），只给纯文本时 `hop_id` 为 null（整条链缺口，见未决 1）。
- 单测：`trace-board.test.js`「A3 详情是 hops/links/gaps/discovery，线从更晚指向更早」（02:00 的来源 → 03:00 的告警那跳，断言 links 方向是 asset→ip）、「A3 两端时间相同时按离告警的远近定方向」。

### A4 告警分析已经取到的证据直接引用，不为同一份再查一遍

- `TraceBoardService` 构造参数 `analysis`（`trace-board.js:256-261`）；`startOrResume` 先问它（`trace-board.js:334-351`），有值就不调 `get_*_event`，`origin_evidence.evidence_id/tool` 用分析那份、`reused:true`。
- 生产接线：`server.js:55-71` `analyzedAlert` 从 `triageMonitor.status(alertId)` 取分析记录的 `input.parsed`（syslog 原始报文，分析当时已落盘，证据号 `syslog:1`），映射出主机 / 来源 / 事件时间作为起点；没有分析记录时 syslog 告警回 422。
- 单测：`trace-board.test.js`「A4 告警分析已取到的证据直接引用，不为同一份再查一遍」（toolbox 的 `callTool` 记名并抛错，断言 `calls` 为空、起点证据是 `syslog:1`、`reused:true`）、「A4 syslog 告警没有分析证据时明确拒绝」。

## 五、未决

1. **AI 自述的断点只有纯文本时 `hop_id` 为 null**：`prompts/trace-board.md` 不在本卡 scope（模型动作词表属 pi 本体资产），提示词仍要求 `gaps` 返回字符串。程序生成的断点都带 `hop_id`；AI 断点只有在模型给 `{hop_id, reason}` 对象时才带得上。前端（T016）需要把 `hop_id:null` 当「整条链的缺口」展示；要让模型稳定给出跳号，得另派卡改提示词。
2. **牧云告警在 poll 模式下的分析证据不能复用**：`InvestigationStore` 只存 `evidence[]{evidence_id,tool,args,fetched_at,sha256}`，不存事件详情；`triage-monitor` 的 poll 记录也不留事件体。所以 A4 的实际复用路径是 syslog 形态（当前部署的主源，`HIDS_TRIAGE_INPUT_MODE=syslog`）；poll 模式仍会查一次事件详情。要彻底复用需让分析侧落事件视图（`investigation-agent.js` / `triage-monitor.js` 不在本卡 scope）。
3. **hop 种类目前只有 `alert` / `host`**：现有取证只产出资产/IP 节点，进程 / 文件 / 账号 / 请求节点要等调查引擎扩（`prompts/trace-board.md` + `trace-board.js` 的候选生成一起改），本卡不扩。
4. **`links[].rel` 仍是原有关系词**（「触达线索」「探测」等），D016 的四句关系词没有落到写边处：改词表要动提示词（out of scope）。
5. **`docs/modules/trace-board.md` / `docs/modules/http-api.md` 未同步**：本卡 scope 只有 `trace-board.js, server.js, openapi.yaml, coding-reports/P003-T014.md`，模块页描述的还是旧的 `nodes/edges/activity` 主数据与字符串 `gaps`。对外契约已写进 `openapi.yaml`；模块页需要一张补文档的卡。
6. **`gaps` 元素类型改了（string → object）**：旧白板文件读取时归一，不写回；`web/src/trace.js` 与页面仍按字符串渲染（本卡 forbidden `web/**`），T016 要跟着换。
