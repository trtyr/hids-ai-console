## 3 未决

1. **内核级 UDP 丢包拿不到**：dgram / socket 缓冲满导致的丢弃在进程内不可见（`syslog-input.js` 的 `SyslogReceiver` 没有计数器，本卡 scope 不含它）。现在计数的是进程看得见的两类：暂停缓冲溢出（`paused.dropped` / `syslog_stats.dropped`）与处理链抛错（`syslog_stats.failed`）。要内核级计数得扩 `syslog-input.js`（带 `SO_RXQ_OVFL` 或接收器侧统计），群主拍过「不扩」。
2. **归档记录不再可查**：TTL 归档后 `status()` 回 null、`cases()` 不列、`summary().counts` 不计（这是 A5「全表扫不随告警量线性变慢」的代价）。要翻旧案得读 `<队列文件>.archive.jsonl`；本卡没有做归档列表/读回接口（卡里没要求，scope 也没有页面）。
3. **取消没有前端入口**：`web/**` 本卡禁改，只有 `DELETE` 接口；按钮留给后续前端卡。
4. **死信的「再给一次机会」是单次**：手工 `POST` 重跑死信记录时 `attempts` 沿用（例如 3），再失败会立刻判回死信。这是有意的（人工重跑只给一次机会，`attempts` 留着做记录），但和「重跑就从零算」是两种口径，写在这里免得后面当成 bug。
5. **文档同步溢出到 scope 外一处**：`docs/architecture.md:132` 的日志事件表还写着 `syslog.skipped` 的 `reason=paused`，现在暂停走 `syslog.buffered`、缓冲溢出才是 `syslog.skipped reason=paused_buffer_full`，另有新增事件 `triage.dead_letter` / `triage.archived` / `triage.cancelled` / `triage.backfill_failed` / `triage.delivery_count_failed`。该文件不在本卡 scope（群主给的是 `openapi.yaml` / `triage-pipeline.md` / `http-api.md`），没敢动，请群主决定是否补一张文档卡。
6. **暂停缓冲的上限是取舍**：`paused_buffer_limit` 缺省 2000 条，超出会丢（计数，不静默）。「暂停不丢」在极端流量下不成立，这是不涨内存的代价，已写进文档 §13。
7. **合并写窗口的兑付方式**：研判过程的状态最多滞后一个窗口（≤1s）落盘；崩溃后靠 `load()` 把 `running` 记录退回 `queued` 重跑兑付。所以「研判完成后立刻断电」时记录可能是 `running`/旧阶段，重启会重跑那一单（at-least-once），不是数据丢失。在飞写期间标的脏由 `flush()` 的 finally 补排下一次合并写（复审修正，见 §5），所以「最多丢一个窗口」这一条对在飞期间的改动同样成立。

## 5 复审轮（2026-11-19，判词 `P003-T036-gc-backend-code-review-mwnnaev8`，verdict=fail）

**要害（major）：合并写 liveness 洞。** 写在飞期间 `markDirty()` 早退（`triage-monitor.js:159`），而 `flush()` 的 `finally` 只清 `flushing`/`flushDone`——在飞期间标的脏没有人补排，写完之后那份脏状态永远不落盘，`persist.unflushed` 永久 true。这砸了本卡自己的承诺「崩溃最多丢一个合并写窗口」（`triage-monitor.js:677`、`triage-pipeline.md §5.1`、R-TRIAGE-12）。

修法：`flush()` 的 `finally` 里 `writtenGen < dirtyGen` 就 `markDirty()` 补排（走同一个 `persistIntervalMs` 限速）。**净增 0 行**——`docs/` 里所有 `triage-monitor.js:NNN` 锚点保持有效。

```
$ sed -n 201p triage-monitor.js
        .finally(() => { this.flushing = false; this.flushDone = null; if (this.writtenGen < this.dirtyGen) this.markDirty(); });
```

失效模式核对：`writtenGen >= dirtyGen` 时不排（不写空快照）；写盘失败路径 `writtenGen` 已被推到目标代，最多多试一次就停，不会成环。
