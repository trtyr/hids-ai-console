# P003-T088 交付报告 · 误报 Agent 强化

**落地**：
1. **handler 拆三段用例** ✅：原先 69 行的 `POST /false-positive` 拆成三个具名函数（都在 `server.js` 模块级，可单测）：
   - `registerFalsePositive({record, reason, who, libraries, previous})`——**同步事务**：只改记录（verdict/feedback/detail/maintenance 初态），不碰后台；
   - `falsePositiveSides({libraries, previous, at})`——**纯逻辑**：单腿补跑时未请求的一侧记 `skipped`，且**原样保留上一轮的 revision / 幂等键**（「已成功的一侧不重复执行」的唯一判据载体）；
   - `startFalsePositiveMaintenance({monitor, record, maintainer, libraries, previous, running, onSettle})`——**异步作业**：失败只写 maintenance 不回滚 verdict，响应不等它；`onSettle` 回调负责落 `maintenance.result` 日志。
   路由体退化成「校验 → 调三个用例 → 回 202」。
2. **单腿重试** ✅（T047 已落）：`libraries: ['rule'] | ['wiki']` 只重跑失败侧；重复项 400（不静默去重）；幂等键 `case_id:库:版本`。
3. **进度可观测** ✅（T089 已落）：`GET /api/events?topics=fp` 推 `fp` 快照与变化（`running` 数）；四轮推进的逐轮状态在 fp-session 文件里（`GET /api/false-positive/sessions/{id}` 取全文）。
4. **幂等语义进契约** ✅：openapi 的误报登记 202 描述已写明「结论已落盘为误报，统一维护 Agent 已开始（或已在跑）」——同一 alertId 重复登记回 202 + 当前进度，不重复起后台任务（`runningMaintenance` 集合挡）。
