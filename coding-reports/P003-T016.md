## 七、未决

1. **位置记忆只能存在浏览器本地**。D016 要求「拖过的位置要记住，写在这一跳上（`x`/`y`，相对告警点）」，
   但三个溯源 operation 里没有写位置的入口（`openapi.yaml:456-560` 只有 `GET` 列表 / `POST` 起板 / `GET` 详情），
   所以本卡写在 `localStorage`（键 `hids.trace.positions.<白板 ID>`）。换机器、换浏览器、清缓存就丢。
   读写只在 `readSavedPositions` / `savePosition` 两处 → **要落成接口字段，请群里派后端加一个写位置的入口**（如
   `PATCH /api/trace/boards/{id}` 或起板正文里的 `positions`），我这边换过去是两个函数的事。
2. **检查器里的「证据里能看的那几行」没有数据源**。`hops[]` / `links[]` 只给 `evidence_id`，
   白板接口不回证据原文（证据明文在告警详情那条链上）。页面如实写「证据正文在告警详情里看」，没有造假数据。
   要在这页看证据，得后端在 hop / link 上带一段可展示的证据摘要。
3. **进行中是 5s 轮询**（`POLL_MS`）。接口没有 SSE / 进度流；T015 的前车之鉴是「没有进度流就不假装有」。
   轮询间隔是页面常量，要更低频/更高频都只是改一个数；真要推送得后端加流。
4. **补了一个稿上没有的「← 溯源列表」返回链接**（D015 把列表和白板拆成两页，稿是独立 html 页不需要返回；
   单页应用里只剩侧栏能回列表）。要是设计不认这条，删 `.trace-tools` 里那一个 `<a>` 即可。
5. **`#/trace/<旧 ID>` 这类旧书签落在列表页**（参数被忽略，不跳白板）：没有做重定向，因为要 redirect 得在
   壳里动手（壳不在 scope）。要兼容请另派卡。
6. **旧白板的 `nodes/edges/activity` 前端不再当主数据**，但后端仍返回（`trace-board.js:126` 的 `...board`），
   `pages/alert-detail.js` 的「关联实体」还在用它们（它走 `src/alert-detail.js` 的另一份 adapter，本卡没动）。
   两套字段并存是 T014 的兼容决定，不是本卡引入的。
