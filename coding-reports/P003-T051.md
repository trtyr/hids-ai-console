## 一、改了什么

### 1. 同一道脱敏闸：`recordFailure()`（`investigation-agent.js:93-106`）

落盘字段只写**固定文案 + 原文字符量**，三种固定文案：

| 情形 | 落盘文案 |
| --- | --- |
| 回包解不出 JSON（`error.model_decode`） | `模型回包不是合法 JSON（SyntaxError），原文 60 字未落盘` |
| 超时（`timeout` / `超时` / `aborted`） | `调用超时，原文 6 字未落盘` |
| 其余 | `上游调用失败，原文 24 字未落盘` |

错误类名只从白名单来（`TypeError` / `SyntaxError` / `RangeError` / `TimeoutError` / `AbortError`），
避免把上游自造的 `name` 抄进记录。**原文一个字不落盘**：V8 的 `JSON.parse` 报错会把回包前 ~10 字带进 `message`
（`Unexpected token 'S', "SECRET_BOD"...`），模型接口与牧云的错误文本同理。

**A2 那一半没有动**：`modelCallError` 抛给调用方的报错照旧原文、`cause` 链照旧；`traceModelCall` 抛出的错误照旧带
`model_decode` / `model_reply` / `model_call` 三标记（与 T046 日志侧同一修法：错误对象给调用方，磁盘只留文案）。
