## 三、验收逐条

### A1 总览数字来自聚合接口。接口还没有时允许空，不允许改去拉牧云现查充数

- 总览现在只读六路，其中数字全来自 `GET /api/agent/triage/status`：结论分布 `verdict_counts`、
  类型分布 `type_counts`、队列四项 `counts`、最后推送 `last_received_at`、syslog 三态 `syslog`
  （`web/src/status.js:47-140`、`web/pages/overview.js:80-92`、`:353`、`:362`）。
- `/api/alerts` 那一路**从 `SOURCE_KEYS` 里删了**（`web/src/status.js:47` 只剩六项），页面没有别的拉牧云退路。
- 接口缺失时：结论四键缺一个 → 该源 `invalid`、六格全是「—」，不拿 0 假装；`type_counts` 为空 → 类型表一行
  「暂无告警数据」、构成说明「接口未返回类型统计。」。
- 单测：`web/test/status.test.js`「六个只读源…一条牧云现查都不发（A1）」（断言请求列表里没有 `/api/alerts`、
  `SOURCE_KEYS` 不含 `alerts`）、「成功：…结论分布 / 类型分布 / 最后推送 / syslog 三态都带出来」、
  「字段照文档：…结论四键缺了就 invalid」；`web/test/pages/overview.test.js` 默认态末尾也钉了同一条。

### A2 告警主列表是研判记录。重复一行。误报一点就改这一行

- 列表源：`GET /api/agent/triage/cases`（`web/src/cases.js:133`、`web/pages/alerts.js:267` 起）。
  一行 = 一条记录，重复次数读 `repeat_count`（`×N`，「维护」列旁边），不另造计数（`web/pages/alerts.js:230-236`）。
- 误报：行级按钮 → 行下理由表单（`aria-label="给 <id> 填误报理由"`，打开即聚焦）→ `POST …/false-positive`
  （正文只有 `{reason}`）→ 202 回来**这一行立刻改结论为「误报」**、`feedback` 留在记录上、
  `maintenance` 写进「维护」列（规则 / 知识库各自「更新中 / 已更新 / 失败」）。
  代码：`web/pages/alerts.js:430-518`；adapter `web/src/cases.js:182-199`。
- 单测：`web/test/pages/alerts.test.js`「A2 误报：点开理由表单 → 提交 → 这一行立刻变误报，理由与维护状态都留在页面上」
  （断言 POST 正文、行内结论变「误报」、「维护」列变「规则 更新中 · 知识库 更新中」、表单收起、播报）；
  短理由不发请求；409 时行不变（另一条用例）。adapter 侧 3 条（正文/本地拦/错误归一）。

### 8.3 代价与残余
