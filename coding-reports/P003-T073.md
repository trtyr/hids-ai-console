## 1. 全端统一错误模型（acceptance 第 1 条：设计先行）

**shape**：`{ error, code }`。`error` 给人看，`code` 给程序判。

**code 表（单一真源 = `src/shared/errors.js`）**：

| 面 | code | status | 语义 |
|---|---|---|---|
| 业务四类（P003-T024 口径不变） | `caller_error` / `not_configured` / `upstream_error` / `internal_error` | 400（类内可覆盖 403/404/405/409/410/422/429）/ 503 / 502 / 500 | 调用方传错 / 没配置 / 上游失败 / 本程序失败 |
| 业务 401（特例 1） | `unauthorized` | 401 + WWW-Authenticate | Basic 闸；正文从纯文本改 JSON，弹窗行为靠头不变 |
| `/api/status` 502（特例 2） | `upstream_error` | 502 | 契约形状 `{configured,connected,reason}` 保留，**新增** `error`（并入统一模型）；构造只能走 `sendCloudwalkerStatusFailure()` |
| SSE 错误帧（特例 3） | 四类之一 | HTTP 200 | `{type:'error', error, code}`——前端可只按 code 判成败 |
| 维护端具名码 | 18 个（`loopback_only` / `preview_loopback_only` / `invalid_url` / `not_found` / `csrf_rejected` / `login_disabled` / `login_disabled_preview` / `rate_limited` / `json_required` / `invalid_credentials` / `forbidden_role` / `unauthorized` / `preview_read_only` / `not_updater` / `package_media_type` / `package_name_invalid` / `revision_required` / `not_configured` / `internal_error`） | 各点位原状态码 | 与业务端同一套 snake_case 命名；文案与原话逐字一致（只加 code 不改话术） |

**文案与 code 的关系**：文案会改，code 不改；分类判据只认错误自带的 `failure`/`status` 标记（`failureKindOf`），不看文案。`internal` 的 `error` 恒为「服务器内部错误」，异常原文与堆栈只进 `http.failed` 日志（T072 起 request_id 反查）。所有错误正文出口统一过 `scrubCredentials`（`src/shared/redaction.js`）。

**现存例外及处置**：上表三个特例全部「构造仍只能经 errors.js」（check-layers 白名单 = errors.js + error-model 中间件）；`POST /api/agent/prompts` 的 405 分支保留专有文案（提示词上传走维护端的历史口径）。维护端动态 catch 的码归类：4xx→`caller_error`、503→`not_configured`、其余→`internal_error`。
