每条用例钉的是什么（对应验收）：

- **A1**：`POST /api/agent/triage/webshell:9001` → 202 `TriageCase`（`alert_id` 原样、`status` 是 queued 或 running——
  `drain()` 同步排工，回包可能已经是 running）→ 等 `done`：假 investigator 只收到一次
  `{alert_id:'webshell:9001', mode:'triage'}`；记录带 `verdict=threat` / `result_alert_id` / `evidence[1]` / `attempts=1`，
  且**没有** `syslog`、`case_dir` 键；`InvestigationStore.latest('webshell:9001','triage')` 能读回这份记录。
- **A2（排队中）**：`concurrency:0` 让记录停在 queued，连发两次 POST 都 202、都 `queued`，
  `GET /api/agent/triage/status` 的 `queue.depth` 仍是 1（没有第二条记录）。
- **A2（在跑中）**：门控假 investigator 把记录卡在 running，第二次 POST 回 202 + `running`，
  放行后研判只跑了一轮（`calls.length === 1`、`attempts === 1`）。
- **A2（已完结）**：done 之后 POST = 人工重试——`attempts` 1→2、`created_at` 沿用、同一 ID 跑第二轮、
  `queue.depth` 回到 0。
- **A3**：`service`（牧云网关）任何方法被调即抛并记账，`eventToolbox` 换成记账替身；整条链跑完后
  两边调用记录都是空数组，研判数据全来自假 investigator，落在 tmp 目录（`mkdtemp`）。
- **A4**：直接读 `openapi.yaml` 与 `docs/modules/http-api.md` 文本，按 `POST /api/agent/triage/{alertId}` 那一块
  （截到下一个 path 条目为止）断言 `重复入队`、`同一 alert ID 只有一条记录`、`人工重试` 三句都在，
  再断言 http-api.md 有同一句口径与 `### 3.9` 那一节——只改一边会红。
