## 2. 本轮改了什么

### 2.1 「8 条命令」实为 9 条，且「都用 `--input-type=module`」对命令 H 不成立

- 原文（§11 开头）：`下面 8 条命令都在仓根目录下用 node --input-type=module -e 跑`
- 实物：§11 有 9 条命令（A–I）；命令 H 是裸 `node -e`（现页面 :530），因为它只查运行时内建、不 import 本模块。
- 改法：改成「下面 9 条命令（A–I）……其中 8 条（A、B、C、D、E、F、G、I）用 `node --input-type=module -e`；
  命令 H 是裸 `node -e`——它只查运行时内建，不 import 本模块」。

### 2.2 「这四条」上文列的是五条

- 原文（§10）：`这四条按本仓分工属于「现状之外的判断」`（上版 :311），而上方 :303–309 明列五条。
- 改法：改成「这五条」。

### 2.3 「约 806 毫秒」的出处没指到

- 原文（§4.3）：`超时毫秒数设 800，约 806 毫秒后抛出 …（实测，见第 11 节命令 G）`，但命令 G 原来的输出里没有耗时，
  这个数只写在侦察记录 #23。
- 第一版改法是给命令 G 加 `Date.now()` 计时、把实测毫秒数贴进输出块。**试了不行**：本卡两次实测得 806 与 804 ms（同一台机器、同一脚本），
  贴死一个数字，页面就做不到「命令原样复跑、输出逐字一致」——正是上一轮被打回的同一类问题。
- 最终改法：命令 G 在输出里打**窗口判定**（`el >= 800 && el < 2000` → `true`），这个值逐次稳定；
  页面正文改成「可复跑证据是命令 G 的窗口判定，不是固定数字；本卡实测 806 毫秒，随机器浮动」。
  这样断言「超时会真的中断」有可复跑证据，806 ms 保留为观测值并说明它不是定值。

### 2.4 自查补的一处：`LLM_TIMEOUT_MS` 的「非正数回落」写得像「非法值全回落」

- 原文（§4.4 表）：`转成数字后不是正数（0、负数、非数字文本、空串、未设置）一律回落到 90000`。
  这句按字面为真，但读起来像在说「不合法就回落 90000」。
- 实测反例：`LLM_TIMEOUT_MS='1e999'` 与 `'Infinity'` 转成 `Infinity`——它是正数，**不回落**，
  装配出的 `timeoutMs` 就是 `Infinity`；发请求时 `AbortSignal.timeout` 抛 `RangeError`
  （`code=ERR_OUT_OF_RANGE`，原文尾缀 `Received Infinity`），请求根本没发出。
- 改法：表里那句改成「转成数字后不是正数时回落到 `90000`；是正数就照用，不管是不是整数或有限值」，
  §4.4 补两条反例（`'1.5'`、`'1e999'`），`R-MODEL-CLIENT-09`、§5 值语义、§7 失败面、§10 未决第 5 条、
  侦察记录 #28 同步覆盖。命令 E 的取值列表加 `1e999`，命令 I 扩成「小数 + 无穷大」两组——
  **命令总数仍是 9 条，没有新增命令**（§2.1 的计数不会因此再错一次）。

### 4.1 §11 九条命令逐块重跑（本轮新加的校验）

脚本放在仓外 `/tmp/t005c/check-blocks.mjs`（不污染工作树），全文贴在这里，拷到仓根即可原样复跑：

```js
import fs from "node:fs";
import { execFileSync } from "node:child_process";

const page = process.argv[2];
const lines = fs.readFileSync(page, "utf8").split("\n");
const start = lines.findIndex((l) => l.startsWith("## 11."));
const raw = [];
let cur = null;
for (let i = start; i < lines.length; i++) {
  const l = lines[i];
  if (l.startsWith("```")) {
    if (!cur) cur = { info: l.slice(3).trim(), body: [] };
    else { cur.body = cur.body.join("\n"); raw.push(cur); cur = null; }
    continue;
  }
  if (cur) cur.body.push(l);
}
const blocks = [];
for (let i = 0; i + 1 < raw.length; i++)
  if (raw[i].info === "bash") blocks.push({ cmd: raw[i].body, out: raw[i + 1].body });

const names = ["A", "B", "C", "D", "E", "F", "G", "H", "I"];
const norm = (s) => s.split("\n").map((x) => x.trimEnd()).filter((x) => x !== "").join("\n");
let bad = 0;
blocks.forEach((b, i) => {
  let got, code = 0;
  try { got = execFileSync("bash", ["-c", b.cmd], { encoding: "utf8", stdio: ["ignore", "pipe", "pipe"] }); }
  catch (e) { got = (e.stdout || "") + (e.stderr || ""); code = e.status; }
  const same = norm(got) === norm(b.out);
  if (!same) { bad++; console.log("  不一致:", names[i], "exit", code); console.log("  期望:", norm(b.out)); console.log("  实得:", norm(got)); }
});
console.log("命令块", blocks.length, "| 不一致", bad);
process.exit(bad === 0 ? 0 : 1);
```

调用方式（仓根）：`node /tmp/t005c/check-blocks.mjs docs/modules/model-client.md`。

```
$ node /tmp/t005c/check-blocks.mjs docs/modules/model-client.md
命令块 9 | 不一致 0
EXIT=0
```

连跑三轮都是 `命令块 9 | 不一致 0` / `EXIT=0`（每轮独立进程）。这就是 §2.3 改窗口判定之后「可原样复跑」的实证：
上一版贴死毫秒数时，同一脚本这一块必报不一致。

## 5. 未决

1. **重试归谁**：文件里没有重试代码，也没有一句话说明重试该由本模块做还是调用方做。页面只写现状（不重试），
   不给判断（§1、§9、§10）。
2. **错误原文截断到 250 字符的依据**：代码里只有 `.slice(0, 250)` 这个事实，没有取舍理由的记载。
3. **传输层错误不翻译**：超时抛 `TimeoutError`、连不上抛 `TypeError: fetch failed`，都没被翻成中文提示。
   是有意留给调用方识别，还是漏了，代码里看不出来。
4. **HTTP 200 也带 `error` 字段时，错误消息里照抄状态码 200**：行为已实测确认（命令 D），是否符合预期没有记载。
5. **超时毫秒数非整数 / 非有限值的兜底**：模块只判「大于 0」，小数与 `Infinity` 照收；实际是运行时的
   `AbortSignal.timeout` 抛 `RangeError`（本机 Node v26.13.0）。该由模块归一化还是配置侧保证，代码里没有说明，
   且具体表现随 Node 版本变化。
6. **超时耗时的数值不可逐字复跑**：804–806 ms 是观测值，页面只能给窗口判定（见 §2.3）。若以后要写死数字，
   得先有能固定耗时的时钟注入点——模块没有这个注入点。
7. **本模块目前没有单元测试覆盖**：仓里没有 `model-client.test.js`。本卡没有新增测试文件——任务卡给的写入范围里
   没有测试文件路径，越界写会被 boundary 判失败。替代做法是页面 §11 的 9 条命令，测试方可以直接照抄成用例。
8. **缺口台账没登记**：本仓缺口台账是 `docs/_meta/gaps.md`，不在本卡 scope，因此第 1–6 条只登记在本报告与页面 §10，
   没有改进台账。**建议下一张卡把这几条并进 `docs/_meta/gaps.md`。**
