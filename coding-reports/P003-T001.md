### 本卡定下的接口契约（下文 openapi 已同步）

| 参数 | 取值 | 语义 |
| --- | --- | --- |
| `type` | 11 个事件类型键之一 | 只查该类；`total` = 该类总数；不在枚举内回 400 |
| `level` | `low/medium/high/critical` 或 `1..4`，逗号可多选 | 合并后过滤；其他值 400 |
| `q` | 任意字符串 | 小写化后对 `id/title/asset/source/target/account/command` 做包含匹配 |
| `from` / `to` | RFC3339 或秒/毫秒时间戳 | 闭区间；解析不了 400；`from > to` 400；无事件时间的告警在带时间筛选时被排除 |
| `sort` | `time`（默认）/ `level` | `time` = 事件时间倒序（老行为）；`level` = 等级降序、同级按时间倒序 |
| `triage_status` | `not_queued/queued/running/done/failed`，逗号可多选 | 挂完 triage 后过滤；无研判记录算 `not_queued` |
| `verdict` | `review/threat/uncertain/false_positive`，逗号可多选 | 挂完 triage 后过滤；无结论（或无记录）算 `review` |
| `truncated`（响应） | boolean | 扫描窗口（上限 500 条）被截断时为 true，此时 `total` 只含窗口内匹配 |

过滤顺序写死在实现与文档里：**type 下推 → 合并 → level/q/from/to → 切页 →（研判侧）挂 triage → 过滤 → 切页**。

## 四、未决

1. **模块文档没同步（scope 外，需要一张卡）**：`docs/modules/http-api.md`（第 7 节「分页参数校验」、路由表 `/api/alerts` 行）与 `docs/modules/event-gateway.md`（`alerts()` 契约）现在与实现有偏差——新参数、`truncated`、`levelKey/verdictKey` 都没写进那两页。这两条路径不在本卡 scope，我没动；接口契约落在 scope 内的 `openapi.yaml`。补齐需要群主派卡或放宽 scope。
2. **前端未接**：`web/src/alerts.js:87` 仍只发 `count`/`offset`，adapter 注释也写着「筛选/排序参数不在这里补」。筛选 UI 与接线归前端卡（`web/**` 本卡 forbidden）。
3. **后置筛选的 total 是「扫描窗口内精确」**：单次请求最多扫 500 条原始事件（`cloudwalker.js` `MAX_SCAN`、`server.js` `TRIAGE_SCAN_LIMIT`），越界回 `truncated: true`。要全量精确计数得靠牧云 RPC 侧过滤或全表扫描，本卡不做——这是刻意取舍，不是漏做。库大的时候前端要读 `truncated` 决定提示。
4. **预存失败**：`maintenance-startup.test.js` 的 symlink 用例在基线就红（`MODULE_NOT_FOUND`），`maintenance-server.js` 在 forbidden 面内，未处理。
5. **`sort=level` 与 `total` 的交互**：`sort=level` 走扫描路径，所以 `total` 在库大于扫描窗口时同样是窗口内计数（`truncated=true`），与不带 `sort` 时的「各类 total 之和」不同。已在 openapi 的 `total` 描述里写明。
6. **动过的对外行为与文档**：新增查询参数与响应字段，文档落点 `openapi.yaml`（本卡 scope 内）；`docs/modules/**` 见第 1 条。
