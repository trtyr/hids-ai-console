## 一、改动清单

### A1 增量轮询 + 指数退避（`triage-monitor.js`）

- `poll()` 改为 `service.alerts({ count: 50, offset, sort: 'time', from: watermark })` 增量取数；游标只由 `from` 决定，
  不再翻页比较时间找边界（`triage-monitor.js:330-407`）。兜底：平台忽略 `from` 时早于游标的行也跳过。
- 排序键固定 `created_at desc, id asc`（`cloudwalker.js:41-43`，poll 显式传 `sort: 'time'`）。
- `poll()` 返回 `{ found, empty, failed }`；连续空轮（含失败轮）`backoffMs = min(intervalMs × 2^emptyPolls, maxBackoffMs)`，
  见到新告警立刻回 `intervalMs` 并清零（`triage-monitor.js:404-405`）。`maxBackoffMs` 缺省 `intervalMs × 16`。
- 定时器由 `setInterval` 改为 `setTimeout` 链（`triage-monitor.js:162-181`），`stop()` 之后不会被在途轮次复活。

### A2 / A11 事件详情一次一拉（四个调用点）

- `triage-monitor.js`：每次 `run()` 建一份详情缓存，`observedToolbox(detailCache)` 只缓存 `get_<type>_event`
  （键 `工具:事件ID`），`matchSyslogEvent` 与 `ruleEngine.evaluate({toolbox})` 用同一个实例；`streamContext.match.event` 继续下传。
  跨告警不共享（`triage-monitor.js:575-593`、`604-625`）。
- `triage-rules.js:277-285`：`match.event` 身份一致（`matched && event_id == id`）时直接复用，不再 `callTool`。
- `investigation-agent.js:356-376`：`streamContext.match.event` 身份一致时构造同形 `cw:N` 证据记录（含 `sha256`/`view`），
  入口不再取数；其余入口照旧。
- `trace-board.js`：**未改实现**（群主口径：只补测试锁行为）。既有用例 `A4 告警分析已取到的证据直接引用，不为同一份再查一遍`
  断言 `calls === []`（`trace-board.test.js:311-340`），本卡复核仍绿，即第四条路径（analysis 复用）已覆盖。

### A3 同指纹 + 同主机 + 上一条已完结 → 复用结论（`triage-monitor.js`）

- `_acceptSyslog()` 在「同秒折叠」之后加一条分支：去重表指向的记录 `status === 'done'` 且有 `verdict` 时，
  不新建记录、不排研判，只累加 `repeat_count`，并同步研判记录、案卷 `result.json`、`05-研判结果.md`；
  返回 `{ reused: true, repeat_count, alert_id }`（`triage-monitor.js:454-477`）。
- 上一条未完结（排队 / 在跑 / 失败）不复用，照常新排（`triage-monitor.js:452-454`）；要重新研判走 `enqueue(alertId, { retry: true })`。

### A4 优先级队列（`triage-monitor.js`）

- 导出 `typeRisk`（11 类，4–11 档）与 `comparePriority`（`triage-monitor.js:19-48`）；
  `drain()` 按（类型风险 desc，`occurrence_count` desc，`created_at` asc）取第一条（`triage-monitor.js:542-545`）。
- syslog 记录的类型从 `input.parsed.msgid` 映射，轮询记录从 `alert_id` 的 `type:` 前缀取（`triage-monitor.js:34-40`）。

### A5 并发 / 队列上限可配 + 丢弃计数（`triage-monitor.js`）

- `concurrency` 缺省读 `HIDS_TRIAGE_CONCURRENCY`（2），`queueLimit` 缺省读 `HIDS_TRIAGE_QUEUE_MAX`（1000）；
  非法值回落默认（`triage-monitor.js:26-31`、`76-80`）。显式构造参数优先。
- 队列深度 = `queued + running`；到上限：手动 `enqueue` 抛 429（`triage-monitor.js:304-308`），
  轮询批量入队与 syslog 收包只丢弃并计数（`378-382`、`478-481`）。`summary()` 暴露 `concurrency` / `queue_limit` / `dropped` /
  `backoff_ms` / `empty_polls`（`triage-monitor.js:240-252`），每次丢弃记 `triage.dropped`（`290-293`）。

### A6 RuleStore 按 mtime 缓存（`rule-store.js`）

- `#load()` 每次 `readdir` + 逐文件 `stat`；`(mtimeMs, size)` 未变的文件复用已解析规则，只重读重解析变化/新增文件，
  删掉的文件立刻消失；重复 `id`、语法错等报错口径不变（`rule-store.js:146-190`）。

### A7 Wiki 目录索引按 mtime 缓存（`wiki-store.js`）

- `list()`（`agentIndex` 的唯一数据源）先算 `(路径, mtimeMs, size)` 签名，签名不变直接返回缓存行（浅拷贝），
  不重读正文、不重解析 frontmatter（`wiki-store.js:67-105`）。

### A8 / A9 / A10 取数缓存（`cloudwalker.js`）

- `defaultTtls = { status: 45000, probe: 5000, snapshot: 15000 }`，构造参数或 `HIDS_STATUS_TTL_MS` /
  `HIDS_PROBE_TTL_MS` / `HIDS_LIST_SNAPSHOT_TTL_MS` 覆盖，`0` 关闭（`cloudwalker.js:95-112`）。
- A8：`status()` 成功结果缓存 45 秒，存 promise（并发请求共用一次探活），失败不缓存（`120-133`）。
- A9：`alert()` 失败后的同类列表探活按类型缓存 5 秒，命中缓存不再探活（`135-145`、`266-270`）。
- A10：`alerts()` 各类型首批 `{total, events}` 按（类型, 批大小, 起点）快照 15 秒，存 promise、失败不缓存、

## 四、未决

1. **A5 的配置面只到 env + `summary()`**：没有把 `HIDS_TRIAGE_CONCURRENCY` / `HIDS_TRIAGE_QUEUE_MAX` 加进
   `config-store.js` 的可写五键（那要改 `config-store.js` / `server.js` / `openapi` 的写配置契约，不在批准范围）。
   现在的口径是「启动参数，`/api/agent/triage/status` 可查，改完要重启」。若产品要运行中可改，另开卡。
2. **A3 的复用不设时间窗**：按卡面「同指纹+同主机且上一条已完结」实现，上一条已完结就一直复用（只累加 `repeat_count`），
   要重新研判只能手动 `retry`。若希望「隔一段时间后重新研判」（如 30 分钟），需要再加一个可配窗口——本卡没加，取舍写进
   `docs/modules/triage-pipeline.md` §5.5 A3。
3. **列表快照 15 秒陈旧度**：`/api/alerts` 首屏可能看不到最近 ≤15 秒新到的告警（A10 的直接代价）。TTL 可配、`0` 可关；
   要看刚到的单条告警走详情接口（不吃快照）。
4. **status 缓存与运行中改配置的交互**：`applyLiveConfig()` 换牧云地址后，`/api/status` 在 ≤45 秒内仍报旧连接的 `connected`。
   清缓存需要 `server.js` 调 `gateway` 的新方法（`server.js` 不在 scope），没做。
5. **缓存都是单进程内存**：重启即冷；RuleStore / Wiki 的缓存键是 `(mtimeMs, size)`，同一毫秒内改写且字节数不变的规则/页面
   要等下一次 mtime 变化才生效（已写进对应文档）。
6. **`probeCache` 没做并发合并**：同一类型多条详情同时失败时，最坏情况会多发一次探活（A9 只承诺短 TTL 复用，未承诺单飞）。
7. **没跑真牧云 / 真模型端到端**：本机没有凭据，A12 的负载用替身（RPC/工具箱/知识库），真实网络延迟与模型耗时**未测量**。
8. **批准清单漏列的两处已补并记录在 recon 第二节**：`syslog-pipeline.test.js`（A3 改了它的既有断言）、
   `openapi.yaml`（`TriageSummary` 是契约真源，加了 5 个键）。
9. **T035 未合**：它也动 `investigation-agent.js` / `investigation-agent.test.js` / `docs/architecture.md`，
   合并时大概率撞，群主已预告（语义两边都保）。本卡只改自己那段，没重排别人的块。
