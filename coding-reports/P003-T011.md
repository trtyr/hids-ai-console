HTTP 契约（详见 `openapi.yaml`）：

- `GET /api/rules` → `{count, rules:[{id,name,description,file}]}`，按 id 排序；空库 `{count:0,rules:[]}`。
- `GET /api/rules/{id}` → `{id,name,description,file,rego}`（`rego` 是整份文件原文，逐字）；id 不合格式 400「规则 id 无效」，不存在 404「规则不存在」。

## 二、验收逐条

### A1 一条规则一份 Rego，有名字，能列、能按 id 读到原文

- 一条规则一个 `.rego` 文件：`rules/` 下三份文件，装载时按文件名排序逐份解析（`rule-store.js:152-171`）。
- 有名字：`# name:` 必填，缺了装载即报错 `rules/<文件>:1: 缺少 # name: 显示名`（`rule-store.js:120`）。
- 能列：`RuleStore#list()`（`rule-store.js:174`）返回 id/name/description/file。
- 能按 id 读原文：`RuleStore#read(id)`（`rule-store.js:180`）返回 `rego` 字段，等于文件全文（用例 `A1 …能按 id 逐字读回原文` 用 `assert.equal(read.rego, source)` 逐字比）；id 不存在、`.`、`../server`、大写、空格、`null`、数字都回 `null`，不越出规则目录。

### A2 告警事实至少含主机、对端、命令、用户、路径、类型、来源 IP；没写的字段就是不限制

- 七个字段名写在 `openapi.yaml` 的 `AlertFact`（`:1616`）。`rule-store.js` 文件头示例里**实际只出现四个**——`type`、`source_ip`、`command`、`path`（`rule-store.js:16-19`）；`host`、`peer`、`user` 不在文件头，只出现在 `AlertFact` 与 `rules/` 的规则里（`webshell_drop.rego` 用 `host`，`honeypot_probe.rego` 用 `peer`/`user`）。
- 用例 `A2 七个字段…都能被规则取值`：一条规则同时写七个 `==`，全字段事实命中；**逐个删掉一个字段**，命中数都变 0——七个键每个都真的被读到。
- 「没写的字段就是不限制」：用例 `A2 规则没写的字段不限制`——只写 `type` 的规则，事实里带不带 `user`/`command`/`peer` 都命中。
- 事实缺字段的语义按 Rego 的 undefined：引用它的条件不成立（`!=` 也一样），`not` 才反转。用例 `A2 事实缺字段按 Rego 的 undefined 处理` 直接断言：`input.user == "root"` 对无 `user` 的事实不命中，`not input.user == "root"` 命中。

### A3 给定一条事实，返回套上的规则名字和 Rego 正文；一条都没有也明确返回空

- `RuleStore#evaluate(fact)`（`rule-store.js:192`）→ `{count, matched:[{id,name,rego}]}`；`rego` 是命中规则的整份原文。
- 空结果明确：没有命中与空规则库都返回 `{count:0, matched:[]}`（`deepEqual` 断言），不是 `null`，不抛错，HTTP 层也不是 404。
- HTTP 层同样验了（用例 `HTTP 列规则 / 按 id 读原文 / 求值`）：命中 200 + 正文含 name/rego；没命中 `{count:0,matched:[]}`；`[]`/`"x"` 正文 400；未知 id 404；`Bad-Id` 400。
