## 实现说明

- **为什么用 mixin 而不是组合**：这是「迁移只搬代码」的收尾，组合会把 39 个方法体改成 `this.column.xxx`
  并重排状态读写顺序，风险远大于收益；mixin 让方法体逐字保留，行为零变化，同时文件按栏切开。
  `Object.defineProperties(..., getOwnPropertyDescriptors(...))` 保住 `writeChain` getter——`Object.assign`
  会把 getter 求值成 Promise 再拷值，测试与调用方会安静地坏掉。
- **私有方法改下划线**：`#schedule` / `#queueFull` / `#countDropped` 无法搬进对象字面量，改为
  `_schedule` / `_queueFull` / `_countDropped`（都在类/栏内部使用，不在 HTTP 契约里）。
- **每栏的依赖**：队列栏只碰内存与 ingestion 解析；持久化栏独占 fs；投影栏只读；重试栏只管 timer；
  门面负责装配与生命周期。`queue-persistence.js` 在 infrastructure 层、只被门面调用，应用层不 import fs。

// node parity.mjs <repoDir> <dataDir> <outFile>
import { writeFile } from 'node:fs/promises';
const [repo, data, outFile] = process.argv.slice(2);
