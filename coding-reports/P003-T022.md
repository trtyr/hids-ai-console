## 二、验收逐条

### A1 模型没给出有效 JSON，或没有返回可用消息时，失败记录里能看到回包摘要

**满足。** 队列侧把 `error.message` 截 250 字写进 `record.detail`（`triage-monitor.js:471`），本卡把整条消息控在 240 字内，
所以摘要整条落得进去。端到端实测（真 `TriageMonitor` + 真 `InvestigationAgent` + 假 model，脚本见 §三）：

```text
A1 记录状态: failed | 阶段: 研判失败
A1 detail 长度: 134 | detail: 模型未在调查轮数内给出有效 JSON 结论（调查 6 轮、已查询 0 项证据后仍没有可用结论；末次回包 25 字：「我先梳理一下这条蜜罐告警，需要核对来源与请求载荷。」；退回 6 次：输出解析失败：Unexpected token '我', "我先梳理一下这条蜜罐…）
```

三种形态各有单测钉住（§四 1-3 + model-client 那条）。

### A2 失败的记录可以再跑一次，不把队列卡死

**满足**（队列侧本来就是这么写的，本卡没动 `triage-monitor.js`，用证据钉住）：

- `enqueue(alertId, { retry: true })` 把已存在的记录重置成 `queued` 再 `drain()`（`triage-monitor.js:207-227`）；
- `drain()` 的 `.finally(() => { this.active--; this.drain(); })` 无条件放并发位（`triage-monitor.js:393`）。

端到端实测：失败 → `active: 0`、`counts.failed: 1` → `enqueue({retry:true})` → `done`、`attempts: 2`（§三）。
agent 侧另有一条单测：同一个 `InvestigationAgent` 实例连跑两次失败后第三次正常出结论（§四 4）。

### A3 已经写成的结论不被这次失败盖掉

**满足。** `history.save()` 只走成功路径（`triage-monitor.js:452`）；失败分支只改 `status/stage/detail`（`triage-monitor.js:470-471`）；
`investigation-agent.js` 根本不持有 `InvestigationStore`。本卡的失败路径是抛错，不返回降级结论。

实测两部分：端到端脚本里「失败后 `history.latest()` 为 `null`（没写）、重跑后盘上才是新结论」；单测里预存一条记录 →
失败 → 目录仍只有一个文件、`latest()` 与预存对象 `deepEqual`（§四 5）。

## 六、未决

1. **250 字预算是跨模块耦合**：`triage-monitor.js:471` 把 `detail` 截到 250 字，本卡按 240 字拼消息。谁改这个截断值，
   `investigation-agent.js:34` 的 `failureTextLimit` 得跟着改；本卡按群主要求没碰队列文件。
2. **摘要会带模型原文片段**：`末次回包 … 字：「开头 50 字」` 可能抄进告警原文或凭据类字段，然后被 `status()` / `cases()`
   带到 HTTP 面（现有 250 字上限，没有脱敏）。要不要脱敏是另一张卡的活，本卡只保证不含请求头与 API key
   （`model-client.js:1-12` 的摘要只描述回包形状）。
3. **`模型没有返回可用消息` 的摘要里没有正文**：正文非空就不算「不可用」，所以这个分支下正文必为空，摘要只描述形状
   （正文 0 字 / 工具调用 0 次 / `finish_reason`）。要看「正文超长被截断」那种回包，靠研判循环的
   `末次回包 K 字：「开头 50 字」`——只有 50 字，看不到末尾（不排除 JSON 主体在末尾的情况）。
4. **A2 的队列侧没有新增单测**：`triage-monitor.test.js` 不在本卡 scope（群主放开的是 `investigation-agent.test.js`），
   所以 A2 用「既有 15 条绿 + 端到端脚本」证明。测试席若要单测级覆盖「failed → retry」，需要另派卡。
5. **`docs/modules/investigation-agent.md` 里旧行号只复位了本卡碰到的段落**：§3.2 / §3.2.1 / §5.6 用的是终稿行号；
   §3.3 之后（复核、引用校验、研判记录结构）仍是 T012/T018 之前的编号，与本卡无关但依然是错的。
   同类旧行号还在 `docs/modules/evidence-view.md`、`docs/_meta/gaps.md`、`web/src/alert-detail.js:17-18`、
   `web/pages/alert-detail.js:59,861`——后两个在 `web/**`，本卡禁改。
6. **`runUnmatchedSyslog` 的降级路径没动**：它模型说明失败时把原因写进 `verdict.analysis`，照样出结论（不是「没交卷」），
   本卡没往里加回包摘要。

## 附录：端到端脚本

`/tmp/a2a3-verify.mjs` 全文（`base` 指向本工作树，直接 `node /tmp/a2a3-verify.mjs` 即可；只用假 model，不碰网络）：

```js
import { mkdtemp } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import path from 'node:path';
const base = '/home/trtyr/.pi-worktrees/hids-ai-console/hids-ai-console/P003-T022';
const { AgentToolbox } = await import(`${base}/agent-tools.js`);
const { InvestigationAgent } = await import(`${base}/investigation-agent.js`);
const { InvestigationStore } = await import(`${base}/investigation-store.js`);
const { TriageMonitor } = await import(`${base}/triage-monitor.js`);

const directory = await mkdtemp(path.join(tmpdir(), 'p003-t022-'));
const history = new InvestigationStore(path.join(directory, 'results'));
const toolbox = new AgentToolbox({
  listTools: async () => [{ name: 'get_honeypot_event', inputSchema: { type: 'object', properties: { id: {} }, required: ['id'] } }],
  callTool: async () => ({ id: 7, source_ip: '192.0.2.2', host_ip: '10.0.0.5' })
});
let mode = 'prose';
const model = { model: 'fake', complete: async (_m, tools) => {
  if (mode === 'prose') return { content: '我先梳理一下这条蜜罐告警，需要核对来源与请求载荷。' };
  if (!tools.length) return { content: JSON.stringify({ assessment: 'supported', concerns: [], missing_evidence: [] }) };
  return { content: JSON.stringify({ verdict: '存疑', confidence: '低', summary: '重跑得到的结论',
    claims: [{ text: '来源 IP 为 192.0.2.2', citations: [{ evidence_id: 'cw:1', pointer: '/source_ip', value: '192.0.2.2' }] }],
    missing_data: [] }) };
} };
const investigator = new InvestigationAgent(toolbox, model);
const monitor = new TriageMonitor({ file: path.join(directory, 'queue.json'), concurrency: 1, investigator, history,
  service: { alerts: async () => ({ alerts: [], partial: false }) } });
const waitFor = async (predicate) => { for (let n = 0; n < 400 && !predicate(); n++) await new Promise(r => setTimeout(r, 5)); };

await monitor.load();
await monitor.enqueue('honeypot:1');
await waitFor(() => monitor.status('honeypot:1').status === 'failed');
const failed = monitor.status('honeypot:1');
console.log('A1 记录状态:', failed.status, '| 阶段:', failed.stage);
console.log('A1 detail 长度:', [...failed.detail].length, '| detail:', failed.detail);
await new Promise(r => setTimeout(r, 50));
console.log('A2 并发位已释放（active）:', monitor.active, '| counts:', JSON.stringify(monitor.summary().counts));
console.log('A3 失败后研判记录库:', JSON.stringify(await history.latest('honeypot:1', 'triage')));

mode = 'verdict';
await monitor.enqueue('honeypot:1', { retry: true });
await waitFor(() => monitor.status('honeypot:1').status === 'done');
const after = monitor.status('honeypot:1');
console.log('A2 重跑结果:', after.status, '| attempts:', after.attempts, '| verdict:', after.verdict, '| summary:', after.summary);
console.log('A3 盘上结论:', (await history.latest('honeypot:1', 'triage'))?.verdict?.summary);
```
