## 四、关键发现

1. **`reply()` 里模型输出的校验失败不往外抛**。它被 `catch` 成一条助手消息「本轮输入已保存；自动整理暂时失败：<原因>」（`wiki-workbench.js:240-242`），会话停在 `collecting`。实测撞出三种：反馈缺 `diagnosis`、客户经验 JSON 块缺失、外部证据不是 HTTPS。调用方只能从 `record.messages` 最后一条看出原因。
2. **单页修订 `update()` 不跑完整的发布前检查**。它只查路径、版本、正文长度、编号与状态、来源五项（`wiki-store.js:154-163`），不查 `title` / `applies_to` / `updated` 格式，也不查 `refs` 与 `evidence` 指向的页是否存在（那些在 `checkBundle()`，`wiki-store.js:210-219`）。
3. **单页修订的历史备份写在全部校验之后**，所以「参数不合规」与「版本冲突」两种失败不会在历史目录里留下任何东西（`wiki-store.js:154-167`）。想在历史目录里反查失败原因是行不通的。
4. **`publishedFor()` 不校验 `review.verdict` 的取值**（`wiki-store.js:332`）。实测仓库里有一条 `review.verdict` 为 `unsuccessful_attack` 的经验同样被返回。
5. **批量发布里「正文太短」的错误文案不是「正文无效」**。长度下限 100 字（`wiki-store.js:243`）排在 `checkBundle()` 之后，所以实际先被检查项拦下，报「维护草案未通过检查：…」。
6. **回放样本只来自会话目录**，要求文件名像 UUID、`status: published`、带审核人与反馈（`wiki-replay.js:23-26`）。判据库目录本身不提供样本。
7. **`reply()` 里 `sourceEvidence()` 被调了两次**（`wiki-workbench.js:220` 与 `:226`，入参相同）。第一次抛错就不会走到第二次。代码与注释里都没写为什么这么写。

2. **判据库目录的内容没逐页读**。本卡的证据源限 `_breakdown.json` 里 `knowledge-base.files` 的三个实现文件（A2 的硬要求），所以判据页正文与 `wiki/_schema.md` 的具体内容没查。页面因此只给出代码层面的要求（「Wiki 操作手册」具体写了什么，页里说「没查到」）。
3. **为什么客户经验不走回放那一套**，代码与注释里都没写，没查到。
4. **单页修订不跑 `checkBundle()` 是设计还是遗漏**，代码里没有说明，没查到。
5. **为什么 `reply()` 里 `sourceEvidence()` 被调两次**，没有注释说明，没查到。
6. **回放样本在真实使用中的覆盖情况没查到**。本卡的实测样本是现造的；真实链路依赖别的会话已经发布过且带反馈。
7. **孤儿证据页查不出来**。`_evidence/` 下有 17 个 `.md` 文件（含 `index.md`），但这三个文件里没有任何一处统计证据页的引用关系，`health()` 只查被引用方是否存在（`wiki-store.js:146-147`）。
8. **页面里的行号对应基线提交 `35530d8`**。代码一旦改动，这些行号要重新核一遍。
