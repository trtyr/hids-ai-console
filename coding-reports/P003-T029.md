## 二、验收逐条

### A1 写配置接口；不重启进程，牧云地址/令牌、模型地址/密钥/模型名运行中就能改，改完 `GET /api/config` 立刻反映

- 接口：`POST /api/config`，正文 `{"<KEY>":"<value>", …}`，部分更新，响应 `{updated:[键名…], config:{…与 GET 同形状}}`。
- 「立刻反映」：store 把覆盖层写进 env，GET 读 `configSummary(config.env)`。
- 「运行中生效」：`applyLiveConfig` 原地换活着的三个客户端对象（不重建——路由是值捕获）。
- 证据（单测）：`✔ A1 写六项后 GET /api/config 立刻反映，updated 逐键回键名（不重启进程）`、`✔ A1 活着的客户端原地换值：牧云 rpc、MCP 客户端、模型三项都走新值`
- 证据（真进程）：`probe-config-write.sh` 里 `PASS 不重启进程，GET /api/config 立刻报新值`、`PASS 写完之后 /api/status 立刻连上新地址（200）`、`PASS 牧云调用用的是写进去的新 Token（stub 收到 Cookie）`——最后这条证明不是「只有 GET 变了」：真的牧云调用打到了新地址、带的是新 Token。
- 变异验红：把路由里的 `applyLiveConfig(...)` 注释掉 → 探针 `FAIL 写完之后 /api/status 应 200` + `FAIL stub 没收到新 Token`（2 条红）；把 `update()` 里的 `apply()` 注释掉 → 单测 `1 fail`。

### A2 机密写入后不回显原文，任何响应不出现 Token 和密码

- 写成功的 200 只回 `updated`（键名）+ `config`（机密只在 `secrets` 里布尔）；400 的 `error` 只点键名，不回显值。
- 证据：`✔ A2 写成功与写失败的响应里都不出现 Token / 密钥原文`——写成功的正文不含新 Token / 新密钥 / 旧 Token；GET 正文不含四个机密；值不合法时（`ftp://secret-in-url.test/v1`）错误正文既不含 `LLM_BASE_URL` 的坏值也不含那段像凭据的串。
- 真进程：`PASS 写成功的正文不含 Token 原文`、`PASS GET 正文不含 Token 原文`、`PASS 日志里没有 Token 原文`、`PASS 重启后的日志里没有 Token 原文`。
- 变异验红：把 `journal('config.updated', { keys })` 改成带 `patch` → 单测 `1 fail`（A5 那条，因为值进了日志）。

### A3 写操作过鉴权闸门；鉴权没启用时行为在文档里写明

- 闸门是 `hasAccess` 那道 Basic 认证（`server.js:413`、`server.js:421`），在 URL 解析与全部路由之前，所以 `POST /api/config` 与 GET 同闸。
- 没配 `HIDS_BASIC_AUTH_PASSWORD`（鉴权未启用）时闸门放行 → **写也放行**。这是合法部署不是推荐部署，已写进 `docs/modules/http-api.md` §3.6「鉴权（A3）」与 `openapi.yaml` `writeConfig.description`（并说明风险：任一能访问端口的人都能改牧云地址、把模型密钥送出去）。
- 证据：`✔ A3 写操作过 Basic 认证闸门；没启用鉴权时放行（文档写明的两态）`——启用了认证：无凭据 401「需要登录后访问」且覆盖层为空（`store.values().LLM_MODEL === 'fake-model'`，被拒的写一个字没落盘）；带正确凭据 200；未启用认证的实例 POST → 200。

2. **两个日志事件没进 `docs/architecture.md` §3.6 的事件表**（`config.updated`、`config.load_failed`）：那张表在 `docs/architecture.md`，不在本卡 scope。本卡把两事件的字段口径写在 http-api.md §3.6 与 `log.js` 的调用点。**建议**派一张小卡补表（一行一个事件）。
3. **运行中生效靠原地改字段**：`rpc-client.js` / `model-client.js` / `mcp-client.js` 不在本卡 scope，所以 `applyLiveConfig` 直接给实例赋 `baseUrl`/`token`/`url`/`apiKey`/`model` 字段。若这几个模块以后把这些字段改成私有或只读（`#field` / getter-only），这里会静默失效。**没有测试能跨模块守住这条**，只能靠注释（`server.js:61-64`）。建议那几张卡改动时 grep 一下 `applyLiveConfig`。
4. **覆盖层只能增不能删**：没有「恢复环境变量 / 删掉某个键」的接口——值必须是非空字符串，要清掉改过的值只能手工删 `.data/config-overrides.json` 再重启（文档 §3.6 已写明）。卡 A1 没要求删，记下。
5. **并发写没有版本号**：两个写请求同时到达是「后写覆盖先写」，没有 ETag / 版本比对；单进程内落盘是原子的、不会写坏文件，但多进程共享同一个 `.data/` 时进程 A 的 env 不会看到进程 B 的改动。现部署是单进程，记下。
6. **鉴权未启用时可写是明文契约，但是真实风险**：按 A3 要求「行为在文档里写明」，写进了 §3.6 与 openapi description，并注明了风险与挡法（配 `HIDS_BASIC_AUTH_PASSWORD`）。部署说明在 `docs/architecture.md` §10.1（scope 外），没同步提醒。

8. **真进程探针不是单测**：`probe-config-write.sh` 19 条是冒烟（≈4s，起了 3 次真进程 + 1 个 stub），单测 9 条才是每次必跑的那套（<0.4s）。两者都在 `evidence/test/P003-T029/`，命令与结论都贴在上面。
