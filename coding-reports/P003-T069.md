# P003-T069 交付报告 · 业务级批量操作（A07）

**新增** `POST /api/batch/{enqueue|false-positive|dispose}`：
- 入参 `alert_ids`：非空数组、上限 100、每项过 `validTriageId`；重复 ID 去重（按首次出现顺序）。
- 返回 `{action, accepted[], rejected[{id, reason}]}`——**部分失败不整体回滚**，拒绝原因复用 caller 类错误口径（404 找不到案件 / 409 研判未结束或重复处置）。
- 三个动作：批量入队（复用 monitor.enqueue）、批量误报（复用误报登记的全部前置检查与后台维护启动）、批量处置（disposition 四态 + 单向迁移）。

**验收**：上限与重复幂等 ✅；部分失败如实汇总 ✅；每条拒绝原因复用现有错误码口径 ✅；四类用例（全成功/部分失败/全失败/超上限）✅。

**T063 处置位的落点**：`disposition` 字段写在 TriageMonitor 记录上（随 persist() 快照落盘），单条处置接口并入批量接口的 `dispose` 动作（避免两套写入口）。设计见 P003-T063.md。

**测试**：evidence/test/P003-T068/batch-related.test.js（T069 三条 + T068 两条）。
