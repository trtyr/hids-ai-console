## 四、关键发现

1. **Basic 认证默认是关的**。`hasAccess()` 在 `HIDS_BASIC_AUTH_PASSWORD` 为空时直接放行（`server.js:58-65`）。这不是配置疏忽，是代码写死的语义——探针 A6 实测空密码时 `/api/session` 回 200。
2. **方法对不上的路径，除一处外都落到 404**。全文件唯一的 405 在 `server.js:232`（`/api/agent/prompts` 的非 GET）。`POST /api/session`、`POST /api/triage/rules` 都回 404「接口不存在」（探针 H4/H5）。
3. **404 有两种文案**：`/api/` 下的未知路径回「接口不存在」（`server.js:355-356`），`/api/wiki/` 下的未知路径回「知识库接口不存在」（`server.js:278-299`）——后者还得先过管理员令牌判定，所以不带令牌时它是 403 而不是 404（探针 H1/H2）。
4. **知识库的两个读接口不需管理员令牌**，因为它们排在令牌判定之前（`server.js:234-249`）；代价是 `/api/wiki/` 下任何别的路径（包括不存在的）都先撞令牌判定。
5. **分页校验排在「后端配没配」之后**。`/api/alerts?count=0` 在没配牧云时回 503 而不是 400（探针 C2）；有牧云服务才验出 400「分页参数无效」（探针 C）。
6. **SSE 只认 `stream=1` 这个字符串**。`stream=0`、`stream=true` 都走普通 JSON 分支（探针 D3）。流式分支里研判抛错也是 200，错误在 `error` 帧里（探针 D2）——判断成败要看帧里的 `type`，不能只看状态码。
7. **两个 400 是靠文案里的「请求正文」四个字匹配出来的**，不是靠错误类型区分（`server.js:357-359`）。探针 F1/F2 实测。
8. **`createServer` 有两个参数没有使用点**：`knowledge`（`server.js:112`）与 `maintenanceEntry`（`server.js:115`），`grep` 只命中这两行。
9. **入口判定的边界**：`server.js:363` 的 `realpathSync(process.argv[1])` 在入口路径不存在时抛 ENOENT，模块加载即失败（以 `-` 作 stdin 入口时实测复现，见侦察记录第 5.1 节）。

## 五、未决

下面几条是本卡**没有解决**的问题，写在这里以免被当成已交付。

1. **牧云侧的真实响应没验证。** 本机无 `CLOUDWALKER_URL` / `CLOUDWALKER_API_TOKEN`，未发起任何外部请求。`/api/alerts`、`/api/alerts/{type}:{id}`、`/api/status` 的响应体形状只按代码里的组装逻辑描述，没有实测样本。模块页第 9.3 节已写明。
2. **模型服务的真实行为没验证。** 没有真实模型服务，SSE 的进度段条数与内容取决于研判过程本身；模块页引用的探针输出用的是替身研判器，不能当成真实链路的节奏。
3. **`openapi.yaml` 与 `server.js` 没有逐条比对。** 本卡只核了条数（契约 35 条路径）与两处引用，没有比对参数与响应体。模块页第 9.1 节明说这是两套分开维护的真源，比对是接口契约卡的事。
4. **`POST /api/wiki/sessions` 的写路径没跑通。** 令牌之后的分支要读研判记录与案件目录（`server.js:250-277`），本卡只探到令牌判定与正文上限两处，没有构造真实案件目录跑完整条链路。
5. **`/api/agent/triage/{alertId}` 的方法分支只测了一条。** 该分支（`server.js:220-227`）对 GET 与 POST 给不同结果（200 / 202），本卡用探针测了 GET 的非法 ID 回 400；POST 路径的非法 ID 未单独测。
6. **行号基准。** 模块页的行号对应 `server.js` 第 373 行版本（commit `35530d8`）。代码一改，这些行号要重新核一遍。

另外两条是**已确认但本卡不改**的事实：`server.js` 的两个无使用点参数（`server.js:112`、`server.js:115`）与唯一的 405 分支（`server.js:232`）。模块页只陈述现状，不写「这里应该改成什么」——那是评审的活。

最后一条是**文档之间的口径不一致，本卡无权改**：`docs/architecture.md:480` 的模块清单里，`http-api` 的覆盖构件只列了四项（路由分发、Basic 认证、管理员令牌、SSE 流式响应），而 `docs/modules/_breakdown.json` 的 `http-api.components` 列了五项，多一项「分页参数校验」。本卡的模块页按 `components` 字段写，五项都覆盖。`docs/architecture.md` 不在本卡 scope 内，所以只记录在这里，不去动它。
