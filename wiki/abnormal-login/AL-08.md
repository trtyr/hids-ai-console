# AL-08 · syslog 里没有的，去 API 查

> ⚠️ **这一条 2026-11-03 改过，改的是根本口径。**
>
> 原来标题是「这几件事拿不到，必须承认」，列了六件事说「拿不到」。
> **其中四件其实拿得到 —— 去 `AbnormalLoginEventService` 查就有。**
>
> syslog 只是一条**告警通知**（谁、哪台机、什么时候）；
> 事件服务才是**证据库**。

| 需要的信息 | syslog 里有吗 | 去哪拿 |
| --- | --- | --- |
| `auth_type`（SSH / RDP / …） | ❌ 没有 | **`AbnormalLoginEventService`** → `auth_type` |
| `repair`（牧云认为哪里异常） | ❌ 没有 | **同上** → `repair` |
| 来源归属地（国家/省/市） | ❌ 没有 | **同上** → `country_code` / `province_code` / `city_code` |
| 来源 IP 的运营者 | ❌ 没有 | **同上** → `owner` |
| `event_description` / `event_solution` | ⚠️ 有字段但**实测全空** | 用固定的处置五步（AL-09） |
| 登录**成功还是失败** | ❌ 没有 | 这一类**只报成功的登录**；失败的走暴力破解类 |
| 登录后的**完整命令历史** | ❌ 没有 | 靠命令记录类（`cloudwalker-full-command`）补，但那是另一类 |
| 资产的重要性等级 | ❌ 没有 | 从配置基线的资产台账读；没登记就标「未知」 |

## 两条硬规矩

1. **能查的必须查。** 上表里标「去 API 拿」的那几项，
   如果 `api_evidence` 里没有 —— 说明这次**没查到**，不等于不存在。
   不许直接判「拿不到」。
2. **查了还是没有，才承认拿不到。** 这时候写清缺什么、为什么缺
   （API 里没这条事件？还是在但字段为空？），存疑里说清楚。
