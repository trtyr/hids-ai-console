# AL-02 · 「来源可信」是最强的一个维度，但它只管一半

**先说结论：来源可信 → 大概率是运维；来源不可信 → 也未必是攻击。**

「可信来源」指**运维登记过的堡垒机 / 跳板机出口 IP**（存在配置基线里）。

| 来源 | 含义 | 能推出什么 |
| --- | --- | --- |
| 在**运维出口池**里 | 这个 IP 就是运维平时登录用的 | 登录**可能**是运维 —— 但账号可能被盗 |
| **不在**出口池 | 这个 IP 我们不认识 | **不知道**是谁 —— 要往下找证据 |

## ⚠️ 有一条极容易搞混的界线

**「这个 IP 在历史上出现过」≠「这个 IP 是运维出口」。**

历史出现过，可能只是**上一次攻击**也是从这个 IP 来的。
把这两个概念合并，就会把攻击者的 IP 当成自己人放过去。

**判据**：只认配置基线里**显式登记的那个池子**，不认「见过」这个弱信号。

## ⚠️ 还有一条：从内网直接连过来，绕开堡垒机

来源 IP 是内网地址（`10.x` / `172.16-31.x` / `192.168.x`），且**不在**运维出口池里。

**这不是「可信」，是「绕过了唯一的入口」。**

运维要登机器，规定动作是从堡垒机跳。一台机器上突然出现内网直连的 root 登录，
两种可能：① 有人在内网横向移动 ② 某个自动化脚本用了 root。

**两种都不能直接放过去 → 存疑。**
