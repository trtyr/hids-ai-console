# 判据夹缝

## 这是什么

**两条判据各自都对，合起来却在某个样本上打架。**

模型遇到这种样本，两边都能引 —— 引哪条取决于它先读到哪条，
于是**同一个样本跑两次可能给两个结论**。

## 2026-11-03 一天踩了四次

| # | 类 | 夹在哪两条之间 | 后果 |
| --- | --- | --- | --- |
| 1 | 可疑命令 | SC-02「单条 `chmod +s` = 待定」 vs SC-11 路径 C「改系统文件有攻击语义」 | S8 判不出来 |
| 2 | WebShell | WS-07「技术栈不对 → 降级存疑」 vs WS-08 第 0 步「web 目录 + web 进程写的 → 真实威胁」 | 一个 `.jsp` 放在只跑 PHP 的机器上被判成真实威胁 |
| 3 | 蜜罐 | 路径 C「浅层交互 = 扫描噪音 → 误报」 vs HP-01「内网来源要转人工」 | 内网机碰蜜罐 5 秒被判误报 |
| 4 | 可疑命令 | SC-06「反弹 shell 形态 = 硬证据」 vs 模型自己找的「来源不可信才能定罪」 | 判定在真实威胁和存疑之间摇 |

## 怎么发现

**不是靠读代码，是靠跑样本。** 前三次都是「期望 A 实得 B」，
而且**重跑结果不一样**（抖动）—— 抖动就是夹缝的信号。

**定位方法**：把模型引用的判据和期望结论对一遍，
看它引的两条是不是互相拆台。

## 怎么修

**给上位的判据加一个「必要条件」，让夹缝消失。**

三个例子：

- 第 1 次：SC-11 第 0 步加「**给系统自带命令加 SUID，单条就够定罪**」——
  把「待定」那半边直接排除
- 第 2 次：WS-08 第 0 步加「**技术栈必须对得上**」——
  跑不起来的不是活着的 WebShell
- 第 3 次：路径 C 加第 5 条「**来源不是内网**」——
  内网横向不叫背景噪音

## 一条可复用的规矩

> **写新判据时，问一句：这条和已有的哪条会在边界上打架？**

打架的地方，**要么加必要条件把它们分开，要么合并成一条**。
留着不管，它一定会在某个样本上暴露 —— 而且是以「抖动」的形式，
最难查。
