# 数据不全不等于不合格

## 这条是被用户问出来的

用户原话：

> 「他那个告警为什么会不合格？为什么？为什么会不合格？
> 为什么不合格的告警你不去查？它都已经告警了，为什么你不去查？」

## 原来错在哪

护栏层依据 GEN-08 硬丢两类：

- `event_state` 是「已忽略 / 已处理」→ 丢
- `event_level` 是 nil → 丢

**两条都站不住：**

① **「已处理」不等于「判对了」。** 运维手滑点一下，真威胁就静默消失。
降噪是让人少看无关的，**不是让人看不到该看的**。

② **「等级缺失」纯粹是错的 —— 数据一直都在，只是 syslog 没带。**
实测 API：WebShell 4/3/3、异常登录 2、蜜罐 2、可疑命令 3。

**实测损失：21400 条里 4828 条被丢（23%），WebShell 类高达 87%。**

## 铁证

样本 W9 / W10 原来期望是「(过滤)」，改口径后判出**真实威胁**：

    W9   file_path=/var/www/html/x.php  file_owner=www-data  event_state=processed
    W10  file_path=/var/www/html/y.php  file_owner=www-data  event_level=nil

「在 web 目录 + web 进程写的」正是 WS-08 第 0 步的硬证据。
**这两条本该判真实威胁，却因为「已处理」和「没等级」被静默丢了。**

## 现在怎么做

护栏**只拦一种**：解析完 payload 是空的（送错了 / 解析器 bug）。

其余一律放行，`state` / `level` 只记成 `guard_flags`，作为研判背景，
**但不构成不判的理由**。

## 一条可复用的规矩

> **能查到的必须查；查了还是没有，才承认拿不到。**
> 而且要说清是「没查到」还是「查到了但字段为空」。
