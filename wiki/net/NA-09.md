# NA-09 · 网络异常判定路径

**要回答**：哪个进程向哪里通信、通信内容/模式是什么、是否与资产职责和授权一致。

1. **取事实**：从事件详情补目标 IP/域名、端口、协议、发起进程、命令行、时间；网络类 syslog 的归属地不代替目标字段。对 DNS 尽量取得同主机、同进程、同目标的时间序列。
2. **看模式**：回连测试域名、高熵/超长子域名、重复查询和非常见进程均可提高调查优先级；检查是否由安全扫描、开发测试或监控触发。单个指标不证明 C2 或外带。
3. **查后续**：核对 DNS 解析后的连接、数据量、进程链和同时间窗其他攻击行为。若只有单条 DNS 事件，不写频次、周期、外带量或“无后续”。
4. **结论**：确认未授权 C2、外带或其他恶意通信 → 真实威胁；确认是授权测试或预期业务流量且覆盖足以排除相反证据 → 误报；单条异常、测试域名未核授权或缺时间序列 → 存疑。

**出处**：[Wazuh 与 Talos 原文核查](../_evidence/dns-original-2026-11-09.md)支持“多指标结合、建立基线”；[MITRE T1071.004](../_evidence/mitre-original-2026-11-09.md)描述 DNS 可被滥用。它们均不支持“命中 dnslog 域名必为真实威胁”。

**SOP 对照**：`sops/net/SOP.md` 第四、五章；频次不可见是明确缺口。
