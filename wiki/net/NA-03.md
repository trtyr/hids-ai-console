# NA-03 · 三条 DNS 判据：谁发的 / 发什么 / 发多少

## 三条 DNS 判据

### ① 谁发的（进程）

MITRE DET0400 强调的是「**非浏览器、非系统进程**」。

| 进程 | 正常发 DNS 吗 |
| --- | --- |
| 浏览器（`chrome` / `firefox`） | ✅ 非常正常 |
| 系统服务（`systemd-resolved` / `chronyd` / `ntpd`） | ✅ 正常 |
| 包管理器（`apt` / `yum` / `docker`） | ✅ 正常 |
| **脚本解释器**（`python` / `perl` / `bash` / `sh`） | ⚠️ **看情况** —— 业务脚本会，攻击脚本更会 |
| **`curl` / `wget` / `nslookup` / `dig` / `nc`** | ⚠️ **看情况** |
| **`powershell` / `rundll32` / `mshta`**（Windows） | ❌ 少见 |

**这一条单独不定罪，但它是第一层过滤。**

### ② 发的是什么（域名形态）

| 形态 | 意味着 |
| --- | --- |
| **`xxx.dnslog.cn`** 这类**已知回连测试服务** | **极强** —— 这个域名存在的意义就是被攻击者用 |
| **子域名是长随机串**（UUID/32+字符无意义） | 强 —— 可能是 base32/base64 编码的数据在往外带 |
| 正常业务域名（`api.example.com`） | 弱 |
| 已知 CDN / 云服务域名 | 弱 |

**熵值高 = 「这不是给人看的名字」= 有人在往里塞数据。**

### ③ 发多少（频次）

Talos 的思路：**要有「正常」的基线，才能看出「偏离」。**

- 一次查询 → 可能只是 `nslookup` 试一下
- 同一个奇怪域名**反复查** → 可能是在外带数据
- 高频 + 子域名每次都不同 → **典型的 DNS 隧道**

> ⚠️ **但频次拿不到。** API 只给单条事件，没有「这个域名的累计查询次数」。
> 这是本类的已知缺口（见 NA-07）。
