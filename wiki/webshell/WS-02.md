# WS-02 · 第一判据：文件在不在 web 目录里（`WS-02b` 见下）

**这是全类最重要的一条，也是最容易被忽略的一条。**

Linux Forensics 那篇《Web Shells in the Web Root》写得很直白：

> "A web shell is a script placed **where the web server will execute it**:
> a PHP file in an upload directory, a JSP in a Tomcat application, a CGI script,
> or a configuration change that makes the server execute something it should
> only serve."

**换句话说**：一个 `.php` 文件如果躺在 `/root/backup/` 里，它**永远不会被执行** ——
因为没有人会通过 HTTP 去访问那个路径。

## 路径怎么判

| 文件在哪 | 能推出什么 |
| --- | --- |
| 在**站点根目录 / 上传目录 / 静态目录**下 | 可以被 HTTP 访问 → **是真东西，要认真看** |
| 在**家目录 / 备份目录 / 临时目录 / 测试工具目录**下 | **web 访问不到** → 不是活着的 WebShell |
| 路径**为空**（syslog 没带） | **先去 API 拿 `path`**（WS-09）；拿不到才判不了 → 存疑 |

## ⚠️ 但「不在 web 目录」不等于「误报」，要分两种情况

### 情况一 · 样本库 / 测试文件

安全团队做检测能力测试时，会把一堆 WebShell 样本放在磁盘上（比如
`/root/POC-tool/files/src/webshell/repository/` 这种）。
**这些文件确实存在，但它们是测试样本，不是被部署的攻击入口。**

**判据**：路径落在**运维登记的测试工具目录**里，且文件是 UUID 之类的无意义名字
→ 误报（但要建议运维确认这些样本该不该长期留在生产机上）。

### 情况二 · 传上来了但还没被用

攻击者可能先把文件传到一个临时目录，再找机会移动到 web 目录。
**这时候文件确实不在 web 目录，但它是攻击的前置动作。**

**判据**：路径不在 web 目录，但**文件所有者 / 创建时间 / 周边行为**有异常
→ 存疑（问人：这个文件是谁放的？）。

**所以「不在 web 目录」的实际用法是：**

```text
不在 web 目录 + 在登记的测试目录里  → 误报
不在 web 目录 + 不在登记目录里      → 看其它证据（存疑起步）
在 web 目录                         → 认真判
```
