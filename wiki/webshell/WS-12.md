# WS-12 · 拿到了代码，怎么看

> 🆕 **2026-11-03 新增。** 触发于用户的一句话：
> 「他没有去读 webshell 文件本身吗？我们直接把 webshell 下载到本地，
> 然后自己看不就完事了吗？」
>
> **他是对的，而且这条一直在 WS-09 里被写成「文件内容拿不到」。**
> 实际上 `WebshellEventService.GetFile {"event_id": ...}` 会返回 base64 的文件内容。
>
> 实测：demo 那条 `php_webshell` 拿到 **9,942 字节**，里面是
> 16 个随机函数名、4 处 `base64_decode`、1 处 `eval` 类调用、
> 59 行里 29 行是垃圾英文注释。

## 为什么代码比特征匹配强

| 证据 | 能告诉你什么 |
| --- | --- |
| 牧云的特征匹配 | 「它**像** php_webshell」 |
| **文件内容本身** | 「它**在干什么**」—— 混淆方式、回连地址、后门口令、执行链 |

**前者是别人的判断结论，后者是原始事实。**

## 看代码时盯这几样（按信息量排序）

| 看什么 | 为什么 | 长什么样 |
| --- | --- | --- |
| **执行入口** | 后门总要有「收指令」的地方 | `eval($x)` / `assert(...)` / `system($_GET['c'])` / `preg_replace('/e')` |
| **解密/解压** | 载荷几乎总是加密的 | `base64_decode` / `gzinflate` / XOR 循环（`$a[$i] ^ $k`）/ `str_rot13` |
| **命令来源** | 值是从外部来的吗 | `$_GET` / `$_POST` / `$_COOKIE` / `$_REQUEST` 直接进执行函数 |
| **混淆痕迹** | 真后门才需要藏 | 随机函数名（`function qmXnc`）、单字母变量、超长单行 |
| **伪装填充** | 干扰静态检测 | 大段无意义英文（`// Have as had so these year any someone...`） |
| **回连地址** | C2 在哪 | 硬编码 IP / 域名 / `fsockopen` / `curl_init` |
| **文件操作** | 能不能上传/读文件 | `file_put_contents` / `move_uploaded_file` / `file_get_contents` |

## 判定要点（**这几条最容易错**）

1. **代码特征不是判决书。** 正常业务代码里 `eval`、`base64_decode` 到处都是 ——
   模板引擎、序列化、图片处理都在用。
   **要看的是「这些东西是否连成一条从外部输入到执行的链」。**

2. **混淆本身就是强信号。** 正常业务代码不会把函数名写成 `qmXnc`、
   不会用 29 行垃圾英文填充。**这是「不想被看懂」的直接证据。**

3. **看懂了 ≠ 一定是攻击。** 还要结合 WS-02（在不在 web 目录）、
   WS-03（谁写的）、WS-08 第 0 步。

4. **读不到代码时退回 WS-09 那条路**（特征匹配 + 文件属性），
   并明确写清「这次没取到内容」。

## 一个重要约束

**分析代码 ≠ 执行代码。** 我们只读文本，不 `php xxx.php`、不 `include`、不跑它。
**读代码是安全的，执行它不是。**
