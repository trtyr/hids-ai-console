# WS-04 · 文件代码特征：能帮你，但不能定罪

> 🆕 2026-11-03：**现在能拿到文件内容了**，所以本条升级为
> 「牧云报的特征」+「你自己读到的代码」两路。
> 怎么读代码见 **WS-12**。
>
> 🆕 2026-11-04：**收窄了「不够定罪」的范围** —— 单个代码特征不够定罪，
> 但 **WS-08 第 0 步的三合一形态除外**（见下「所有权怎么用」）。

**最诱人的判据，也是最容易造成误报的判据。**

WebShell 的典型特征：

| 特征 | 例子 |
| --- | --- |
| 执行系统命令 | `system()` / `exec()` / `shell_exec()` / `passthru()` / `popen()` |
| 代码执行 | `eval()` / `assert()` / `create_function()` |
| 编码混淆 | `base64_decode()` / `gzinflate()` / `str_rot13()` / `chr()` 拼接 |
| 变量函数 | `$_GET['x']($_POST['y'])` 这种把参数当函数名调 |
| 一句话木马 | `<?php @eval($_POST['cmd']); ?>` |

## ⚠️ 这些特征在正常业务代码里到处都是

**一个正常的 PHP 应用里，`eval()` 和 `system()` 都可能出现：**

- 模板引擎会 `eval()` 编译后的模板
- 运维脚本会 `system()` 调系统命令
- 加密封装会 `base64_decode()`

**所以「文件里有 eval」不是证据，是线索。**

## 所有权怎么用

| 情形 | 怎么算 |
| --- | --- |
| **单个**代码特征，其他什么都没有 | **不够定罪** → 要看路径和所有权 |
| 代码特征 + 在 web 目录 + web 进程写的 | 强证据 |
| 代码特征 + 在 web 目录 + 文件名随机（如 `a8f3c.php`） | 强证据 |
| **三合一形态**（混淆痕迹 + 解码链条 + 外部输入到执行，三条同时出现） | **直接定罪，不看 owner** → 走 **WS-08 第 0 步** |

> ⚠️ **为什么「单个」要加粗**：上面那些特征单独出现时，正常业务代码里到处都是，
> 所以只能当线索。但**三条同时出现**（随机函数名/超长单行/垃圾填充 +
> `base64_decode`/XOR 循环/`gzinflate` + `$_GET`/`$_POST` 直接进 `eval`/`system`/`assert`）
> 就不是「业务代码碰巧用了 eval」能解释的了 —— 这是后门形态本身。
>
> 这一条**不看 owner**：攻击者提权后以 root 在 web 目录写后门，是最典型的 WebShell，
> 不能因为「不是 web 进程写的」就判不了。**代码摆在那里，是后门就是后门，跟谁写的无关。**
> 「谁写的」只影响误报路径的判断（WS-03 / WS-08 路径 B）。
>
> 三合一形态的完整定义与判定顺序见 **WS-08 第 0 步**，本条不重复。
