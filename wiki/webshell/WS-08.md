# WS-08 · 判定程序

**拿到一条 WebShell 告警，按顺序走，第一个命中的就是结论。**

## 第 0 步 · 有没有真实威胁的硬证据？

出现以下之一 → **真实威胁**，直接结束：

- **文件在 web 目录 + 所有者是 web 进程账号 + 技术栈对得上**
  （上传漏洞的典型形态）—— WS-02 + WS-03 + WS-07
- **`event_type = 异常IP外连` 且外连目标是陌生 IP/域名**（它在活着、被人用）—— WS-05
- **🆕 文件代码本身就是后门形态**（2026-11-03 补）—— WS-12
  **三个同时出现**：
  1. **混淆痕迹**：随机函数名（`qmXnc`）、超长单行、大段垃圾英文填充
  2. **解码链条**：`base64_decode` / XOR 循环 / `gzinflate` 之类
  3. **外部输入到执行**：`$_GET`/`$_POST` 直接进 `eval`/`system`/`assert`

  > **这一条不看 owner。** 之前只看「web 进程写的」，
  > 于是「攻击者提权后以 root 在 web 目录写了个后门」这种**最典型的 WebShell**
  > 反而判不了 —— 所有者不是 web 进程，硬证据不成立，只能存疑。
  >
  > **代码摆在那里，是后门就是后门，跟谁写的无关。**
  > 「谁写的」只影响**误报路径**的判断（WS-03 / WS-08 路径 B），不影响「这是不是后门」。

> ⚠️ **第一条为什么要求「技术栈对得上」**：
> 一个 `.jsp` 文件放在只跑 PHP 的机器上，**web 服务器根本不会执行它**。
> 它是「可疑文件」，但不是「活着的 WebShell」。
>
> 两条判据（WS-07 技术栈、WS-08 判定程序）在这里必须一致 ——
> 否则会掉进「技术栈说降级、判定程序说定罪」的夹缝，
> 模型的结论会在真实威胁和存疑之间摇摆。
> （可疑命令类的第 12 个设计缺陷就是这个形态，这里提前堵上。）

## 第 1 步 · 能给「误报」吗？

两条路径任一成立：

### 路径 A · 安全测试样本库

**文件路径落在运维显式登记的测试工具目录里**，且文件不在任何 web 根目录下。
→ 这是安全团队的样本库，不是被部署的攻击入口 → **误报**

> ⚠️ 但建议顺手提一句：这些样本不该长期留在生产机上。

### 路径 B · 正常业务文件被误判

**四条同时满足**：

- 文件在 web 目录里
- 文件所有者是**业务账号**（不是 web 进程，也不是 root）
- **文件已经有相当年头**（创建距今 ≥ 30 天）
- `event_type` 不是「异常IP外连」

→ 业务自己的代码，被特征匹配误伤了 → **误报**

> ⚠️ **为什么是「文件年龄」而不是「业务上线时间」**：
> 「业务上线时间」我们**拿不到**（不在 syslog 里，也不在配置基线里）。
>
> 2026-11-03 实测踩的坑：原来第四条写的是「创建时间早于业务上线时间」，
> 而事实层根本给不出这个数据 → 模型发现「这条无法核对」，
> 于是拒绝判误报 → 把它判成存疑。
>
> **模型的判断是对的** —— 拿一个拿不到的数据当必要条件，
> 等于让「缺失信息」偷偷变成「不满足」。改成能算出来的「文件年龄」，
> 判据才可核对。

## 第 2 步 · 都不成立 → **存疑**

| 场景 | 为什么存疑 | 该问人什么 |
| --- | --- | --- |
| 路径拿不到（`file_path` 空、API 也没补到） | 判不了是不是 web 目录 | 这个文件的实际路径是什么？ |
| 在 web 目录，但所有权正常 | 看不出是谁放的 | 这个文件是你们部署的吗？ |
| 不在 web 目录，也不在登记目录 | 可能是传上来还没用 | 这台机器上有人放测试文件吗？ |
| 有代码特征，但其它都没有 | 可能是业务代码 | 这个文件属于哪个应用？ |
| 技术栈对不上 | 跑不起来，但为什么在这 | 这台机器上装过 PHP 吗？ |

**存疑必须写清「缺什么信息才能定」。**
