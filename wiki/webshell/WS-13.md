# WS-13 · WebShell 判定路径

**要回答**：告警文件是否含可远程控制的逻辑、是否能由当前 Web 技术栈执行、是否被调用及是否造成后果。

1. **取事实**：文件完整路径、哈希、内容或安全只读分析结果、Web 根目录基线、技术栈、文件来源/写入者、访问日志、子进程和外连。`file_path` 为空时先回查事件详情；仍空则写明缺口。
2. **看代码与可达性**：外部输入到执行、动态解码、命令执行或文件操作的组合值得重点核查；单独 `base64`、`eval`、扩展名或目录位置均不足以定性。文件在 Web 目录也要核该服务器能否执行其语言。
3. **看调用与结果**：访问记录、对应请求参数、Web 进程子进程或出站连接可支持利用链。只看到后门文件可判文件风险，但不能推断已被使用；不在 Web 目录也不能仅凭此判无害。
4. **核对授权**：测试样本库、业务代码和变更工单需要匹配文件哈希、资产、时间和用途；文件 owner 为 root 或业务账号均不能单独决定结论。
5. **结论**：确认未授权 WebShell 文件或其使用 → 真实威胁，明确“落地/调用/执行”的层级；确认是登记样本或误识别 → 误报；内容、可达性或来源未核实 → 存疑。

**出处**：MITRE [T1505.003](../_evidence/mitre-original-2026-11-09.md)将 WebShell 描述为置于可访问 Web 服务上的脚本；旧库 CISA/NSA/ACSC 页面只给机构首页，见[来源审计](../_evidence/source-limitations-2026-11-09.md)。

**SOP 对照**：`sops/webshell/SOP.md` 第三章九步；只读分析文件，不能为验证而执行可疑代码。
