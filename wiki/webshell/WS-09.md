# WS-09 · syslog 里没有的，去 API 查

> ⚠️ **这一条 2026-11-03 改过，改的是根本口径。**
>
> 原来标题是「这几件事拿不到」。**其中最要命的那一条（文件完整路径）其实是拿得到的** ——
> syslog 的 `file_path` 常常是空，但 `WebshellEventService` 的 `path` 有完整路径。
>
> 而「文件在不在 web 目录」是本类的**第一判据**。原来因为「只看 syslog」
> 把它判成「拿不到 → 存疑」，等于把可判的案子全推成存疑。

| 需要的信息 | syslog 里有吗 | 去哪拿 |
| --- | --- | --- |
| **文件的完整路径** | ⚠️ `file_path` **常见为空** | **`WebshellEventService`** → `path` |
| **WebShell 类型** | ⚠️ `file_type` 拼写不统一 | **同上** → `webshell_type` |
| 有没有被隔离 | ❌ 没有 | **同上** → `isolate_state` |
| `repair`（牧云认为哪里异常） | ❌ 没有 | **同上** → `repair` |
| **文件内容** | ❌ 没有 | **能取到！** `WebshellEventService.GetFile {"event_id": ...}` 返回 base64 内容 → 存到 `05-文件内容.txt`，**直接看代码**（WS-12） |
| **谁写的** | ❌ 没有进程信息 | 从文件所有者反推（WS-03） |
| **这个文件被访问过几次** | ❌ 没有 | 靠 `event_type` 和 `file_access_time` 间接推 |
| **站点用的是什么框架** | ❌ 没有 | 从配置基线的 `web_roots` 反推（WS-02b） |
| **它是怎么进来的** | ❌ 没有 | 要结合访问日志，不在这一类 |

## 两条硬规矩

1. **能查的必须查。** 路径为空时**先去 API 拿 `path`**，拿到了就按 WS-02 判；
   拿不到才说「判不了」。
2. **`api_evidence` 里有值，就用它算判据。** 事实层已经把 API 补的字段
   并进 payload 再算 criteria —— 你看到的 `path.path` / `criteria` 已经是
   **补全之后**的结果，不需要自己再补一遍。
