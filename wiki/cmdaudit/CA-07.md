# CA-07 · 处置与用法：它是证据，不是处置对象

## 处置与用法

### 这一类本身没有「处置」

你没法对「一段命令流水」做处置 —— 要处置的是那一条可疑命令、
那一次提权、那个 WebShell。

**所以它的动作永远是 `watchlist` 或 `escalate`**，
`suggested_action.note` 要写清「建议去看哪一条会话」。

### 它真正该怎么用

| 场景 | 用法 |
| --- | --- |
| 别的类判了「存疑」 | **回头翻这个会话**，看前后命令能不能定性 |
| 别的类判了「真实威胁」 | 用这个会话**还原攻击链**，写进报告 |
| 日常巡检 | 按 `suspicious_event_count > 0` 排序，先看这些会话 |
| 事后复盘 | 按 `session_id` 拉出完整命令序列 |

### 三态在这里的落点

| 结论 | 什么情况 |
| --- | --- |
| `真实威胁` | 会话里有关联到硬证据的可疑命令（反弹 / 挖矿 / 提权链） |
| `误报` | 纯运维会话：可疑数 0，命令都是常规形态 |
| `存疑` | 可疑数 >0 但拿不到具体命令；或者命令全是自定义脚本 |

> **最重要的一句**：这一类的价值不在于「判得准」，
> 而在于**它是唯一能看到整串的视角**。所以宁可判存疑，
> 也不要把一个可能藏着线索的会话判成误报糊过去。
