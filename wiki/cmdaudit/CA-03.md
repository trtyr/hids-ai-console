# CA-03 · `suspicious_event_count` 是最重要的一个数

## `suspicious_event_count` 是最重要的一个数

**它直接告诉你：这个会话里，有几条命令被牧云的规则判成可疑。**

| 值 | 意味着 |
| --- | --- |
| `0` | 这个会话里没有触发任何可疑规则 |
| `> 0` | **有** —— 而且它同时给了你「可疑几条」 |

### 但它不能单独定案

`suspicious_event_count > 0` **不等于**「这个会话是攻击」：

- 运维自己跑 `nmap` / `nc` 也会触发可疑规则
- 装软件、调防火墙、查日志，都可能命中

**它是「去查那几条」的指路牌，不是结论。**

### 反过来：`= 0` 也不等于安全

**可疑规则只覆盖「它认识的形态」。** 攻击者用规则不认识的写法，
`suspicious_event_count` 就是 0。

所以：

```text
= 0  → 不能判「确认安全」（只能说「没触发规则」）
> 0  → 必须去看那几条具体命令
```

### 和「命令数」配着看

| 命令数 | 可疑数 | 像什么 |
| --- | --- | --- |
| 少（1~3） | 0 | 登上来看看就走，或者脚本/探针 |
| 多（20+） | 0 | 运维在排查（`ls` `cd` `cat` `grep` 一大串） |
| 少 | **> 0** | **最值得看** —— 上来就干正事 |
| 多 | **> 0** | 长时间作业里夹了可疑动作 |
