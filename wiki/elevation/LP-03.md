# LP-03 · 提权者是谁：身份是第一维度

## 提权者是谁

`origin_effect_user` 是**谁在执行这次提权**（原有效用户）。
`user` 是**提到谁**（空 = root）。

### 三种身份，三种含义

| `origin_effect_user` | 意味着 | 结论方向 |
| --- | --- | --- |
| `root` | root 在提权（自己提自己） | 通常无意义，可能是 sudo 嵌套 |
| **服务账号**（`www-data` / `nginx` / `tomcat`） | **web 进程在提权** | **极可疑** —— 应用不该需要 root |
| **普通用户**（运维账号 / 业务账号） | 人在操作，或在跑脚本 | 要看这个账号平时提不提权 |
| 未知 / 空 | 不知道谁 | 存疑 |

### 「这个账号平时提不提权」怎么判

**这需要历史基线** —— 而这个基线现在**没有**。

所以实际做法：

1. 如果 `origin_effect_user` 是**服务账号** → **直接加重**
   （web 进程提权，几乎只有两个原因：应用有漏洞，或者机器已经被控制）
2. 如果是普通用户 → 需要看：
   - 这个程序（`exename`）是不是运维常用的（`dash` 在巡检脚本里很常见）
   - 提权之后这个进程还干了什么（LP-08）
3. 拿不到身份 → 存疑

> ⚠️ 不要假设「普通用户提权就正常」。攻击者拿到一个低权限账号之后，
> 第一件事就是提权 —— 而那时候它表现出来的也就是「一个普通用户在提权」。
