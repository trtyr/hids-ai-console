# LP-02 · SUID 提权：哪个程序带 SUID 才正常

## SUID 提权：哪个程序带 SUID 才正常

**这是这一类最硬的一条判据。**

SUID 位的意思是「**谁执行它，就临时获得文件所有者的权限**」。
所以「哪个程序带了 SUID」直接决定了它危险不危险。

### 正常的 SUID 程序（系统自带、白名单）

这些**本来就该带 SUID**，它们的存在就是为了让普通用户完成特权操作：

```text
sudo   su   passwd   ping   ping6   mount   umount
chsh   gpasswd   newgrp   pkexec   crontab   fusermount
expiry   chfn   wall   write   at
```

**`dash` / `bash` / `sh` 不在这份名单里。**

一个 shell 带 SUID = **任何能执行它的人都直接变成 root，不需要密码**。
**这不是「运维习惯不好」，这是把机器敞开。**

### GTFOBins 那一类（拿到 SUID 就等于拿到 root）

GTFOBins 收集的是「**能用来绕过本地限制的合法程序**」。
它们带 SUID 的风险远高于别的程序，因为**用法是现成的**：

| 程序 | 带 SUID 之后能干什么 |
| --- | --- |
| `sh` / `bash` / `dash` | 直接 `-p` 保持权限 → root shell |
| `python` / `perl` / `ruby` | `os.setuid(0)` → root shell |
| `find` | `-exec /bin/sh -p \;` |
| `vim` / `vi` | `:!sh` |
| `less` / `more` | `!sh` |
| `awk` | `system("/bin/sh")` |
| `tar` | `--checkpoint-action=exec` |
| `nc` | 反弹 root shell |
| `cp` / `mv` / `cat` | 读写任意文件（改 `/etc/shadow`、写 authorized_keys） |

### 判据怎么用

```text
exename 是 shell（sh/bash/dash/zsh/ksh）        → 极可疑
exename 在 GTFOBins 名单里                     → 可疑
exename 在系统 SUID 白名单里                    → 正常，不是提权事件
exename 是业务自己的程序（路径在 /opt 之类）      → 要看它是不是本该有 SUID
```

> ⚠️ **但「可疑」不等于「判真实威胁」** —— 还得看**谁在用**（LP-03）
> 和**它是什么时候出现的**（LP-06）。运维自己给 dash 加 SUID 做巡检也是常事，
> 那是「配置不当」，不是「入侵」。
