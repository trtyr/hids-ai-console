# LP-07 · syslog 和 API 各有什么

## syslog 和 API 各有什么

**这一类跟暴力破解正好相反**：syslog 给的信息**比 API 多**。

### syslog 侧（19 个字段，很全）

| 字段 | 是什么 |
| --- | --- |
| `process_name` | 干提权这件事的进程名 |
| `process_command_line` | 它的命令行 |
| `process_path` | 它的路径 |
| `process_id` / `process_tree` | PID 和父进程链（`[{pid, uid, euid, ppid}]`） |
| `file_permission` | 文件权限（能看到 SUID 位） |
| `user_name` / `user_gname` | 原用户 / 原组 |
| `user_target_user` / `user_target_user_id` | 提到谁（`0` = root） |

**`process_tree` 里的 `uid` / `euid` 就是判据要的东西** ——
`uid != 0` 且 `euid == 0` 正是「提权」的定义。

### API 侧（字段名完全不同）

| API 字段 | 等价于 syslog 的什么 |
| --- | --- |
| `exename` | `process_name` |
| `origin_effect_user` | `user_name`（谁提的） |
| `user` | `user_target_user`（提到谁，空 = root） |
| **`privilege_escalation_type`** | **syslog 里没有** —— 这是 API 独有的 |
| `repair` | syslog 里也没有（持续时长） |

### 所以这一类的补证据方向是反的

**被判据需要、但 syslog 里没有的只有两样**：
`privilege_escalation_type`（提权方式）和 `repair`（持续时长）。

**其余全在 syslog 里** —— 所以 syslog 必须解析干净，特别是 `process_tree`
（它是个**转义的 JSON 字符串**，要先解一层）。
