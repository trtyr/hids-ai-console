# LP-01 · 这一类告警在说什么

## 一条本地提权告警，说的是一件什么样的事

**某个用户，在这台机器上把一个进程**提成了更高权限**（通常是变成 root）。**

牧云按「**这个进程的提权方式**」报上来，并带上：
进程名、父进程链、原用户、目标用户。

### 这一类真正要回答的问题

**不是「有没有发生提权」——** 提权是运维的日常操作，
`sudo apt update` 就是一次提权。

**是：这次提权，是谁在提、提到哪、用什么提到？**

- `sudo` / `su` 提权 → PAM 认过证了，**是授权的人干的**
- **SUID 提权** → 没走认证，靠「这个程序本身带 SUID 位」
  → **这正是攻击者最爱的手法**（MITRE T1548.001）

**所以这一类的重心在「提权方式 + 提权者 + 提的是哪个程序」这三样上。**

### 数据长什么样（demo 实测）

**17,189 条，全部是同一个形态**：

```text
privilege_escalation_type = SUID提权
exename                   = dash
origin_effect_user        = collie
user                      = （空 → root）
```

也就是说：**一个叫 `collie` 的普通用户，通过一个带 SUID 位的 `dash` 拿到了 root。**
这个形态在 demo 里出现了 17,189 次，一次例外都没有。

这是这一类的真实面貌：**巨量噪音，而且全是同一个良性形态**（运维巡检脚本）。
