# LP-05 · 判定程序：按顺序走，第一个命中就是结论

## 判定程序

**第一个命中的就是结论，不要反复横跳。**

```text
第 0 步 · 有没有「明确是攻击」的证据？
         · 提权之后 300 秒内出现了：可疑命令 / 反弹 Shell / 恶意文件 /
           WebShell / 网络外连                          → 真实威胁
         · 或者 提权者是服务账号（www-data 之类）        → 真实威胁
        ↓ 没有

第 1 步 · 能不能排除「这次提权是攻击」？
        · 提权方式是 sudo / su（**经过认证**）
        · 且 提权者不是服务账号
        · 且 exename 在系统 SUID 白名单里
        三条全成立                                      → 误报
        ↓ 缺任一条

第 2 步 · 存疑
        写清缺什么：是提权者身份不明？
                    还是 exename 不在白名单也不在 GTFOBins？
                    还是不知道提权之后干了什么？
```

### 第 0 步为什么把「服务账号」也算硬证据

`www-data` / `nginx` / `tomcat` 这些账号**不该有提权动作**。
它们提权的唯一合理解释是「应用有漏洞」或「机器已被控制」。

**这是本类唯一一条不依赖「后续行为」的硬证据** ——
因为后续行为可能还没发生（攻击者可以等）。

### 为什么第 1 步要求「经过认证」

`sudo` 的认证事件是**牧云看不到的**（syslog 里没有 PAM 日志）。
所以这一条只能靠 `privilege_escalation_type` 字段间接推：
类型是 sudo/su → 机制上一定认过证 → 可以当弱良性信号。
