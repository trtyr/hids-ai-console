# LP-09 · 处置建议：先看提的是哪个程序，再决定动不动

## 处置建议

| 结论 | 动作 | 做什么 |
| --- | --- | --- |
| **真实威胁** | `escalate` | 1. **立刻查那个提权进程在干什么**（`process_tree` 往下看）<br>2. 查提权后 300 秒内的所有行为<br>3. 查这个 SUID 是谁加的（`ls -l` + 文件时间）<br>4. 移除 SUID 位 / 隔离主机 |
| **误报** | `ignore` | 建议把该程序登记到「已知 SUID 工具」清单，下次不再报 |
| **存疑** | `watchlist` / `escalate` | 写清缺什么：提权者身份？程序来源？后续行为？ |

### 为什么「先看提的是哪个程序」比「先看谁在提」更重要

因为**同一个提权者，提 `sudo` 和提 `dash` 是两件事**：

- 提 `sudo` → 这是正常机制
- 提 `dash` → **这台机器上有一个 shell 带着 SUID 位**，
  不管这次是谁在提，**这个配置本身就是个洞**

**所以发现 shell 带 SUID 时，就算这次提权者是运维，也要报出来让人去把这个位去掉。**
「运维自己加的」不等于「安全」。
