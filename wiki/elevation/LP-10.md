# LP-10 · 本地提权判定路径

**要回答**：权限是否真的改变、由谁触发、采用什么机制、是否符合该主体的授权。

1. **取事实**：原始 UID/EUID、目标身份、进程树、命令行、父进程、程序路径与哈希、时间和后续行为。不能把实时进程快照未见当作历史进程不存在。
2. **确定机制**：区分 sudo/su、SUID/SGID、漏洞利用和检测器推断。服务账号触发提权应优先调查，但账号名称本身不是攻击证据。
3. **核对授权**：查 sudoers、工单、程序基线与变更窗口。SUID 在系统清单中、使用 sudo 或位于运维目录，都不足以单独排除滥用。
4. **结论**：确认未授权权限提升，或有与本次提权可靠关联的恶意后续动作 → 真实威胁；确认符合授权与资产基线且无相反证据 → 误报；机制、操作者或结果缺失 → 存疑。

**出处**：MITRE [T1548.001/T1548.003](../_evidence/mitre-original-2026-11-09.md)明确攻击者可滥用 SUID 和 sudo；不能用“用了 sudo”直接洗白，也不能以“服务账号提权”直接定罪。

**SOP 对照**：`sops/elevation/SOP.md` 第三、四章；三份清单应作为资产配置基线逐项核查。
