# BF-09 · 处置建议：先看有没有进去，再谈封 IP

## 处置建议

**顺序很重要：先确认有没有进去，再决定封不封 IP。**

| 结论 | 动作 | 做什么 |
| --- | --- | --- |
| **真实威胁**（`success_count > 0`） | `escalate` | 1. **立刻查那个账号的登录记录**（从哪登的、登完干了什么）<br>2. 该账号立即改密 / 禁用<br>3. 查有没有后续横向<br>4. 再封来源 |
| **误报**（纯噪音） | `ignore` | 建议加来源到黑名单，或把该服务限制来源 |
| **存疑** | `escalate` | 写清缺什么，特别是 `success_count` 没拿到时 |

### 为什么不能一上来就封 IP

封 IP 是**成本最低、心理满足最强、但最没用**的动作：

- 攻击者换个 IP 就绕过去了
- 而你**失去了「有没有进去」这个判断窗口** —— 封了之后对方不来了，
  你也看不到后续的横向行为了
- 如果已经进去了，封 IP 只是让对方改用别的通道，反而更难发现

**先确认没进去，封 IP 才有意义。**
