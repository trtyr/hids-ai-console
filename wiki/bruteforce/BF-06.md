# BF-06 · 目标服务是不是「本该对外」—— 这条决定暴露面

## 目标服务该不该对外

`auth_service` 告诉我们被打的是哪个服务。**同样 100 次失败，性质完全不同：**

| 服务 | 该不该对公网开 | 被爆意味着 |
| --- | --- | --- |
| `ssh`（运维机、跳板机） | 通常该（但要限来源） | 常规噪音 |
| `ssh`（数据库机、应用机） | **不该** | **暴露面有问题** |
| `rdp` / `mssql` / `mysql` | **绝不该** | 高危暴露 |
| `ftp` | 通常不该 | 高危暴露 |

### 但这条拿不全

**配置基线里没有「这台机器的哪些服务本来就该对外」这个信息。**

### 所以实际做法（**2026-11-03 改过，原来和 BF-04 打架**）

原来这里写的是「拿不到角色 → 存疑」。**那是错的**，理由：

- 按那个写法，**380 条 `success_count=0` 的外网 ssh 扫描全都得判存疑**
- 而 BF-04 第 1 步又说这种可以判误报
- 两条判据互相打架 —— 模型的反应是**引用 BF-06 反驳程序给的结论**（B1 实测）

现在的写法：

| 情况 | 判 |
| --- | --- |
| `auth_service` 是**高危服务**（rdp / mssql / mysql / ftp） | **加重，不判误报** |
| `ssh` + 外网 + `success_count = 0` | **误报**（互联网背景噪音） |
| `ssh` + 外网 + `success_count > 0` | **真实威胁** |
| **角色登记为「不该开 ssh 的机器」**（数据库机 / 应用机） | **存疑** —— 暴露面问题 |
| 角色拿不到 | **按 `ssh` 的默认处理（判误报）**，但**写清这条前提** |

### 为什么「ssh 默认对外」是个合理默认

`ssh` 在绝大多数生产 Linux 机器上**本来就是对外开着的** —— 运维要登录。
「这台机器不该有 ssh」是**配置问题**，不是**告警判据**。

**所以「角色」是加重条件，不是成立条件。**

> ⚠️ 但「不许假设 ssh 一定是噪音」这句话**仍然成立**，它的意思是：
> **别因为服务是 ssh 就完全不看别的**（`success_count` / 来源 / 角色都要看）。
> 不是「必须拿到角色才能判」。
>
> 这条改动的实际影响：B1（外网扫描器爆 ssh、没进去）
> **从「存疑」回到「误报」** —— 它是 demo 里绝大多数告警的样子。
