# BF-08 · syslog 里没有的，去 API 查

## syslog 里没有的，去 API 查

> ⚠️ 这一类是**最依赖 API** 的：syslog 少的恰好是最关键的三样。

| 需要的信息 | syslog 里有吗 | 去哪拿 |
| --- | --- | --- |
| **谁在试**（来源 IP） | ❌ 没有 | `BruteForceService` → `source_ip` |
| **试了多少次** | ❌ 没有 | 同上 → `failure_count` |
| **有没有试进去** | ❌ 没有 | 同上 → `success_count` |
| 打的是哪个服务 | ⚠️ 有 `service_name`，常为空 | 同上 → `auth_service` |
| 来源归属地 | ❌ 没有 | 同上 → `country_code` / `owner` |
| 目标服务该不该对外 | ❌ 没有 | **配置基线**（资产角色） |
| 登录账号 | ❌ 没有 | **拿不到**，如实说 |

### 两条硬规矩

1. **能查的必须查。** `success_count` 拿不到，这一条就判不了。
2. **查了还是没有，才承认拿不到** —— 而且要写清是「API 没这条事件」
   还是「事件在但字段是空的」。

### 关联方式（和别的类一样）

syslog 没有 `event_id`。按 `host_ip` + `event_start_time` ± 300 秒匹配。
**匹配不上就如实说「没找到」**，不许拿别的爆破事件顶替 ——
顶替会把「来源是谁」整个搞错，而这个字段是本类的核心。
