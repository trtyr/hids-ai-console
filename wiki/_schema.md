# 知识库维护手册

## 适用范围

本文件供知识维护助手与人工审核员使用。研判 Agent 只读取 `status: active` 的判据；当前只有 `GEN-12` 与 12 类场景判定页属于自动判据。历史页面标为 `deprecated`，保留原编号、正文和替代编号供追溯。

## 更新一条判据前

1. 先看 [入口页](index.md)、本类判定页、对应 `sops/<类>/SOP.md` 与 `analysis-steps.html`，再看当前告警的原始字段和时间窗。SOP.md 是底稿，流程图是仓库声明的流程交付物。
2. 外部材料必须定位到**具体文章或技术页**，记录访问日期、标题、URL、原文可支持的命题与适用边界。机构首页、搜索摘要和旧证据页的转述不能当原文。
3. 客户案例须有事件 ID/工单/授权记录和引用，明确资产、时间、行为、结果、反例、有效期。不能将演示环境统计推广到客户环境。
4. 区分检测标签、行为证据、执行结果、授权状态。不能用缺字段填补推理。`status: draft` 的经验不参与自动复用。
5. 改动结论方向时，检查同类旧页、跨类引用、客户经验和测试样本是否冲突；记入 `log.md`。已发布编号不重用。

## 判据页字段

```yaml
---
id: NA-09
title: 网络异常 · 示例
applies_to: [net]
refs: [GEN-12]
status: active
updated: 2026-11-09
evidence: [_evidence/dns-original-2026-11-09.md]
---
```

修订必须保留既有 `id`；状态只可用 `active`、`draft`、`deprecated`。人工审核发布前，列出支持证据、反证、缺口及对旧结论的影响。新增外部证据先建立 `_evidence/` 页，不能直接引用未核查网页。旧页退役应保留 `deprecated_reason` 与 `superseded_by`。

## 结论契约

- 真实威胁：有可信证据支持未授权攻击或危害；另写明尝试、被拦截、已执行或已造成影响。
- 误报：核实为授权、预期或检测误触发，并列出授权范围与反例检查。
- 存疑：关键事实或授权未核清，明确需要补什么、从哪里补、谁能确认。

无论三态为何，自动研判只提出建议，不直接关闭、加白或处置。引用必须指向真实判据 ID 与可复核的当前事件字段。
