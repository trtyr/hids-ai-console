# RS-06 · 和别的类的关系：反弹 Shell 往往是链条的终点

## 反弹 Shell 在攻击链里的位置

**它很少是第一步。**

```text
入口（WebShell / 暴力破解成功 / 钓鱼）
   ↓
执行（可疑命令）
   ↓
提权（本地提权）
   ↓
**反弹 Shell**（把控制权交出去）
   ↓
横向 / 持久化
```

### 所以要回看前面 300 秒

| 前序事件 | 意味着 |
| --- | --- |
| 这个 web 目录里刚落地了文件（WebShell） | 应用被打穿了 —— 反弹 Shell 是后续 |
| 刚有一次提权（本地提权） | 提权之后马上连出去 —— 攻击者在建立通道 |
| 刚跑了可疑命令（可疑命令） | 命令本身就是那个反弹 shell |

**回看到任何一条，都让「真实威胁」更确定**（虽然第 0 步已经够了）。

### 这个关联的实际用途

第 0 步已经能定案。回看前序的价值在于：
**告诉你「入口在哪」** —— 这对处置比结论本身更重要。

只封掉这条外连没用 —— 攻击者换一条通道就回来了。
**得先把入口堵上**（删 WebShell / 改密码 / 修漏洞）。
