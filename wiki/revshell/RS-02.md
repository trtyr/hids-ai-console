# RS-02 · 父进程是最强的信号

## 父进程是最强的信号

**同一条反弹 Shell，父进程是 `nginx` 和父进程是 `bash`，性质完全不同。**

| 父进程 | 意味着 | 分量 |
| --- | --- | --- |
| **web server / 应用进程**（`nginx` `apache2` `httpd` `php-fpm` `tomcat` `java` `node`） | **应用被打穿之后拿到的 shell** | **极强** |
| 数据库（`mysqld` `postgres` `redis-server`） | 数据库被利用 | **极强** |
| `cron` / `systemd` | 计划任务里跑的东西 | 要看脚本是什么 |
| **`bash` / `sh` / `sshd`** | 人在 shell 里敲的 | **弱** —— 运维自己也可能这么干 |
| `python` / `perl` | 脚本拉起脚本 | 中 |

**为什么 web 进程拉起 shell 是「极强」**：

正常业务逻辑里，**没有任何一种情况需要 web 进程去起一个 shell**。
它一旦出现，前面一定发生了「有人往这个应用里塞了代码」。

reverseshell.app 的原话：好信号包括
「**带 socket 方向父进程的 shell**」「**从 web worker 拉起的解释器**」
「**数据库引擎拉起的命令 shell**」。

### 但这一条拿不全

`parent_process_cmdline` / `parent_process_path` 在 syslog 里有，
但**实测可能为空**（文档的示例里 `process_path` 就是空的）。

所以：**拿不到父进程时，不能用它当「良性」的证据** —— 只能算「不知道」。
