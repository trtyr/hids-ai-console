# RS-09 · 反弹 Shell 判定路径

**要回答**：是否真的建立了能远程输入并执行命令的通道，由谁发起、连到哪里、持续多久。

1. **取事实**：进程树、完整命令行、shell/解释器、目标地址与端口、网络连接状态、文件描述符或重定向关系、会话时间，以及前后 Web、数据库或登录事件。
2. **识别完整形态**：`/dev/tcp`、`nc -e`、`socat exec:`、`dup2`、`mkfifo` 等是有用特征；核对是否把输入输出接到网络并启动解释器。`nc`、Python 或 4444 端口单独不是反弹 Shell。
3. **核对执行与授权**：进程命令存在不等于连接成功，连接成功也不等于已执行后续命令。已登记运维目标或演练仍须匹配时间、资产和动作。
4. **结论**：确认未授权的远程命令通道或执行 → 真实威胁；确认是授权测试或误识别且无相反证据 → 误报；只有载荷片段、连接缺失或授权未知 → 存疑并优先保全会话证据。

**限制**：仓库 Invicti、Sysdig 等证据页仅给栏目或首页，不能支撑“三条件必然定案”的原文说法；见[来源审计](../_evidence/source-limitations-2026-11-09.md)。ATT&CK [T1059](../_evidence/mitre-original-2026-11-09.md)仅提供命令解释器行为框架。

**SOP 对照**：`sops/revshell/SOP.md` 第三、四章；父进程与命令行是调查重点，仍需核网络和结果。
