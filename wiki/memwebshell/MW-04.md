# MW-04 · 判定程序

## 判定程序

```text
第 0 步 · 进程是不是「已知的攻击工具或被注入的正常服务」？
        · `process_name` 匹配已知攻击工具
          （mettle / meterpreter / beacon / cobaltstrike）
        **或** 进程是正常服务（java / tomcat / nginx / sshd / mysqld）
          **且** class_name 有值（= Java 内存马）
        命中                                    → 真实威胁
        ↓ 没有

第 1 步 · 能不能判「这是运维/测试自己的」？
        · 进程路径在运维登记的测试/POC 目录里
        · 且 这台机器是测试机
        两条全成立                              → 误报
        ↓ 缺任一条

第 2 步 · 存疑
        写清缺什么
```

### 为什么第 0 步把「正常服务 + class_name」也算硬证据

因为**那个组合本身就是内存马的定义**：「一个正常 Java 容器里，
凭空多出来一个不认识的类，而且被判恶意」。

**Java 容器不会自己生成恶意类。**

### 第 1 步为什么要求「测试机」

demo 里那条就是 POC 测试文件（`rapid7/mettle`）。
**「进程名像攻击工具」+「在测试机上跑 POC」= 测试，不是攻击。**

两个条件缺一不可：只成立「在 POC 目录」但在生产机上 —— 那还是得查。
