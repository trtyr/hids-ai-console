# MW-02 · 两种形态：原生进程内存 vs Java 内存马

## 两种形态

API 里有一个 `type` 字段，取值 2（demo 只见过这个）。而 `class_name` 是空的。

但在别的环境里，**这两样会用来区分两种完全不同的攻击：**

| 形态 | 特征 | 是什么 |
| --- | --- | --- |
| **原生进程内存** | `class_name` 空、`process_name` 是正常二进制 | 代码被注入到进程内存里（meterpreter 那种） |
| **Java 内存马** | `class_name` / `class_loader` / `container_hash_id` 有值、`process_name` 是 `java` | **往 Web 容器里注了一个 Servlet / Filter / Listener** |

### 为什么这个区分很重要

**Java 内存马的危害比原生内存注入更持久**：

- 它挂在 Web 容器里，**重启容器就恢复了**
- 它**不需要文件**，查磁盘查不到
- 它**继承 Web 应用的权限**，天然能做 WebShell 能做的所有事

**所以「`process_name = java` + `class_name` 有值」这个组合，分量比别的都重。**

### demo 是哪种

**是原生进程内存那种**（`class_name` 空、`process_name` 是 `mettle_amd64.el`）。
Java 内存马那条路**在 demo 上没数据**，判据只能靠权威资料写。
