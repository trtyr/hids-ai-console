# SC-02 · SUID 提权链：单条不是威胁，链才是

> CISA《Eviction Strategies Tool · T1548.001 Setuid and Setgid》：
> 「The `chmod` command can set these bits with bitmasking, `chmod 4777 [file]`
> or via shorthand naming, `chmod u+s [file]`. This will enable the setuid bit.」
> 「Alternatively, adversaries may choose to **find and target vulnerable binaries with
> the setuid or setgid bits already enabled**. The setuid and setguid bits are indicated
> with an "s" instead of an "x" when viewing a file's attributes via `ls -l`.
> **The `find` command can also be used to search for such files.**」
> MITRE ATT&CK T1548.001：
> 「An adversary may abuse configurations where an application has the setuid or setgid
> bits set in order to get code running in a different (and possibly more privileged)
> user's context.」

**含义**：

1. `chmod u+s` / `chmod 4777` **本身不一定是攻击** —— 装某些软件时就得这么干。
2. 但 CISA 明确写出了攻击者的标准序列：
   **`chmod +s <系统程序>` → 找带 SUID 的程序 → 利用它提权**
3. `find / -perm -4000` 既是运维排查手段，也是这条链的第二环。

**推论**：判「chmod +s」时，**必须问一句「这条链后面有没有接上利用动作」**。
单条 `chmod +s` → 无后续 = 待定；`chmod +s` → 紧接着 SUID 枚举 → 落地可执行文件 = 真实威胁。

## ⚠️ 但有一个例外：**被改的是系统自带命令**（2026-11-02 补充）

上面那条「必须等链走完」有个前提：**被加 SUID 的是自己装的东西**。

**如果被加 SUID 的是系统自带命令，这条推论不适用 —— 单条就够判威胁。**

理由：**运维没有任何正当理由给 `/usr/bin/find` 加提权位。**

| 被改的文件 | 是什么 | 单条 `chmod +s` 够不够定罪 |
| --- | --- | --- |
| `/usr/bin/find`、`/bin/ls`、`/usr/bin/passwd` … | 系统自带命令 | **够** —— 加了就是留后门 |
| `/opt/myapp/start.sh`、`/usr/local/bin/mytool` | 自己装的应用 | **不够** —— 装软件时需要 |
| 任何**非系统目录**下的文件 | 自己装的东西 | **不够** |

**这条的判据在事实层已经算好了**（`suid_target`），直接读：

| 事实字段 | 含义 |
| --- | --- |
| `suid_target.is_suid_command` | 这条命令是不是在加 SUID/SGID 权限 |
| `suid_target.target_path` | **被改的那个文件**（不是被执行的那个程序） |
| `suid_target.target_is_system_command` | 目标是不是系统自带命令 ← **关键** |
| `suid_target.reason` | 人话说明，直接读就行 |

> ⚠️ **别把「被执行的程序在哪」当成「被改的文件在哪」** ——
> `chmod +s /usr/bin/find` 里，被执行的是 `/usr/bin/chmod`（系统自带，正常），
> **被改的是 `/usr/bin/find`**。这是两回事。

## ⚠️ 「枚举」不等于「利用」

`find / -user root -perm -4000 -print` 单独出现时，是**审计动作**，不是攻击动作。

**理由**：这条命令出现在**每一份 Linux 加固清单**里 —— 运维跑它是为了
「看看系统里现在有哪些 SUID 程序是隐患」。它是**防守方**的动作。

**它只有在两种情况下才是链上的一环**：

1. **前面**有 `chmod +s`（说明有人在给自己开后门，然后来盘点）
2. **后面**接上了利用动作（枚举完就去执行某个 SUID 程序）

**两种都不满足 → 它就是一次排查 → 误报。**

**推论**：不要因为「这条命令在攻击链上出现过」就把它单独判成威胁 ——
**链是链上所有环节一起构成的，缺一环就只是其中一段。**

**Red Canary 的补充**（同一条技术）：
> 「Execution of setuid and setgid binaries **can be considered normal behavior**
> on many Linux distributions.」

**所以「执行了 setuid 程序」不能单独定罪。**
