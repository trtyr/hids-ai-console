# SC-05 · 谁执行的：执行者身份是第一维度

**这一类的判定必须先回答「谁在执行」。** 三条线索：

## 5.1 用户身份

`user_name` / `user_gid` / `user_gname`。运维通常用自己的账号，攻击者提权后是 root。

## 5.2 会话来源 IP（`env` 里）

系统日志的 `env` 字段里带着：

```text
SSH_CLIENT=115.216.116.160 51287 22
SSH_CONNECTION=115.216.116.160 51287 172.20.208.23 22
```

**这是 SSH 登录的来源 IP —— 也就是「谁在这台机器上敲的命令」。**

**⚠️ 极其容易搞错的一点**：这个 IP **不是攻击者的 IP，是登录者的 IP**。
如果运维从 `115.216.116.160` 登录进来执行了挖矿命令 —— 那 `115.216.116.160` 就是运维自己，
**不是攻击者**。

**它的正确用途**：

- 把**同一条命令**和**同一个登录会话**串起来（SSH_CLIENT 相同 = 同一个会话干的）
- 判断「这条命令是交互式敲的还是脚本/计划任务跑的」（有 `SSH_TTY` / `XDG_SESSION_ID`
  = 人在终端里敲的；没有 = 脚本、cron、自动化跑的）
- 和**异常登录**告警交叉：同一个 IP 在别处登录失败了，这里却登录成功了

## 5.3 交互 vs 自动化

| env 特征 | 含义 |
| --- | --- |
| `SSH_TTY=/dev/pts/N` | 人在终端里敲的 |
| `XDG_SESSION_ID=NNNN` | 有会话 |
| `SSH_CLIENT` / `SSH_CONNECTION` | 走 SSH 进来的 |
| 都没有 | **本地脚本 / cron / 容器 / 自动化跑的** |
