# 架构 L0：边界、不变量与数据流

这份文档只回答四个问题：这套后端分成哪几块、块与块之间谁依赖谁、一条告警进来走哪三条路、以及哪几条规则是**任何模块都不许破**的。
往下钻的接口字段、失败码、函数入参一律不在本页——它们各归 L1 模块页，一门课一处真源。

## 1. 定位

本页是文档分层的**最上层**，读者是「要判断一个改动该落在哪一块、会不会破掉别处的假设」的人。
判据很简单：先在本页找到那块地，再看第 5 节的不变量有没有被踩到，最后才去对应的模块页读细节。

- 模块页清单与文件对应关系：[docs/modules/_breakdown.json](../modules/_breakdown.json)
- 面向新人的全景导览（进程、入口、配置、怎么跑测试）：[docs/architecture.md](../architecture.md)
- 这里描述不出来、只能记下现状的缺口：[docs/_meta/gaps.md](../_meta/gaps.md)

## 2. 构件与模块边界

按「谁拥有这份状态、谁定义这份契约」切成七块。每块只对它自己的状态负责，跨块的状态改动一律走对方的公开面：

| 层 | 负责 | 明确不管 |
| --- | --- | --- |
| 入口 | 起进程、装配依赖、路由与身份闸门 | 任何业务流程判断 |
| 编排 | 把一次业务流程从起点推到终点，决定调谁、调几轮、失败怎么办 | 具体协议细节、磁盘布局 |
| 取证与投影 | 把外部查询包装成模型可调用的工具；把原始返回压成有指针的精简视图 | 结论怎么下 |
| 事件网关 | 外部平台的类型表、方法名映射、原始行归一化 | 研判与存储 |
| 存储 | 读写状态、判据、提示词、升级包、候选经验；决定落盘格式 | 谁在什么时候调用它 |
| 传输 | 与外部服务通信，各自封装超时、错误翻译与响应校验 | 业务语义 |
| 维护端 | 独立的维护入口与升级包链路，与业务入口分进程起 | 业务 API 的鉴权口径 |

两条容易被踩的边界：

- **存储层不认识业务流程**。它接收的是已经算好的对象，不判断「这条结论该不该下」「这次研判算不算成功」。
- **维护端不复用业务入口的鉴权**。它有自己的令牌与角色口径，两边混用会把运维权限漏进业务面。

## 3. 依赖方向

一条总规矩：**箭头只往下，回指一律走回调或注入**。

- 入口 → 编排 → 取证 / 投影 / 网关，编排与取证都可以用存储；存储与传输是并列的两支，互不依赖。
- 唯一的装配点是业务入口文件：它把传输实例、网关实例、工具箱、模型客户端、存储逐个造出来再交给编排层。别的地方不 new 这些件，只接构造参数。
- 存储层认得谁、不许认得谁：七个文件里三个零本地 import（调查记录、候选经验、脱敏闸），四个是单向取用、无环——提示词存储取配置根与判据库目录（缺种子时触发整库种子），判据库存储取配置根与规则存储的种子函数，规则存储只取配置根，更新存储只取脱敏闸。出现反向 import（存储层指向编排层）或环就是越界。

判断一次改动是否越界，看它要跨几条线：如果新代码让存储层开始 import 编排层，或者让传输层开始判断业务语义，那就是方向反了，
应当把判断上提到编排层，或者把数据通过参数传下去。

## 4. 数据流：三条主线

三条主线覆盖了这套后端绝大多数代码路径。读一条主线时，只需要关心它经过哪几个构件、在哪一步写盘。

**主线一：拉取式研判（轮询驱动）**

1. 编排层的轮询任务按游标向事件网关要增量事件，网关把不同类型的结果合并、排序后交给上层。
2. 队列按「类型风险、出现次数、时间」排序，达到上限就拒收并计数，不无限吃内存。
3. 轮到的告警进入研判：先落案件材料，再进取证循环，最后出结论并写研判记录。
4. 状态沿「排队 → 在跑 → 完成或失败」迁移；失败记录按退避重排，到了次数上限进死信。

**主线二：推送式（syslog 驱动的旁路）**

1. 业务进程内的 UDP 接收器把报文解析成统一结构（同一个 HTTP 服务进程，随启动挂上 UDP socket，见 `server.js` 的 `attachSyslog` 接线），先落案卷材料，再尝试与平台上的事件对上号。
2. 对上号就交给同一条研判队列；对不上号走旁路，旁路把结论口径固定成「存疑」，并在缺口里写明没匹配上。
3. 暂停期间收到的报文进缓冲而不是丢弃，恢复后逐条回灌，游标与排队记录都不动。

**主线三：回写式（人改判据，下次研判吃到）**

1. 人工反馈或复核结论进入维护链路：候选经验整理、误报规则提案、判据页草案。
2. 经过校验、回放、人工发布之后，落到数据根下的判据库或规则库；没有人工确认的一律不进库。
3. 下一次研判启动时，编排层读到的就是改过的那一版——提示词在每次研判里现读（不是启动时快照），判据与规则同样按当次请求从各自的库读取。规则库是存储层成员（`rule-store.js`），在架构篇的分组表里与提示词、判据并列，不从属于它们。

## 5. 跨模块不变量

下面六条任何一块都不许破。它们分散在各模块页里，但**破一条就是跨模块事故**，所以在这里收成一份：

| 不变量 | 破了会长什么样 | 权威页 |
| --- | --- | --- |
| 落盘一律「临时文件 + rename」，读到的永远是完整快照 | 读到半截 JSON，解析失败后被当成「文件不存在」 | [record-store](../modules/record-store.md)、[trace-board](../modules/trace-board.md)、[triage-pipeline](../modules/triage-pipeline.md) |
| 本系统只读外部平台，不下指令 | 出现处置动作，或者调用非查询类接口 | [event-gateway](../modules/event-gateway.md)、[architecture.md 第 9 节](../architecture.md) |
| 结论里的每一条事实都要能被原始证据指针核验，核不过就降级 | 结论凭模型口头断言交付，客户无法复核 | [investigation-agent](../modules/investigation-agent.md) |
| 运行态路径只有一个来源，不另拼一套 | 两处算出不同的数据根，数据看起来「丢了一半」 | [docs/architecture.md 第 8 节](../architecture.md) |
| 队列记录、白板、记录文件的文件名不含外部 ID 原文 | 外部标识以路径形式泄露，或者改名换目录后读不回来 | [record-store](../modules/record-store.md)、[triage-pipeline](../modules/triage-pipeline.md) |
| 提示词、判据、规则的生效版本必须能被指纹或版本号描述，乐观并发靠它拦 | 两个人同时改，后写的把先写的覆盖掉 | [prompt-store](../modules/prompt-store.md)、[knowledge-base](../modules/knowledge-base.md)、[triage-rules](../modules/triage-rules.md) |

## 6. 执行概念：一次告警的一生

一条告警的一生只有五个状态位值得记：进来（收到/入队）、开始（在跑）、出结论（完成）、失败（可重排）、终结（死信或归档）。
这三个地方的状态名字必须对得上，否则会出现「队列说在跑、记录说已完成、白板还在追」的三方打架：

- 队列侧：排队 / 在跑 / 完成 / 失败 + 死信标记。
- 记录侧：一份「告警 + 模式」一条记录，后写的覆盖先写的。
- 白板侧：在跑 / 完成 / 失败 / 中断（进程重启后由读路径把僵死状态改写成中断）。

并发上的三条既有约定：同一条告警在同一秒内重复投递合并成一条并累加计数；同一条外部事件在一次研判里只真拉一次；
写路径串行、读路径不排队。

## 7. 资源与余量

进程级的硬上限、软上限与它们的权威页，收在 [docs/architecture.md 第 14 节](../architecture.md) 的一张索引表里，**本页不抄第二份数字**。
这里只交代取用原则：

- 所有上限都是单进程内的常量或环境变量，没有跨进程配额，也没有回压到外部平台的手段。
- 超限只有两种处置：拒收并计数（队列满、分页越界），或降级并记缺口（轮数用尽、证据超预算）。没有「无限排队等锁」这条路。
- 计数类指标（丢弃数、缺口数）只增不减，进程重启归零——想把它们当长期指标用，得另做持久化。

## 8. 约束与理由

几个看起来「本可以做得更好」的地方，都是有意的取舍：

- **状态用文件而不是数据库**：部署面只有 Node 与一个可写目录，没有 DBA 也没有迁移窗口；代价是并发靠单进程队列与 rename 原子性来保，
  多进程部署时这些保证不再成立。
- **只读不写外部平台**：本系统的产物是给人看的结论，不是自动处置。越界去下指令的风险（误封、误阻断）远大于收益。
- **判据、规则、提示词都是「活数据」**：它们随误报经验持续修改，所以放在数据根下由人发布，而不是编译进代码；
  代价是每次研判都要重新装载，并靠指纹与版本号保证「读到的就是发布的那一版」。
- **接口契约有两份文本**：路由与 `openapi.yaml` 分开维护，这是当前现状而非目标状态，改路由时两边都要动，
  缺口记在 [docs/_meta/gaps.md](../_meta/gaps.md) 第四节。
- **维护端独立成进程**：升级包、密钥、维护会话不跟业务 API 同生共死；代价是多一套认证与部署步骤。

## 9. 往下一层怎么走

- 想知道某一块的接口、入参域、失败码：打开第 2 节表里对应的模块页，模块页的「公开面」「值语义」「失败面」三节就是这些内容。
- 想知道某个文件里某一行在干什么：模块页的引用都按 `文件:行号` 标，行号基准写在页首，代码变了要重核。
- 想确认一条承诺有没有被测试盯住：模块页的承诺编号（形如 `R-<模块>-<两位数字>`）与测试里的回指注解是同一套编号。
