# 常规告警 SOP：本项目的牧云 API 适配

本流程参照 ai-hids-ops 各场景的 `analysis-steps.html` 和判据库。牧云 syslog 是触发通知，收到一条就建立一条研判任务；牧云 API 是补充事实的证据库。当前键值对载荷可带 `event_id` 和 `host_id`，有事件 ID 时先精确回查并核对主机身份；缺少 ID 时才按同类、主机 IP、事件时间前后五分钟查询首批事件并核对内容。匹配不到或身份不清时写明缺口，不能借用不相关事件。判据通过只读 Wiki 工具取得；深度溯源白板另用 MCP。不要把产品自身的 `rule_subject`、`repair` 当作独立事实。

1. **解析**：先解析原始 syslog，核对类型、主机、事件时间和关键行为，再读取可关联的牧云事件。只有载荷无法解析才中止；缺字段不是不合格入口，应先查询、仍缺则判存疑；“已忽略”“已处理”“等级为空”均不能丢弃。
2. **收集事实**：依场景查询本次行为、同一资产和来源的相关事件、历史模式与后续升级行为。API 查询返回 0 与查询失败是两回事。时间关联须核对同一会话、进程、账号或连接；不能只凭同主机和时间接近。
3. **选择判据**：先分开核对可观察行为、执行结果和授权范围，再按当前场景判定页给出三态结论。场景必要字段取不到时写明缺口，不能把未知当成已满足。
4. **Agent 研判**：用实际查到的证据解释行为语义和因果，给出“真实威胁 / 存疑 / 误报”之一。“攻击尝试未成功”写进摘要或分析，描述成功状态。
5. **独立校验**：检查 JSON、三态结论、证据指针、良性条件、反证和数据缺口。不合格最多重研判两次；仍无法核实时输出存疑并解释原因。
6. **保存结果**：每条 syslog 单独保留原文、字段、事实、上下文、判据索引、单段报告和结构化结果；保留场景判据版本、API 查询记录、证据引用、校验情况和建议行动。

当前场景判定页来自本项目 2026-11-09 核查版 Wiki。旧仓库判据保留为历史页，不参与自动研判。场景提示词中的威胁与误报特征是调查线索；与当前判定页冲突时按当前判定页核对。仓库样本中的固定阈值、配置基线或 syslog 窗口统计，只有当前 API 证据能支持且与客户环境相符时才适用。
本 SOP 与场景特征参考冲突时，先遵守本项目的证据安全边界和三态输出契约，再核对本类判定程序的必要条件、客户基线与反例。仓库样本中的预计算结论不是本项目已有能力；不得照抄“程序已经给出结论”。

## 查询、判据与报告的分工

系统已给出本类和通用 Wiki 目录及常驻判定程序；只在边界不明时按需读取少量相关页，不为完整性遍历全部判据。wiki_search、wiki_page 是方法检索，不能代替当前告警的 syslog 和 API 证据。由 syslog 触发的任务可用 read_case_file 按需读取本条告警的材料目录；文件是阅读视图，引用仍应指向原始字段。

区分原始详情、当前页样本、查询完整覆盖的窗口与跨主机范围。0 只对已查询范围成立，未返回、失败、截断及数据过期均写缺口。历史模式的跨度、次数、升级事件数与客户基线必须实查；样本阈值不是客户生产事实。

历史告警只证明过去曾检出相应行为或文件，不能据此声称文件当前仍在磁盘、已被加载或已执行。描述当前状态前须查询实时资产或文件事实；没有这类证据时使用“历史告警显示曾检出”。

沿用本项目 summary、analysis、claims、evidence_facts 等结构化字段。摘要一句话；由 syslog 触发的任务另提供 report，供运维直接阅读：一段自然语言，讲清何时、哪台机器、做了什么、三态结论及依据、缺口与具体下一步，材料充分时参考 300～500 汉字。给人的正文不堆判据编号，不抄核心提示词或整页判据；结构化事实保留原始证据指针。
