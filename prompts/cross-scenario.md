# 跨场景关联规则（每次研判都要检查）
1. 研判任何一条告警时，都要查询同一主机前后 24 小时的其他告警。如果多条告警能串成攻击链，在 attack_chain 中说明，并且整体风险取攻击链中最高的一项。
2. 常见攻击链，出现时要提高置信度：
   - Webshell → 可疑命令 → 本地提权 → 反弹Shell / 内存后门
   - 暴力破解 → 异常登录 → 命令记录中的侦察和持久化
   - 恶意文件 → 网络异常（C2 / 矿池）
   - 蜜罐诱捕（来源为内网主机）→ 对来源主机的全面回查
3. 一条告警被判定为真实威胁时，要在 recommended_actions 中列出需要回查的关联对象：同一 IOC 的其他主机、同一账号的其他登录、同一来源 IP 的其他目标。
4. 同一条规则在多台主机上同时触发，且内容高度一致：若时间与发布/批量运维对应，倾向误报；若时间与发布无关，警惕批量入侵或供应链问题，不能直接批量判定误报。
5. 不要因为前面多条同类告警都是误报，就默认后续同类告警也是误报。每条告警都要独立取证。

# 合并补充：关联边界
吸收 ai-hids-ops 对命令记录、会话和时间窗的区分：同一主机上相近时间的两个事件只构成候选关联；优先找同一账号、会话、进程链、命令目标、网络连接或文件哈希。按时间重建“登录 → 侦察 → 提权 → 落地 → 横向/外连”的顺序，并记录各环节未核实之处。告警之后同一会话出现的攻击行为比主机历史上的普通噪音更有解释力。对重复事件先核对是否只是同一事件重复投递，再比较原始行为。

关联窗口以本次工具实际接受的筛选条件、返回时间范围与翻页覆盖为准。没有完整覆盖不能把“未见其他告警”写成“从未发生”；仅累计多个攻击阶段标签不能代替真实的账号、进程、会话、文件或连接链。不同事件的风险标签不互相充当证据，授权也不能从一次会话扩展到其他目标。
