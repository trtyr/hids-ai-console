# 告警列表页设计稿 · 开发交接说明

对应文件：`alerts.html`
关联页面：`overview.html`、`index.html`

---

## 1. 页面职责

按时间倒序列出告警，支持关键词与类型 / 等级 / 结论 / 研判状态筛选、按时间或等级排序、翻页、批量重新研判、查看单条摘要。自动研判队列不再单独成页，状态与开关并入了本页。

告警 ID 单独成列，等宽小字，点击可打开抽屉；搜索框同样支持按 ID 查。

---

## 2. 结构

```
左侧导航 196px │ 顶栏：告警 · 共 N 条 · 更新时间 · 刷新
               │ 筛选条：搜索 · 类型 · 等级 · 结论 · 清除 · 结果计数
               │ 批量条（选中后出现）：已选 N 条 · 重新研判所选 · 清除选择
               │ 表头吸顶：□ · 等级 · 告警 ID · 告警 · 类型 · 资产 · IP · 研判状态 · 结论 · 时间
               │ 表格：单行单元格，时间倒序
               │ 分页：范围 · 页码 · 每页 20 / 50
               │ 右侧抽屉：结论与摘要、关键字段、研判步骤、证据来源、原始字段、操作
```

- 等级是普通列：6px 色点 + 文字，没有贯穿整行的色带，也没有背景胶囊。
- 时间列显示 `YYYY-MM-DD HH:MM:SS`，直接取 `createdAt`；为空显示「—」。
- 列宽固定，标题单行截断，不出现横向滚动；`assetIp`、`hostId`、`createdAt` 为空时显示「—」。
- 导航选中态用底色区分，不再用左侧竖线。

抽屉内容（480px，自上而下）：

1. 头部：告警 ID（可一键复制）、等级、标题、资产 · IP · 精确时间；右上角固定「查看完整详情」与关闭。
2. 研判结论：整块按结论类型给极淡底色（真实威胁用危险色、存疑用警示色、其余中性）；结论字样 21px 带小方块，下方是摘要段落与缺失证据。
3. 关键信息：两列网格带横线与中缝，资产、IP、事件类型、事件 ID、主机 ID、发生时间、场景、研判状态。
4. 研判步骤：带连接线的纵向时间线，已完成节点用实心点，处理中用空心点；待研判只有入库与等待两步。
5. 证据来源：标题右侧显示总数，下方按进程树 / 命令行 / 网络连接 / 文件哈希 / 账号会话拆条。
6. 原始字段：eventType、eventId、hostId、levelKey，默认收起，展开时箭头转向。
7. 底部固定操作：失败任务为「重试」，完成任务为「重新研判」，排队中与研判中禁用并显示当前状态。

## 3. 设计依据

参考了 Elastic Security 的 Alerts 页面与 Splunk ES 一类的告警队列，它们共同的做法是：

- 筛选在表格上方（搜索 + 状态 / 等级 / 主机等下拉），而不是把筛选做成卡片；
- 等级、状态都是表格里的普通列，用色点或短标签表示，不画整行色带；
- 选中若干行后出现「Selected N」批量操作条；
- 详情用侧栏或行内展开，不在列表里堆两行元信息；
- 表头可排序并有方向指示；
- 表格行是单行单元格，字段各占一列。

这一版按这些共性落地，去掉了上一版的等级左色带、按天分隔和「标题 + 元信息」两行单元格。

## 4. 数据与分页

- 示例数据按总览的 11 类计数生成，共 347 条，按 `ts` 倒序：
  `brute_force 128 / network_audit 63 / webshell 42 / suspicious_operation 31 / abnormal_login 24 / malware 17 / honeypot 12 / elevation_process 11 / revshell 9 / memory_webshell 6 / memory_security 4`。
- 筛选与排序目前都在前端对示例数据计算，分页也基于筛选后的结果。
- 真实接口 `GET /api/alerts` 只支持 `count` 与 `offset`，需要后端补充 `q`、`type`、`level`、`verdict`、`triage_status`、`sort` 参数，前端把筛选/排序值直接透传即可，表格与分页无需重写。

| 界面元素 | 接口字段 |
| --- | --- |
| 总数 | `total` |
| 行数据 | `id、eventType、asset、assetIp、level、createdAt`，研判信息读 `triage.status`、`triage.stage`、`triage.verdict_label`、`triage.verified_facts`、`triage.evidence_sources` |
| 队列条 | `/api/agent/triage/status` 的 `enabled`、`input_mode`、`counts`、`last_error` |
| 搜索 | 匹配标题、ID、资产、IP |
| 抽屉事实 / 证据 | `triage.verified_facts`、`triage.evidence_sources`；接口没有条目级数据，界面只显示数量 |
| 抽屉结论摘要 | `triage.report`（示例按结论生成） |
| 抽屉研判步骤 | `triage.steps`、`triage.stage`（示例为 `T+` 节点） |
| 抽屉原始字段 | `eventType`、`eventId`、`hostId`、`levelKey` |
| 队列暂停 / 恢复 | `PUT /api/agent/triage/control` |
| 重试 / 重新研判 | `POST /api/agent/triage/{alertId}` |
| 批量重新研判 | 逐条调用同一接口 |
| 分页 | `count`、`offset` |

## 5. 交互与状态

| 状态 | 触发方式 | 呈现 |
| --- | --- | --- |
| 默认 | 打开页面 | 347 条、时间倒序、每页 20 |
| 搜索 | 输入关键词 | 实时过滤标题 / ID / 资产 / IP，回到第 1 页 |
| 类型 / 等级 / 结论 / 研判状态筛选 | 下拉选择 | 结果计数变为「N / 347 条」，出现「清除筛选」 |
| 查看失败 | 队列条「查看 N 条失败」 | 自动切到失败筛选，只显示失败任务 |
| 暂停 / 恢复 | 队列条按钮 | 状态文字与圆点切换，读屏播报 |
| 清除筛选 | 点击清除或空态按钮 | 重置全部条件并聚焦搜索框 |
| 排序 | 点击「等级」或「时间」表头 | 同列再点切换升降序，表头箭头与 `aria-sort` 同步 |
| 翻页 | 上一页 / 下一页 / 页码 | 表格降透明，完成后聚焦首条标题 |
| 每页条数 | 20 / 50 | 回到第 1 页 |
| 单条选择 | 勾选行 | 顶部出现批量条与已选数量 |
| 全选当前页 | 表头复选框 | 仅当前页；跨筛选、跨页选择保留 |
| 批量重新研判 | 批量条按钮 | 所选完成 / 失败任务回到排队，计数同步，清除选择并播报数量 |
| 打开抽屉 | 点击行或标题 | 右侧 480px 抽屉，从上到下依次为：结论与摘要、关键字段、研判步骤、证据来源、原始字段（默认收起），头部右上角是「查看完整详情」，底部固定重试 / 重新研判按钮 |
| 关闭抽屉 | 关闭 / 遮罩 / Esc | 焦点回到原行标题 |
| 空结果 | 筛选无匹配 | 表格内提示并提供「清除筛选」 |
| 未定稿页面 | 其他导航项 | 主区占位，抽屉自动收起 |

筛选与排序会重置页码，但不会清空已选告警；批量操作作用于全部选中项。研判状态与结论分两列：状态列只显示排队中 / 研判中 / 完成 / 失败（没有 `triage` 时为「未研判」），结论列只显示真实威胁 / 存疑 / 误报，未产生结论显示「—」，两者不拼在一起。抽屉里的步骤只在 `triage.steps` 有数据时出现，前端不再生成时间线。

---

## 6. 响应式

- ≥ 1100px：完整导航，显示 IP 列
- ≤ 1100px：导航收为 56px 图标栏，隐藏 IP 列
- ≤ 900px：顶部横向导航，隐藏时间列
- ≤ 760px：隐藏类型列与 ID 列（ID 仍在抽屉与搜索中），抽屉占满宽度并出现遮罩，筛选条换行
- ≤ 620px：保留选择、等级、告警、资产、研判，标题字号 12px
- 队列条在窄屏换行，计数保持在右侧
- 表格固定布局，最小宽度 320px，无横向滚动

## 7. 后续待补

- 后端筛选 / 排序参数（`q`、`type`、`level`、`verdict`、`triage_status`、`sort`）；队列计数需要额外的 `/api/agent/triage/status` 请求。
- 未匹配牧云事件的 Syslog 案件（`triage.alert_id` 有值、`matched_alert_id` 为空）目前没有列表入口，后续可加「未匹配案件」筛选视图。
- 时间范围选择器，需要接口支持 `from` / `to`。
- 告警详情页：原始事件、证据链、研判步骤、溯源白板。
- 批量重研判的结果汇总提示。

---

## 8. 主题

深色为默认，顶栏右侧可切换浅色，选择会记忆。颜色统一由 `assets/theme.css` 提供，切换逻辑在 `assets/theme.js`；复选框勾选图标通过 `--check-icon` / `--dash-icon` 两套资源随主题切换。
